# 02-7 모델 선택과 모델 목록 조회: 상세 기획

- 상태: planned
- 상위 문서: [02-client.md](../../02-client.md)

## 목적
모델 이름으로 클라이언트를 만들고, 엔드포인트의 모델 목록을 조회한다. 작업 03·04가 설정에 적힌 모델 이름만으로 대화하고, 사용자가 서버에 있는 모델 id를 알아볼 수 있게 한다.

## 범위(In)
- 설정([02-2](../02-2-config/plan.md))과 키([02-1](../02-1-secrets/plan.md))로 모델 이름에 맞는 클라이언트를 만든다. 샘플링은 모델별 값이 기본값보다 앞서고, 모델의 `reasoning`과 `extra`를 요청에 싣는다.
- `GET {base_url}/models`: 최상위 `data` 배열의 문자열 `id`만 필수로 읽고 나머지 필드는 버린다.
- 인증은 [02-5](../02-5-transport/plan.md)와 같다.

## 비범위(Out)
- `ls` 같은 사용자 명령: 작업 04.
- 모델 목록의 쪽 나누기(매개변수 없이 호출하면 전체를 돌려준다고 문서화됨).
- LM Studio 고유 REST(`GET /api/v1/models`)와 `id` 외 필드(`created`, `owned_by`, `meta` 등) 해석.
- 응답 형식이 다른 API.

## 선행 세부 작업
[02-6 재시도 적용](../02-6-retry-apply/plan.md).

## 참고 자료
- RESEARCH.md 작업 02 절
  - OpenAI API 참조, 모델 목록: 응답은 `object: "list"`와 `data` 배열. 필수로 읽는 것은 `data[].id`뿐이다.
  - llama.cpp server README, 모델 목록: `id`가 파일 경로일 수 있고, `meta`가 `null`일 수 있다. 모르는 필드와 `null` 필드는 무시한다. 인증은 Bearer 한 가지만 보낸다.
  - Ollama OpenAI 호환 문서, 모델 목록: 응답은 `data[].id`만 필수로 읽는다.
  - vLLM OpenAI 호환 서버: 응답 필드가 문서에 없다. OpenAI 형식으로 해석하되 `data[].id` 외에는 요구하지 않는다. 키가 있으면 항상 Bearer 헤더를 보낸다.
  - LM Studio 모델 목록과 인증: OpenAI 호환 `GET {base_url}/models`만 쓰고 고유 REST는 쓰지 않는다. 응답이 `data` 배열이 아니면 형식 오류로 알린다.
  - OpenRouter 모델 목록: `data[].id`만 읽고 나머지는 버린다. 쪽 나누기는 적용하지 않는다. HTTP 오류 본문은 요약하고 키와 주소를 가려 싣는다.
  - 모델 목록 서버별 정리: `data[].id`는 여섯 곳 모두에서 유일한 공통 필드이고, 인증 헤더는 Bearer로 통일한다.
- DECISIONS D3, D13.

## 리스크
- 일부 서버는 `/models`를 지원하지 않거나 형식이 다르다. 조회 실패는 오류로 알리고, 설정은 손으로 쓸 수 있다.
- 엔드포인트 2개·모델 3개 시험에서 요청이 엉뚱한 엔드포인트로 가면 키가 다른 서버에 새는 사고가 된다. 모의 서버 2개가 각자 받은 요청을 기록해 확인한다.
- 모델 목록 조회에는 재시도를 적용하지 않는다(D14). 일시적 실패(429, 503)도 바로 오류로 알리므로 사용자가 다시 부른다.
