# 02-7 모델 선택과 모델 목록 조회: 작업 계획

- 상위 문서: [plan.md](plan.md), [spec.md](spec.md)
- 검증 명령과 공통 DoD는 [상위 문서](../../02-client.md)의 '세부 작업 공통 기준'을 따른다.

## 구현 단계
- [ ] 1. 모델 이름으로 클라이언트를 만든다. 설정에서 모델과 엔드포인트를 찾고, 키를 정하고(02-2), 서버용 id와 샘플링(모델별 값이 기본값보다 앞섬), `reasoning`, `extra`를 요청에 쓴다. 없는 모델 이름은 이름만 밝힌 오류로 끝낸다. 확인: 엔드포인트 2개, 모델 3개, 모의 서버 2개로 요청이 해당 서버로만 가고 본문의 id와 샘플링이 맞는지 확인하는 통합 테스트(AC 1), 없는 이름 오류 단위 테스트(AC 2).
- [ ] 2. 모델 목록 조회를 만든다. `GET {base_url}/models`, 인증은 [02-5](../02-5-transport/tasks.md)와 같고, `data[].id`만 필수로 읽는다. 재시도하지 않고 시간 초과는 02-5 설정을 쓴다(D14). 확인: 정상 응답의 id 목록과 모르는 필드·`null` 필드 무시를 확인하는 통합 테스트(AC 3).
- [ ] 3. 형식 오류를 만든다. `data`가 없거나 배열이 아님, `id`가 없거나 문자열이 아님. 확인: 경우마다 형식 오류이고 오류에 키와 주소가 없음을 확인하는 통합 테스트(AC 3).
- [ ] 4. 취소와 시간 초과가 02-5와 같이 동작함을 확인한다. 확인: 응답을 지연시키는 모의 서버와 취소 토큰으로 확인하는 통합 테스트(AC 3).
- [ ] 5. `docs/RESEARCH.md` 작업 02 절의 모델 목록 항목들(OpenAI, llama.cpp, Ollama, vLLM, LM Studio, OpenRouter, 서버별 정리)에 02-7 적용 위치를 갱신한다.
- [ ] 6. 작업 전체 마무리로, 설정이 있으면 실제 엔드포인트로 1회 확인한다. 출력에 URL과 키를 찍지 않는다.

## 테스트 계획
- 종류: 로컬 모의 서버 통합 테스트(모의 서버 2개가 각자 받은 요청을 기록한다), 오류 종류별 단위 테스트.
- 주입할 것: 설정(임시 폴더의 설정 파일 또는 직접 만든 설정), 자격 파일에서 읽은 이름별 값, 취소 토큰, 시험용 시간 값.
- 테스트 파일은 관심사별로 나눈다(모델 선택, 모델 목록). 측정은 dev-principles 3절(DRY)·6절(이름과 함수)로 한다(`.agents/skills/dev-principles/SKILL.md`, Claude Code와 Cursor는 `.claude/skills/dev-principles/SKILL.md`).
