# 02-7 모델 선택과 모델 목록 조회: 명세

- 상위 문서: [plan.md](plan.md)

## 입력과 출력
- 모델 이름으로 클라이언트 만들기
  - 입력: 검증된 설정([02-2](../02-2-config/spec.md)), 자격 파일에서 읽은 이름별 값([02-1](../02-1-secrets/spec.md)), 모델 이름.
  - 출력: 그 모델이 가리키는 엔드포인트로 요청하는 클라이언트. 요청 본문에는 그 모델의 서버용 id와 샘플링, `reasoning`, `extra`가 쓰인다.
- 모델 목록 조회
  - 입력: 엔드포인트(base_url, 키는 있으면), 취소 토큰.
  - 출력: 서버가 알려 준 모델 id 문자열 목록.
- 실패하면 오류.

## 동작 규칙

### 모델 이름으로 클라이언트 만들기
정상
- 모델 이름에 맞는 설정 항목을 찾아 그 모델이 가리키는 엔드포인트로 요청하는 클라이언트를 만든다.
- 요청 본문에는 모델 이름이 아니라 설정에 적힌 서버에 보낼 id를 쓴다.
- 샘플링은 모델별 값이 기본값(`sampling`)보다 앞선다.
- 키는 02-2의 키 정하기(자격 파일 `credentials.jsonc`의 `api_keys`에서 엔드포인트 이름으로 찾기)로 정한다. 키가 없으면 인증 없이 요청한다.
- 요청은 그 모델이 가리키는 엔드포인트로만 가고 다른 엔드포인트로 가지 않는다.

거부
- 설정에 없는 모델 이름은 이름만 밝힌 오류로 끝난다.

### 모델 목록 조회
정상
- `GET {base_url}/models`로 요청한다. 인증은 [02-5](../02-5-transport/spec.md)와 같다(키가 있으면 `Authorization: Bearer`, 없으면 헤더 없음).
- 최상위 `data` 배열의 각 항목에서 문자열 `id`만 필수로 읽는다. 나머지 필드(`object`, `created`, `owned_by`, `meta` 등)는 없어도 받아들이고 버린다.

오류
- `data`가 없거나 배열이 아니면 형식 오류로 알린다.
- `id`가 없거나 문자열이 아니면 형식 오류로 알린다.
- HTTP 오류 상태는 오류로 알린다. 본문은 요약하고 키와 주소를 가려 싣는다.
- 취소와 시간 초과는 [02-5](../02-5-transport/spec.md)와 같이 동작한다.
- 재시도하지 않는다. 사용자가 직접 부르는 한 번짜리 조회라 실패를 바로 알리는 편이 낫다(D14).
- 연결·헤더 대기 시간 초과는 02-5와 같은 설정을 쓰고, 본문 읽기는 유휴 시간 초과를 따른다(D14).

## 오류 종류와 담는 것
| 오류 | 담는 것 | 담지 않는 것 |
|---|---|---|
| 모델 이름 없음 | 모델 이름 | 설정의 다른 값, 주소, 키 |
| 모델 목록 형식 오류 | 오류 종류 | 키, base_url 호스트, 응답 원문 전체 |
| HTTP 오류, 시간 초과, 취소 | [02-5 spec.md](../02-5-transport/spec.md)와 같다 | 키, base_url 호스트 |
- 오류의 Display·Debug에 키와 base_url 호스트가 없다.

## 기본값
[02-2 spec.md](../02-2-config/spec.md)의 `http` 기본값(연결 10초, 헤더 대기 300초, 스트림 유휴 120초)을 그대로 쓴다.

## AC
1. Given 엔드포인트 2개, 모델 3개, 모의 서버 2개가 있을 때, When 모델 이름으로 클라이언트를 만들어 요청하면, Then 그 모델이 가리키는 엔드포인트의 모의 서버로만 요청이 가고, 요청 본문에 그 모델의 id와 샘플링이 쓰인다.
2. 설정에 없는 모델 이름은 이름만 밝힌 오류로 끝난다.
3. Given 모의 서버가 `GET /models`에 응답할 때 모델 id 목록을 돌려주고, `data`가 없거나 `id`가 문자열이 아니면 형식 오류로 알린다. 오류에는 키와 주소가 없고, 취소와 시간 초과는 02-5와 같이 동작한다(테스트).
