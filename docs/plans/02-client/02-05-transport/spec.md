# 02-5 클라이언트 트레이트와 스트리밍 전송: 명세

- 상위 문서: [plan.md](plan.md)
- 결정: [D15](../../../DECISIONS.md#d15-생각-옵션과-추가-요청-값), [D26](../../../DECISIONS.md#d26-02-4-재시도-비대상402-등과-입력-매핑), [D28](../../../DECISIONS.md#d28-02-클라이언트-브랜치-리뷰-1-보정-범위-2026-11-03)

## 입력과 출력
- 입력
  - 요청: 모델 id, 메시지, 도구, 샘플링, 모델의 `reasoning`과 `extra`(있으면).
  - 취소 토큰.
  - 엔드포인트 정보: base_url(`/v1`까지 포함), 서버 종류 `kind`, 키(자격 파일에 있으면, 키 정하기는 [02-2](../02-02-config/spec.md)), 시간 설정([02-2 spec.md](../02-02-config/spec.md)의 기본값 참조).
- 출력: 이벤트 스트림. 이벤트의 종류와 복원 결과는 [02-3 spec.md](../02-03-sse/spec.md)와 같다. 스트림이 끝나면 사용량(또는 "없음")과 시각(요청 시작·첫 토큰·마지막 토큰)을 돌려준다.
- 실패하면 오류. 오류의 종류는 아래에 있다. 02-6이 [02-4](../02-04-retry/spec.md)에 넣을 수 있도록 헤더 전 연결 실패는 `PreHeaderConnectKind`와 같은 세부로 구분한다(D26).

## 동작 규칙

### 요청
- 대화는 `{base_url}/chat/completions`로 스트리밍 요청한다. `base_url`에 scheme을 붙이지 않고 그대로 이어 붙인다(D19).
- 요청 본문에는 모델 id, 메시지, 도구, 샘플링을 넣는다.
- `tool_choice`, `n`, `stream_options`는 보내지 않는다.
- 모델에 `reasoning`이 있으면 아래 표로 바꿔 본문에 넣는다(D15). 없으면 관련 필드를 보내지 않는다.
- 값 매핑: `off`→`none`, `low`/`medium`/`high`는 그대로. enum 밖 값은 `extra`에만 둔다(설정 검증이 이미 네 값만 허용).

| `kind` | 본문에 넣는 형태 |
|---|---|
| `openai`, `ollama`, `vllm`, `llamacpp` | `"reasoning_effort": "<값>"` |
| `openrouter` | `"reasoning": { "effort": "<값>" }` |
| `lmstudio` | 공통 thinking 필드를 **넣지 않는다**. 필요하면 `extra`에만 적힌 키를 합친다 |

- 모델에 `extra`가 있으면 그 값(하위 객체 포함)을 본문에 그대로 합친다. 예약 키(`model`, `messages`, `stream`, `tools`)는 [02-2](../02-02-config/spec.md)가 이미 거부했으므로 본문의 이 키들은 클라이언트가 채운 값이다.
- 키는 `Authorization: Bearer` 헤더에만 넣는다. 본문, URL, 다른 헤더에는 넣지 않는다.
- 엔드포인트에 키가 없으면 Authorization 헤더 없이 요청한다.

### 응답
정상
- 서버가 보내는 스트림은 [02-3](../02-03-sse/spec.md)과 같은 규칙으로 복원한다.
- 사용량은 서버가 주면 그 값이고, 주지 않으면 "없음"이다.
- 시각은 요청 시작, 첫 토큰, 마지막 토큰 순서로 남는다. 평균으로 줄이지 않고 요청별 원시 시각을 돌려준다.

경계(시간 초과)
- 연결 시간 초과는 HTTP 라이브러리의 연결 시간 설정에 맡긴다.
- 헤더 대기 시간과 스트림 유휴 시간은 따로 잰다.
- 헤더가 유휴 시간 설정보다 늦지만 헤더 대기 시간 설정 안에 오면 성공한다.
- 헤더가 끝내 오지 않으면 헤더 대기 시간 초과로 끝난다.
- 헤더 이후 본문이 멈추면 유휴 시간 초과로 끝난다.

취소
- 스트림 도중 취소하면 500ms 안에 취소 오류 하나를 내고 스트림이 끝난다.
- 취소하면 연결을 정리해 서버 쪽 연결이 3초 안에 닫힌다.

디코더 계약(D28)
- 스트림에 붙인 `StreamDecoder`가 한 번 `Err`를 낸 뒤, 같은 인스턴스에 `push`·`finish`를 다시 불러도 **성공으로 오해할 수 있는 `Ok`를 내지 않는다**(실패를 유지하거나, 전송 층이 첫 `Err` 이후 디코더를 쓰지 않음을 테스트로 고정).

오류
- 아래 표의 실패를 오류로 알린다.
- 서버 오류 본문은 어림 가리기 뒤, **이 요청에 알고 있는 키·base_url 호스트 문자열**로 한 번 더 가리고 길이를 제한해 담는다(D28).
- 이 세부 작업은 재시도하지 않는다(재시도는 [02-6](../02-06-retry-apply/spec.md)).

## 오류 종류와 담는 것
헤더 전 연결 세부는 코드의 `PreHeaderConnectKind`와 이름을 맞춘다. 02-6이 [02-4 매핑 표](../02-04-retry/spec.md)로 옮긴다(D26).

| 오류 | 담는 것 | 담지 않는 것 | 02-4 입력(참고) |
|---|---|---|---|
| 연결 실패 — DNS 실패 | 종류 `DnsFailure` | 키, base_url 호스트 | 헤더 전 연결(후보) |
| 연결 실패 — 연결 거부 | 종류 `ConnectionRefused` | 키, base_url 호스트 | 헤더 전 연결(후보) |
| 연결 실패 — 연결 시간 초과 | 종류 `ConnectTimeout`, 설정 초 값(D14) | 키, base_url 호스트 | 헤더 전 연결(후보) |
| 연결 실패 — 헤더 전 재설정 | 종류 `ResetBeforeHeaders` | 키, base_url 호스트 | 헤더 전 연결(후보) |
| 연결 실패 — TLS | 종류 `Tls` | 키, base_url 호스트 | 헤더 전 연결(후보) |
| 연결 실패 — 프록시 등 | 종류 `Proxy` | 키, base_url 호스트 | 헤더 전 연결(후보) |
| 헤더 대기 시간 초과 | 구간(헤더 대기), 설정 초 값 (D14) | 키, base_url 호스트 | 헤더 대기 초과(비후보) |
| 스트림 유휴 시간 초과 | 구간(유휴), 설정 초 값 (D14) | 키, base_url 호스트 | 02-4 입력 아님 |
| 비정상 HTTP 상태 | 상태 코드, 가린 뒤 길이를 제한한 본문 요약 | 키, base_url 호스트 | 상태·402 등(02-4 표) |
| 스트림 오류, 형식 오류 | [02-3 spec.md](../02-03-sse/spec.md)와 같다 | 키, base_url 호스트 | 02-4 입력 아님 |
| 취소 | 취소됨 | 키, base_url 호스트 | 02-4 입력 아님 |

- 오류의 Display·Debug에 키와 base_url 호스트가 없다.
- 시간 초과 오류에 담는 구간 이름과 설정 초 값은 비밀 값이 아니다(D14).

## 기본값
[02-2 spec.md](../02-02-config/spec.md)의 `http` 기본값: 연결 10초, 헤더 대기 300초, 스트림 유휴 120초. 테스트는 짧은 시험용 값을 준다.

## AC
1. Given 모의 SSE 서버가 [02-3 AC 1](../02-03-sse/spec.md)과 같은 형식을 보낼 때, When 끝까지 받으면, Then 02-3과 같은 결과로 복원된다. 디코더가 한 번 실패한 뒤에는 같은 인스턴스로 성공 `Ok`를 내지 않는다(또는 전송 층이 첫 `Err` 이후 디코더를 쓰지 않음을 테스트로 확인)(D28).
2. 모델의 `reasoning`·`extra`가 위 `kind` 표대로 요청 본문에 들어간다(모의 서버로 본문 확인: `reasoning_effort` / OpenRouter 중첩 / `lmstudio`는 공통 필드 없음). 키는 `Authorization: Bearer` 헤더에만 들어가고, 키가 없는 엔드포인트는 Authorization 헤더 없이 요청한다. 서버가 오류 본문에 키를 되돌려 줄 때와 연결이 실패할 때도, 알고 있는 키·호스트로 한 번 더 가린 뒤 Display·Debug에 키와 base_url 호스트가 없다(테스트, D28).
3. 헤더가 유휴 시간 설정보다 늦지만 헤더 대기 시간 설정 안에 오면 성공하고, 헤더가 끝내 오지 않으면 헤더 대기 시간 초과, 본문이 멈추면 유휴 시간 초과로 끝난다.
4. 스트림 도중 취소하면 500ms 안에 취소 오류 하나를 내고 스트림이 끝나며, 서버 쪽 연결이 3초 안에 닫힌다(테스트).
5. 사용량은 서버가 주면 그 값, 주지 않으면 "없음"이고, 시각은 요청 시작, 첫 토큰, 마지막 토큰 순서다(테스트).
6. 헤더 전 연결 실패는 위 표의 세부 종류(`DnsFailure` 등)로 구분되어 오류에 담기고, 02-4 매핑 표의 「헤더 전 연결」 후보와 맞는다(단위 또는 통합 테스트, D26).
