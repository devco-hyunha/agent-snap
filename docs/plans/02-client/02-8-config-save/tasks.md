# 02-8 설정 저장: 작업 계획

- 상위 문서: [plan.md](plan.md), [spec.md](spec.md)
- 검증 명령과 공통 DoD는 [상위 문서](../../02-client.md)의 '세부 작업 공통 기준'을 따른다.

## 구현 단계
- [ ] 1. 주석을 보존하며 JSONC를 고치는 방식을 정한다. 필요한 크레이트는 라이선스를 확인하고, 파일 원자적 교체와 주석 보존 편집 자료를 조사해 `docs/RESEARCH.md`에 적는다. 확인: `docs/DECISIONS.md`에 결정과 라이선스 확인이 있고 RESEARCH.md에 실제로 열어 본 링크만 있다.
- [ ] 2. JSONC 쓰기를 만든다. 엔드포인트 추가·수정·삭제와 모델 옵션 쓰기, 키 칸은 쓰지 않음, 주석과 손대지 않은 항목 보존, 파일이 없으면 새로 만듦. 확인: 주석이 든 파일에 저장한 뒤 주석·다른 항목이 그대로이고 다시 읽으면 검증을 통과하는 단위 테스트(AC 1).
- [ ] 3. 자격 파일 쓰기를 만든다. `api_keys` 아래 키 추가·바꾸기, 주석과 다른 항목 보존, 파일이 없으면 새로 만듦, 이름 변경 시 키 이름 변경, 삭제 시 키 삭제. 확인: 쓴 뒤 02-1 해석으로 다시 읽어 같은 값이고 주석과 다른 항목이 그대로임을 확인하는 단위 테스트(AC 2, 3).
- [ ] 4. 안전한 쓰기를 만든다. 임시 파일에 쓰고 바꾸기, 쓰기 전 02-2 검증, 두 파일을 함께 바꿀 때의 순서. 확인: 교체 실패를 일으켜 기존 파일이 그대로이고 임시 파일이 남지 않음을 확인하는 단위 테스트, 검증 실패 입력에 파일이 바뀌지 않음을 확인하는 단위 테스트(AC 4).
- [ ] 5. 모든 저장 오류의 Display·Debug에 키 값과 base_url이 없음을 모아 확인한다(AC 5).
- [ ] 6. `docs/RESEARCH.md`에 1단계 조사 항목의 적용 위치를 적고, 구현 중 결정을 `docs/DECISIONS.md`에 적는다.

## 테스트 계획
- 종류: 네트워크 없는 단위 테스트. 임시 폴더에서 파일을 쓴다.
- 주입할 것: 파일 교체 실패(시험용), 설정 폴더 경로.
- 테스트 파일은 관심사별로 나눈다(설정 파일 쓰기, 자격 파일 쓰기, 안전한 쓰기, 오류 가리기). 측정은 dev-principles 3절(DRY)·6절(이름과 함수)로 한다(`.agents/skills/dev-principles/SKILL.md`, Claude Code와 Cursor는 `.claude/skills/dev-principles/SKILL.md`).
