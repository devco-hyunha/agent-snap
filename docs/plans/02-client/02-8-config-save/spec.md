# 02-8 설정 저장: 명세

- 상위 문서: [plan.md](plan.md)

## 입력과 출력
- 엔드포인트 저장(추가·수정)
  - 입력: 사용자 설정 폴더 경로, 엔드포인트 항목(`name`, `base_url`, `kind`), 그 엔드포인트를 쓰는 모델의 옵션(`reasoning`, `extra`, 샘플링), 선택 키 값(비밀 값). 수정이면 바꾸기 전 이름.
  - 출력: 성공 또는 저장 오류. 성공하면 폴더의 `agent-snap.jsonc`와 `credentials.jsonc`가 바뀐다.
- 엔드포인트 삭제
  - 입력: 사용자 설정 폴더 경로, 엔드포인트 이름.
  - 출력: 성공 또는 저장 오류.

## 동작 규칙

### 설정 파일 쓰기 (D16)
- 엔드포인트 항목에는 `name`, `base_url`, `kind`만 쓴다. 키 칸은 쓰지 않는다(D10).
- 모델 옵션은 해당 모델 항목에 쓴다.
- 사용자가 단 주석과 이번 저장이 건드리지 않은 항목은 그대로 남는다.
- 파일이 없으면 새로 만든다.

### 자격 파일 쓰기 (D16)
- 키는 `credentials.jsonc`의 `api_keys` 아래에 엔드포인트 이름을 키로 쓴다. 이름은 적힌 그대로 쓴다.
- 이미 있는 이름이면 그 값을 바꾸고, 없으면 항목을 더한다. 사용자가 단 주석과 다른 항목은 그대로 남는다.
- 쓴 파일을 [02-1](../02-1-secrets/spec.md) 해석으로 다시 읽으면 같은 값이 나와야 한다.
- 키 값을 주지 않은 수정은 자격 파일의 기존 키를 그대로 둔다.
- 이름을 바꾸면 자격 파일의 기존 키 이름을 새 이름으로 바꾼다(값은 그대로). 기존 키가 없으면 아무것도 하지 않는다.
- 엔드포인트를 삭제하면 자격 파일의 그 키를 지운다. 키가 없으면 아무것도 하지 않는다.
- 파일이 없으면 새로 만든다.

### 안전한 쓰기
- 각 파일은 같은 폴더의 임시 파일에 먼저 쓰고, 다 쓴 뒤 바꾼다. 쓰는 도중 실패하면 기존 파일은 바뀌지 않고 임시 파일은 정리한다.
- 쓰기 전에 바뀐 결과를 [02-2](../02-2-config/spec.md) 검증에 통과시킨다. 통과하지 못하면 어느 파일도 바꾸지 않고 02-2와 같은 이름만 밝힌 오류를 낸다.
- 이름 바꾸기처럼 두 파일을 함께 바꿀 때 한쪽만 바뀐 채 끝나지 않도록 쓰는 순서를 정한다(구현 때 정해 문서에 적는다).

## 오류 종류와 담는 것
| 오류 | 담는 것 | 담지 않는 것 |
|---|---|---|
| 검증 실패 | 02-2와 같다 | base_url, 키 |
| 파일 쓰기·교체 실패 | 대상 파일 종류(설정, 자격), 오류 종류 | 경로 전체, 키 값, base_url |
| 수정·삭제할 엔드포인트 없음 | 엔드포인트 이름 | 주소, 키 |
- 모든 오류의 Display·Debug에 키 값이 없다.

## 기본값
없음.

## AC
1. Given 사용자가 주석을 단 `agent-snap.jsonc`가 있을 때, When 엔드포인트를 추가하거나 수정해 저장하면, Then 다시 읽으면 02-2 검증을 통과하며 새 값이 읽히고 사용자 주석과 손대지 않은 항목이 그대로 남는다.
2. Given 주석을 단 `credentials.jsonc`가 있고 키 값과 함께 저장할 때, When 저장하면, Then 키는 자격 파일의 `api_keys` 아래 엔드포인트 이름에만 쓰이고(02-1 해석으로 다시 읽으면 같은 값, 사용자 주석과 다른 항목은 그대로) 설정 파일 어디에도 키 값이 없다.
3. Given 엔드포인트 이름을 바꿀 때, When 저장하면, Then 자격 파일의 키 이름도 새 이름으로 바뀌고 값은 그대로이며, 삭제하면 그 키도 지워진다.
4. Given 쓰는 도중 실패를 일으킬 때(교체 실패 시험), When 저장하면, Then 기존 설정 파일과 자격 파일이 바뀌지 않고 임시 파일이 남지 않는다. 02-2 검증에 실패하는 입력도 어느 파일도 바꾸지 않는다.
5. 모든 저장 오류의 Display·Debug에 키 값과 base_url이 없다(테스트).
