# 02-8 설정 저장: 상세 기획

- 상태: planned
- 상위 문서: [02-client.md](../../02-client.md)

## 목적
엔드포인트를 추가·수정·삭제하고 키를 저장하는 기능을 라이브러리에 둔다. 나중에 화면(UI)이 이 기능을 불러 쓴다. 사용자가 손으로 쓴 설정 파일을 저장 한 번으로 망가뜨리지 않고, 키가 설정 파일로 퍼지지 않게 한다(DECISIONS D16).

## 범위(In)
- 엔드포인트 추가·수정·삭제: `agent-snap.jsonc`에 `name`, `base_url`, `kind`와 모델 옵션(`reasoning`, `extra`, 샘플링)을 쓴다.
- 키 저장: 자격 파일 `credentials.jsonc`의 `api_keys` 아래 엔드포인트 이름으로만 쓴다. 저장 기능은 설정 파일에 키를 쓰지 않는다.
- 엔드포인트 이름을 바꾸면 자격 파일의 키 이름도 함께 바꾼다. 엔드포인트를 삭제하면 자격 파일의 그 키도 지운다.
- 보존: 설정 파일과 자격 파일 모두 다시 쓸 때 사용자가 단 주석과 손대지 않은 항목이 그대로 남는다.
- 안전한 쓰기: 임시 파일에 쓰고 바꾸기. 쓰는 도중 실패해도 기존 파일이 깨지지 않는다.
- 저장하기 전에 결과를 [02-2](../02-2-config/plan.md) 검증에 통과시킨다.

## 비범위(Out)
- 화면(UI): 이 작업 범위가 아니다.
- 설정 읽기와 검증: [02-2](../02-2-config/plan.md). 이 세부 작업은 그 검증을 다시 쓴다.
- 자격 파일 해석: [02-1](../02-1-secrets/plan.md). 이 세부 작업은 02-1 해석으로 다시 읽어 같은 값이 나오는 형태로만 쓴다.
- 환경 변수 쓰기, 여러 프로세스가 동시에 저장할 때의 잠금.
- 설정 파일 백업과 되돌리기.

## 참고 자료
- DECISIONS
  - D10: 설정 파일과 자격 파일 분리, JSONC 형식, 키는 `api_keys` 아래 엔드포인트 이름으로.
  - D16: 저장은 설정 파일에 엔드포인트·모델 옵션, 자격 파일에 키. 두 파일 모두 주석 보존, 이름 변경·삭제 때 키 함께 처리. 주석 보존 방식은 구현 때 크레이트 라이선스 확인과 함께 정한다.
- RESEARCH.md: 파일 원자적 교체(임시 파일에 쓰고 바꾸기)와 JSONC 주석 보존 편집은 구현 첫 단계에서 조사해 적는다. 링크는 직접 열어 확인한 것만 적는다.

## 리스크
- 주석을 보존하는 JSONC 편집은 쓸 수 있는 크레이트나 방법이 제한될 수 있다. 라이선스를 확인하고 정하며, 맞는 것이 없으면 사용자에게 보고한다.
- Windows에서 열려 있는 파일을 바꾸면 교체가 실패할 수 있다. 실패해도 기존 파일이 그대로 남는지 테스트로 확인한다.
- 키 값이 오류나 임시 파일 이름으로 새면 노출된다. 모든 오류의 Display·Debug에 키 값이 없음을 테스트로 확인한다.
- 이름을 바꾸다 한쪽 파일만 바뀌면 키와 엔드포인트가 어긋난다. 두 파일을 쓰는 순서와 실패 시 상태를 구현 때 정해 테스트한다.
