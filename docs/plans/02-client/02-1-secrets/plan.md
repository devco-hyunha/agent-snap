# 02-1 비밀 값 래퍼와 자격 파일 읽기: 상세 기획

- 상태: done
- 상위 문서: [02-client.md](../../02-client.md)

## 목적
키를 가린 채 다루고, 사용자 설정 폴더의 자격 파일 `credentials.jsonc`에서 엔드포인트 이름으로 찾는다(DECISIONS D10). 이후 모든 세부 작업이 키와 주소를 이 세부 작업의 비밀 값 래퍼로 다루므로, 가장 먼저 만든다.

## 범위(In)
- 비밀 값 래퍼: Debug와 Display에서 값을 가리고, 값은 명시적으로만 꺼낸다.
- 자격 파일 읽기: JSONC(주석과 마지막 쉼표 허용)이고 `api_keys` 아래에 엔드포인트 이름별 문자열 키가 있다. 문법 오류는 줄 번호만, 값이 문자열이 아닌 항목은 그 엔드포인트 이름만 밝힌 오류로 거부한다.
- 키 찾기: 엔드포인트 이름으로 `api_keys`에서 값을 찾는다. 이름은 적힌 그대로 쓰고 대소문자와 `-`·`_`를 구분한다. 못 찾거나 빈 문자열이면 "없음"이고, 자격 파일이 없어도 "없음"이다.
- JSONC 해석 크레이트의 라이선스 확인과 선택. 02-2와 02-8이 같은 해석기를 쓴다.

## 비범위(Out)
- 사용자 설정 폴더 위치 계산과 설정 파일 읽기: [02-2](../02-2-config/plan.md)에서 다룬다. 이 세부 작업은 자격 파일의 내용을 받아 해석한다.
- 설정 파일에 `api_key` 칸이 있을 때의 거부: [02-2](../02-2-config/plan.md).
- 키를 HTTP 요청에 싣는 일: [02-5](../02-5-transport/plan.md).
- 자격 파일 쓰기: [02-8](../02-8-config-save/plan.md).

## 리스크
- JSONC 해석기의 오류 메시지에 값이 담길 수 있다. 오류를 줄 번호만 담는 형태로 바꿔 보고하는 것을 테스트로 확인한다.
- 값이 문자열이 아닌 항목의 오류에 값이 새면 키가 노출된다. 엔드포인트 이름만 담고 모든 오류의 Display·Debug를 테스트로 확인한다.
- 엔드포인트 이름과 자격 파일의 이름이 한 글자라도 다르면 키를 못 찾고 키 없이 요청한다. 이름을 그대로 비교하고, 서버가 인증 오류를 돌려주면 사용자가 이름을 맞추게 한다.
