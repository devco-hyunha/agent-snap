## 목적

설정 파일 `snap.jsonc`와 자격 파일 `credentials.jsonc`에 값을 쓰는 저장을 라이브러리에 둔다. 사용자가 엔드포인트와 모델을 추가·수정·삭제하고, 키는 자격 파일에만 저장하게 하기 위함이다. 두 파일 모두 사용자가 단 주석과 손대지 않은 항목을 그대로 보존한다. 화면(UI)은 두지 않고 라이브러리 기능만 둔다.

## 리서치 및 설계 근거

- 리서치 조사(2026-11-28, 읽기 전용 서브): `jsonc-parser` 0.34.0에 `cst` 기능을 켜면 `CstRootNode`가 모든 주석과 공백을 유지한 채 값만 편집해 다시 쓴다. `ast`는 주석을 모음으로만 담고 `serde_json::Value`로 옮기면 주석이 사라진다. 저장소의 해석 창구(기획 시점에는 `crates/snap-core/src/jsonc.rs`, T1 이후에는 `crates/snap-core/src/jsonc/parse.rs`)는 `parse_to_serde_value`만 쓰므로 저장에 쓸 수 없었다.
- 기각한 대안: `jsonkit` 0.3.0은 주석을 지우는 도구(`strip_comments`·`minify` 전용), `json-patch` 5.0.0은 `serde_json::Value` 대상이라 주석 개념 없음, `jsonformat` 2.1.0은 포맷 전용. `monochromatic-jsonc-edit` 0.1.3은 주석 보존 편집을 제공하지만 LGPL-3.0이라 결정 4번의 allow 목록(OSI·FSF 관례 10종, copyleft 거부)에 걸려 기각.
- 파일 교체 근거: `tempfile::NamedTempFile::new_in(원본 폴더)` + `persist()`가 같은 볼륨을 보장하고 원자적으로 교체한다. `std::fs::rename`은 마운트 지점이 다르면 실패하고, copy 대체 경로는 반쯤 쓴 상태를 남길 수 있어 쓰지 않는다. Windows는 다른 프로세스가 파일을 열면 교체가 실패하고, 유닉스는 성공하지만 열려 있던 쪽은 옛 inode에 남는다.
- 자체 텍스트 치환 방식 기각: 주석 안 키 이름 오탐, 문자열 안 `//`, 배열 안 중복 키, CRLF·BOM 위험이 있고 토큰 범위 기반으로 방어해야 한다. `cst`가 있으면 필요하지 않다(YAGNI).
- 사용자 결정(2026-11-28): 저장 API는 연산 단위(엔드포인트·모델·키 추가·수정·삭제)로만 노출하고 파일 전체를 통째로 갈아쓰는 함수는 두지 않는다. 범위에 모델 연산을 포함한다. 자격 파일 키 저장(추가·수정·삭제)을 이번 범위에 넣는다. 파일 교체는 `tempfile`을 제품 의존으로 추가해 쓴다. 저장 직전에 기존 검증을 재사용해 통과 못 하면 거부한다. 파일이 없으면 새로 만든다(폴더가 없으면 폴더도 생성).
- 결정 6번 다 볼 점 해소: CST 편집은 텍스트 위치에서 값만 고르므로 키 순서가 저절로 보존된다. `serde_json`의 `preserve_order` 기능은 켜지 않는다.

## 범위(In)

- `jsonc-parser`의 `cst` 기능을 켜고, 주석·공백·정렬을 보존하는 편집 창구를 둔다.
- `tempfile`을 제품 의존으로 추가해, 원본 폴더에 임시 파일을 쓰고 원본과 교체하는 원자 저장을 둔다. 설정 폴더가 없으면 만든다.
- 엔드포인트 추가·수정·삭제 연산을 `snap.jsonc` 저장에 둔다.
- 모델 추가·수정·삭제 연산을 `snap.jsonc` 저장에 둔다.
- 키 추가·수정·삭제 연산을 `credentials.jsonc` 저장에 둔다. 키 값은 자격 파일에만 쓴다.
- 저장 직전에 기존 설정 검증(`check_config`)과 자격 구조 검사를 재사용하고, 통과하지 못하면 쓰지 않는다.
- 저장 실패 오류 타입과 거부 문구(한국어·영어)를 locale에 둔다.

## 리스크

- CST 편집은 루트 노드를 드롭하면 조상 약참조가 사라져 패닉이 난다. 노드 수명을 함수 안에서만 쓰고 시험으로 확인한다.
- 저장 직전 검증은 편집 결과 텍스트를 다시 해석해 검사하는 왕복이다. 검증이 편집과 어긋나면 저장만 되고 읽기 실패가 생긴다. 왕복 시험으로 확인한다.
- Windows는 다른 프로세스가 파일을 열면 교체가 실패한다. 실패 시 원본이 그대로인지 확인하는 시험을 둔다.
- 자격 파일이 없을 때 새로 만드는 형식(최상위 `api_keys` 객체)이 읽기 규칙과 맞아야 한다. 읽기 시험과 같은 재료를 쓴다.
- `tempfile`을 제품 의존으로 추가하면 `cargo deny check` 대상이 늘어난다. 결정 4번 allow 목록 안에서 통과하는지 확인한다.

## AC

1. Given 엔드포인트가 하나도 없는 설정 파일일 때, When 엔드포인트 추가 연산을 부르면, Then 파일에 그 엔드포인트가 추가되고 다시 읽었을 때 그 엔드포인트가 보인다.
2. Given 설정 파일에 사용자가 단 주석이 있을 때, When 엔드포인트·모델 연산을 부르면, Then 그 주석과 손대지 않은 항목이 그대로 남는다.
3. Given 같은 이름의 엔드포인트가 있을 때, When 수정 연산을 부르면, Then 그 항목만 바뀌고 다른 항목은 그대로다.
4. Given 모델이 있는 엔드포인트에서 모델 추가·수정·삭제 연산을 부르면, Then `endpoints[].models` 안 항목만 바뀌고 엔드포인트 항목은 그대로다.
5. Given 키 추가 연산을 부르면, Then 키 값이 `credentials.jsonc`에만 쓰이고 `snap.jsonc`에는 키 칸이 생기지 않는다.
6. Given 검증 규칙에 걸리는 값(예: `api_key` 칸, 0 이하 `context_window`)으로 저장을 부르면, Then 저장이 거부되고 원본 파일이 그대로다.
7. Given 설정 파일·자격 파일·폴더가 없을 때, When 저장 연산을 부르면, Then 파일과 폴더가 새로 만들어진다.

## 시험 계획

- 임시 폴더(`tempfile`)에서 파일을 읽고 쓰는 왕복 시험을 둔다. 네트워크는 쓰지 않는다.
- 주석 보존 시험은 사용자가 단 주석(줄 주석·블록 주석)이 있는 파일을 재료로 쓴다.
- 거부 시험은 원본 파일 내용이 그대로인지(해시·문자열 비교)로 확인한다.
- 키 가리기 시험은 오류 Display·Debug에 키 값이 안 나오는지로 확인한다.
- OS별 실경로 확인은 Windows·WSL 양쪽에서 같은 책임을 확인하는 시험을 둔다.
