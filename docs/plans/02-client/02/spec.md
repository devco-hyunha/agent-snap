# 02-2 명세와 AC

- 상위 문서: [plan.md](plan.md)

## 입력과 출력
- 설정 읽기
  - 입력: snap 설정 폴더 경로(02-1의 `config_dir`를 주입으로 받는다). 폴더 안 `snap.jsonc`를 읽는다. 주석(`//`, `/* */`)과 마지막 쉼표를 허용한다.
  - 출력: 검증을 통과한 설정(`language`, 엔드포인트 목록과 각 엔드포인트 아래 모델 목록, 샘플링 기본값, 시간·재시도 값). 실패하면 설정 오류. 내부 진실은 중첩(`endpoints[].models`)으로 보관한다.
- 키 정하기
  - 입력: 검증된 엔드포인트, 자격 파일에서 읽은 이름별 값(02-1).
  - 출력: 그 엔드포인트의 비밀 값 또는 키 없음.

## 설정 항목
- `language`: 기본 `ko`. 허용값은 `ko`, `en`. 모르는 값은 설정 오류로 거부한다. locale 선택 코드는 바꾸지 않는다(작업 04).
- `endpoints`: `name` 필드를 가진 배열. 생략·빈 배열 허용, 생략은 `[]`로 정규화한다.
- 엔드포인트: 필수 `name`, `base_url`(`SecretString`으로 담음), `kind`, 그 아래 `models` 배열. 키 칸(`api_key`, `api_key_env`)은 없다.
- `kind` 허용값: `openai`, `openrouter`, `ollama`, `vllm`, `llamacpp`, `lmstudio`. 서버 전체 목록이 아니라 OpenAI 호환 공통 형식에서 요청 필드 이름이 다른 서버를 가르는 값이다. 모르는 값은 엔드포인트 이름만 밝히고 거부한다. 목록 밖 서버는 `extra`로 우회한다.
- `base_url` 검증: scheme을 `http`/`https`로만 한정(scheme은 대소문자 구분 없음). 빈 문자열·앞뒤 공백·끝 슬래시 거부. 호스트와 `/v1` 경로는 검사하지 않는다.
- 모델(`endpoints[].models`): 필수 `name`, 서버에 보낼 `id`(둘 다 trim 후 비면 거부). 선택 `sampling`, `reasoning`, `extra`. 모델에 `endpoint` 칸은 없다.
- `sampling`: 샘플링 기본값. 모델별 값이 있으면 모델별 값이 앞선다(적용은 02-7). 지원하는 항목은 `temperature`, `top_p`, `max_tokens` 세 가지다. 없는 항목은 요청 본문에 싣지 않아 서버 기본을 따른다.
- `extra`: 공통 옵션에 없는 값을 하위 객체까지 담는 객체. 요청 본문에 합치는 일은 02-5가 한다.
- `http`: 시간·재시도 값. 인정 키는 `retries`, `backoff_min`, `backoff_max`, `retry_after_max`, `connect_seconds`, `header_wait_seconds`, `stream_idle_seconds` 7개만이다. 옛 toml 이름 호환은 없다.

## 기본값
- `language`: `ko`.
- `endpoints`·`models` 생략: `[]`.
- `reasoning`·`extra`: 없으면 아무것도 더하지 않는다.
- `sampling`: 모델별 값과 `sampling` 어디에도 없는 항목은 두지 않는다.
- `http`: `retries` 3, `backoff_min` 1초, `backoff_max` 30초, `retry_after_max` 60초, `connect_seconds` 10초, `header_wait_seconds` 300초, `stream_idle_seconds` 120초.

## 동작 규칙
### 정상
- 정상 설정을 읽으면 엔드포인트(그 아래 모델 포함), 샘플링, 시간 값이 읽히고 빠진 값은 기본값이 된다.
- `endpoints`·`models`가 비어 있어도 읽기는 통과한다(고를 모델 없음은 02-7·CLI).
- 자격 파일에 이름이 없는 엔드포인트를 허용한다(키가 필요 없는 로컬 서버).
- 모델 이름과 서버에 보낼 `id`는 서로 다를 수 있다.
- 다른 엔드포인트끼리는 같은 모델 별칭을 허용한다. 유일성은 같은 엔드포인트 안에서만 본다.
- 엔드포인트·모델 `name`은 trim한 뒤 저장·자격 매칭에 쓴다.
- 알 수 없는 칸(거부 칸이 아닌 것)은 무시한다.

### 키 정하기
- 자격 파일 `api_keys`에 trim한 엔드포인트 이름이 있고 빈 문자열이 아니면 그 키를 쓴다. 이름은 적힌 그대로 쓰며 대소문자와 `-`·`_`를 구분한다.
- 이름이 없거나 빈 문자열이거나 자격 파일이 없으면 키 없음이다.

### 경계
- `temperature` 0 이상 2 이하, `top_p` 0 초과 1 이하, `max_tokens` 1 이상 정수.
- 엔드포인트·모델 이름은 trim 후 비어 있지 않고 `/`를 포함하지 않는다. 선택 키 `엔드포인트이름/모델이름`의 구분자이기 때문이다. 그 밖의 형식 제한은 없다.
- `http` 시간 값은 소수 초를 허용하고 0 초과 유한한 값이어야 한다. `retries`는 0 이상 정수(0은 재시도 안 함). `backoff_min`과 `backoff_max`가 같은 값은 허용한다.
- 설정 폴더 경로를 받아 읽는 기능은 폴더 위치 계산과 독립이라 임시 폴더로 시험할 수 있다.

### 거부(이름만 밝힌 오류)
| 거부 사유 | 담는 것 | 담지 않는 것 |
|---|---|---|
| 엔드포인트에 `api_key`·`api_key_env` 칸 | 엔드포인트 이름, "키는 credentials.jsonc에 둔다" 안내 | 칸 값, `base_url` |
| 최상위 옛 `models` | "모델은 endpoints[].models에" 안내 | 모델 값, 주소, 키 |
| 모델에 `endpoint` 칸 | 모델 이름(또는 위치) | 주소, 키 |
| 엔드포인트 이름 중복(trim 후) | 엔드포인트 이름 | 주소, 키 |
| 같은 엔드포인트 안 모델 이름 중복(trim 후) | 엔드포인트 이름, 모델 이름 | 주소, 키 |
| trim 후 빈 엔드포인트 이름 | 엔드포인트 자리 표시 | 주소, 키 |
| trim 후 빈 모델 이름·빈 모델 `id` | 엔드포인트 이름, 모델 이름 | `id` 값, 주소, 키 |
| trim 후 `/`가 든 이름 | 엔드포인트 이름, 모델 이름 | 주소, 키 |
| `kind` 값 오류 | 엔드포인트 이름 | 입력 값, 주소, 키 |
| `base_url` 형식 오류 | 엔드포인트 이름 | 입력 값, 주소, 키 |
| `reasoning` 값 오류 | 모델 이름 | 입력 값, 주소, 키 |
| `extra` 예약 키(`model`, `messages`, `stream`, `tools`) | 모델 이름, 예약 키 이름 | `extra` 값, 주소, 키 |
| 샘플링 범위 벗어남·모르는 항목 | 항목 이름, 모델(또는 기본) 이름 | 입력 값, 주소, 키 |
| `http` 값 오류(0 이하·무한대·숫자 아님)·모르는 키 | `http.<항목>` 이름 | 입력 값, 주소, 키 |
| `backoff_min` > `backoff_max` | 두 항목 이름 | 입력 값, 주소, 키 |
| `language` 값 오류 | 항목 이름 | 입력 값 |
| JSONC 문법 오류 | 줄 번호 | 줄 내용, 값 |
| 빈 파일·최상위가 객체가 아님 | 오류 종류만 | 파일 내용, 주소, 키 |

- 설정의 `Debug`와 모든 설정 오류의 `Display`·`Debug`에 `base_url` 호스트와 키가 없다.

## AC
1. Given 주석이 든 정상 설정(`endpoints[].models` 중첩)과 설정 폴더 지정 값이 있을 때, When 읽으면, Then 엔드포인트·모델·샘플링·시간 값이 읽고 빠진 값·생략한 `endpoints`·`models`는 기본값(`[]` 포함)이 된다(테스트).
2. Given AC 2의 거부 사유가 각각 있을 때, When 읽으면, Then 각각 거부되고 오류에는 이름만 있고 값·주소·키는 없다(테스트). 다른 엔드포인트에 같은 모델 별칭이 있어도 허용한다.
3. Given 검증된 엔드포인트와 자격 파일의 이름별 값이 있을 때, When 키 정하기를 하면, Then trim한 이름이 있고 빈 문자열이 아니면 그 비밀 값, 없거나 빈 문자열이면 없음, 자격 파일이 없으면 없음으로 매핑된다(테스트).
4. Given JSONC 문법이 틀린 설정이 있을 때, When 읽고 확인하면, Then 줄 번호만 알리고 값·줄 내용이 없다(테스트).
5. Given 설정의 `Debug`와 모든 설정 오류의 `Display`·`Debug`와 저장소 루트의 `snap.example.jsonc`가 있을 때, When 확인하면, Then `base_url` 호스트와 키가 가려지고(테스트), 예시 파일은 자리표시자만 담고 읽으면 검증을 통과한다(테스트).
6. 게이트 3종이 Windows와 WSL(Ubuntu)에서 통과하고, 테스트 밖 `unwrap`/`expect`/`panic` 0건, 공개 항목에 한국어 문서 주석.
7. `jsonc-parser` 라이선스 확인이 `docs/DECISIONS.md`에 있고, 리뷰 기록이 `docs/reviews/02/`에 있다.

## 테스트 배치(책임별 파일)
- 읽기와 기본값: 정상 설정, 빠진 값, 빈 목록.
- 검증: 이름 규칙, `kind`, `reasoning`, `base_url`, `sampling`, `http`, `extra` 예약 키, 거부 칸 4종.
- 키 정하기: 이름 있음, 빈 문자열, 이름 없음, 자격 파일 없음.
- 오류 가리기: `Debug`·`Display` 가림, JSONC 줄 번호.
- 예시 파일: `snap.example.jsonc` 읽기 통과.
- 해석기: 자격 파일 읽기가 같은 해석기를 쓰되 02-1 규칙(형식·trim·None)이 그대로임을 확인.

## 02-1 계승 시험
02-1의 시험 13개(비밀 값 래퍼 가리기, 자격 파일 이름 조회, trim, 이름 없음, `api_keys` 누락, 값 타입 오류, 파일 없음, 설정 폴더 경로)는 해석기 교체 뒤에도 그대로 통과해야 한다. 규칙을 바꾸지 않고 파서만 교체한다.
