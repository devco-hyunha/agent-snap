# 02-2 설정 읽기와 검증: 상세 기획

- 상태: planned
- 상위 문서: [02-client.md](../../02-client.md)

## 목적
`agent-snap.jsonc`를 읽어 엔드포인트, 모델, 샘플링, 시간 설정으로 검증하고, 엔드포인트마다 쓸 키를 자격 파일에서 정한다(D10). 이후 세부 작업이 이 설정 값만 믿고 쓸 수 있게, 잘못된 설정은 읽는 시점에 이름만 밝힌 오류로 거부한다.

## 범위(In)
- 설정 항목: `target_language`(기본 `ko`), 엔드포인트 목록(`name`, `base_url`, `kind`), 모델 목록(이름, 서버에 보낼 id, 쓸 엔드포인트 이름, 모델별 샘플링, 선택 `reasoning`, 선택 `extra`), `sampling` 기본값, `http` 시간·재시도 값.
- 모델 이름과 id를 따로 둔다(서버가 파일 경로를 id로 줄 수 있다).
- base_url은 비밀 값 래퍼([02-1](../02-1-secrets/plan.md))로 담는다.
- 키 정하기: 자격 파일 `credentials.jsonc`의 `api_keys`에 엔드포인트 이름이 있으면 그 키, 없으면 키 없음(D10). 이름으로 찾는 일은 02-1을 쓴다.
- 엔드포인트에 `api_key` 칸이 있으면 값을 출력하지 않고 "키는 credentials.jsonc에 둔다"는 설정 오류로 거부한다(D10).
- 사용자 설정 폴더 위치 계산(Windows는 Roaming AppData, 그 밖은 XDG 관례)과, 폴더 경로를 받아 설정을 읽는 기능을 나눠 둔다.
- 검증: 엔드포인트 이름 중복(정확히 같을 때만)과 이름 형식, 모델 이름 중복, 없는 엔드포인트를 가리키는 모델, `kind` 값, `reasoning` 값, `extra`의 예약 키, 샘플링 항목과 범위(D14).
- `agent-snap.example.jsonc`를 자리표시자만으로 만들고, `.gitignore`의 설정 파일 이름을 `agent-snap.jsonc`로 바꾼다.

## 리스크
- 사용자가 설정에 `api_key`를 적거나 `base_url` 값이 오류에 찍히게 할 수 있다. `api_key`는 값을 읽지 않고 칸 이름만으로 거부하며, 값을 담지 않는 오류와 비밀 값 래퍼로 막는다.
- JSONC 해석기의 오류 메시지에 값이 담길 수 있다. 오류를 줄 번호만 담는 형태로 바꿔 보고하는 것을 테스트로 확인한다. 해석 크레이트는 02-1에서 라이선스를 확인하고 정한 것을 쓴다(D10).
- 엔드포인트 이름이 자격 파일의 키 이름이 되므로 이름이 비어 있으면 키를 둘 곳이 없다. 이름이 비어 있지 않은 문자열인지 읽는 시점에 검사한다.
- 샘플링 항목과 범위를 D14에서 정했다. `temperature`(0 이상 2 이하), `top_p`(0 초과 1 이하), `max_tokens`(1 이상 정수) 세 가지이며, 범위를 벗어나거나 모르는 항목은 이름만 밝혀 거부한다. 서버가 실제로 받는 범위와 다르면 작업 06 실제 서버 확인에서 다시 본다.
