# 02-3 SSE 파싱과 델타 복원: 명세

- 상위 문서: [plan.md](plan.md)

## 입력과 출력
- 입력: 바이트 조각의 순서열. 조각 경계는 임의이며 줄 중간, 멀티바이트 문자 중간, CRLF 중간에 걸릴 수 있다.
- 출력: 조각을 넣는 동안 나오는 이벤트(content 조각, 생각 조각, 도구 호출 델타, 사용량, 끝)와, 끝까지 합친 하나의 응답(content, 생각, index별 도구 호출, 모르는 델타 필드의 원문 JSON, 사용량 또는 "없음").
- 실패하면 스트림 오류 또는 형식 오류.

## 동작 규칙

### SSE 줄 처리
정상
- 줄 끝은 CRLF, LF, CR 모두 받는다.
- `:`로 시작하는 주석 줄(`: keep-alive`, `: OPENROUTER PROCESSING`)은 이벤트를 만들지 않는다.
- 여러 `data` 줄은 개행으로 잇고, 빈 줄에서 이벤트를 내보낸다.
- 맨 앞 BOM 하나는 버린다.
- `[DONE]`을 받으면 스트림이 정상으로 끝난다.
- 조각 경계에서 잘린 줄과 멀티바이트 문자는 다음 조각과 이어 붙여 해석한다. 결과는 한 번에 넣은 것과 같다.

경계
- 스트림이 빈 줄 없이 끝나면 남은 data를 마지막 이벤트로 처리한다(D12).
- 한 바이트씩 넣어도 한 번에 넣은 것과 결과가 같다.

오류
- 마지막 이벤트가 잘린 JSON이면 형식 오류로 끝난다. 잘못된 내용을 받아들이지 않는다.
- 잘못된 JSON 청크는 형식 오류로 끝난다.

### 델타 복원
- content는 보낸 순서대로 이어 붙인다.
- 생각은 `reasoning_content`와 `reasoning` 두 이름 모두 생각으로 읽는다. 보낸 순서를 유지한다.
- tool_calls는 index별로 id, 이름, 인자 문자열을 합친다. 서로 다른 index의 델타가 번갈아 와도 index별로 합쳐진다.
- 모르는 델타 필드(예: `reasoning_details`)는 원문 JSON으로 남긴다.
- usage가 오면 그 값을 사용량으로 읽고, 오지 않으면 "없음"이다.
- 최상위 `error` 청크는 스트림 오류로 끝낸다.

## 오류 종류와 담는 것
| 오류 | 담는 것 | 담지 않는 것 |
|---|---|---|
| 스트림 오류(`error` 청크) | 서버가 준 오류의 요약(키·주소를 가린 뒤 길이를 제한해 담는다) | 키, base_url 호스트 |
| 형식 오류(잘못된 JSON, 잘린 마지막 이벤트) | 몇 번째 이벤트인지, 오류 종류 (D14) | 키, base_url 호스트, 청크 원문(서버가 되돌린 키가 섞일 수 있다) |
- 오류의 Display·Debug에 키와 주소가 없다.

## 기본값
없음.

## AC
1. Given AC 2~5의 형식이 섞인 바이트가 있을 때, When 임의 경계(한 바이트씩 포함)로 나눠 넣으면, Then 결과가 한 번에 넣은 것과 같다.
2. 주석 줄은 이벤트를 만들지 않고, content·reasoning·tool_calls가 보낸 순서대로 복원된다.
3. Given 번갈아 오는 병렬 tool_call 델타가 있을 때, Then index별로 id·이름·인자 문자열이 합쳐진다.
4. 모르는 델타 필드는 원문 JSON으로 남는다. `error` 청크는 스트림 오류로 끝나고(오류에 키·주소 없음), 잘못된 JSON은 형식 오류로 끝난다.
5. usage를 주면 그 값을, 주지 않으면 "없음"을 돌려준다.
