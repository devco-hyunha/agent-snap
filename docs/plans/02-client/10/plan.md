# 02-10 작업 02 전체 리뷰: 상세 기획

- 상태: 진행 (기획 승인 2026-11-28. `feature/client`에서 나눈 `feature/client-review`에서 착수)
- 상위 문서: [02-client.md](../../02-client.md)
- 선행 세부 작업: [02-9 설정 저장](../09/plan.md) 완료(PR #15로 `feature/client` 병합 2026-11-28). 02-1~02-9 모두 병합 완료.

## 목적

작업 02(설정과 스트리밍 클라이언트)를 닫기 위함입니다. 02-1~02-9가 만든 코드가 기획과 같은지, 하네스와 프로젝트 규칙을 지켰는지, 코드로서 견고한지를 한 번에 점검해 02 기획의 AC를 확정합니다. 새 기능은 추가하지 않습니다.

## 리서치 및 설계 근거

- 리서치 게이트 생략 근거: 새 기능을 만들지 않는 리뷰 작업이라 알고리즘·아키텍처 선정처럼 설계 결론을 바꾸는 학술·기술 판단이 없습니다(plan-harness 2절 생략 조건의 문서·리뷰 작업).
- PROJECT_RULES "작업마다 조사 기록" 규칙에 대한 미적용 이유를 `docs/RESEARCH.md` 02 절에 남깁니다(02-10 항목: 조사 미적용, 근거는 위 생략 근거).
- 리뷰 축 정본: `docs/plans/02-client.md`의 AC 4가 review-harness 체크리스트 7항목과 dev-principles 2~11절, 하네스 준수를 요구합니다. 사용자 결정(2026-11-28)으로 3축(기획·코드 정합 / 하네스 준수 / 코드 리뷰)만 씁니다.
- 저장소 전체 구조 점검은 02-2 T6·02-9 T5가 각각 계획 범위에서 수행했고, 사용자 결정(2026-11-28)으로 02-10 대상은 02 계획 범위로 좁힙니다.

## 범위(In)

- 02-1~02-9가 만든 코드와 계획 문서의 정합을 확인합니다(기획이 약속한 동작과 실제 구현이 같은지).
- 하네스·프로젝트 규칙 준수(언어·eli5, 승인·안전 6원칙, 상수·locale 배치, 책임별 파일 분리, OS 분기 분리, 시험 분리)를 확인합니다.

- 게이트 4종(Windows·WSL)과 CI 매트릭스를 재실행해 확인합니다.
- 02 기획 AC 1~4를 항목별로 확인하고, 결과를 `docs/reviews/02/`에 남깁니다.
- 결함이 나오면 02-10 잔여로 이관해 같은 계획 안에서 보정합니다(사용자 결정 2026-11-28).

## 리스크

- 02-1~02-9 개별 리뷰가 각 작업 단위만 봤기 때문에, 계획 간 경계(02-2 검증 규칙과 02-9 저장 검증 재사용, 02-5 전송과 02-6 재시도)가 서로 어긋난 채로 남았을 수 있습니다. 정합 감사(T1)가 그 경계를 먼저 봅니다.
- 감사 표가 대상 코드를 좁히면 점검이 줄어듭니다. PROJECT_RULES는 대상의 참값을 정하고 표로 채우지 않은 판정을 미완료로 봅니다.
- 결함이 많으면 02-10이 길어집니다. 잔여는 같은 계획 안에서 잇고 새 계획 번호로 분리하지 않습니다.

## AC

1. Given 02-1~02-9의 계획 문서 각 항목일 때, When 코드·시험과 대조하면, Then 약속한 동작이 코드 경로와 시험 경로로 확인되고, 확인되지 않은 항목은 차이로 기록됩니다.
2. Given 02 기획 AC 1~4일 때, When 항목별로 확인하면, Then 각 AC가 충족 근거(시험 경로 또는 확인 명령)와 함께 기록됩니다.
3. Given 02 계획 범위 코드일 때, When review-harness 체크리스트 7항목과 dev-principles 2~11절을 적용하면, Then 지적이 심각도와 함께 기록되고, 지적 0건이거나 남은 지적이 02-10 잔여로 이관됩니다.
4. Given 키 값과 `base_url` 호스트일 때, When 02 계획 범위의 Display·Debug·오류 텍스트를 확인하면, Then 어떤 출력에도 값이 나오지 않음이 시험 경로로 확인됩니다.
5. Given 게이트 4종과 CI 매트릭스일 때, When Windows·WSL과 PR CI를 재실행하면, Then 전부 통과로 기록됩니다.
6. Given T1~T4가 밝힌 결함일 때, When 02-10 잔여로 이관하면, Then 보정 후 재리뷰 PASS 기록이 `docs/reviews/02/`에 남습니다.

## 시험 계획

- 새 시험을 만들지 않습니다. 기존 시험 트리(22개 묶음, 455건)를 게이트로 재실행해 근거로 씁니다.
- 가리기 확인은 기존 `tests/*/hidden.rs`·`tests/save/redact.rs` 경로를 근거로 삼고, 계획 범위에 없는 책임이 있으면 지적으로 남깁니다.
- 네트워크는 쓰지 않습니다. CI 재실행은 기존 워크플로우를 재사용합니다.
