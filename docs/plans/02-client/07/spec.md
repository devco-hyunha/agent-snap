# 02-7 모델 선택과 모델 목록 조회: 명세

- 상태: 완료 (T1~T5 구현·개별 리뷰 PASS, 작업 단위 전체 리뷰 r1 미달 → 보정 → r2 PASS. `feature/client-endpoint`를 `feature/client`에 병합)
- 상위 문서: [plan.md](plan.md)
- 선행 결정: 14번(전송 크레이트), 15번(`reasoning` 변환), 29번(`context_window` 자동 채우기 미적용)

## 입력과 출력

- 선택 키 조립
  - 입력: 설정 파일의 `Config` 한 채, 자격 파일 키 목록, 선택 키 문자열 `엔드포인트이름/모델이름`.
  - 출력: 조립된 클라이언트(`LlmClient` 트레이트 구현, 재시도 래퍼 포함)와 서버에 보낼 모델 id.
  - 실패: 엔드포인트 이름이 설정에 없거나, 모델 이름이 그 엔드포인트 `models`에 없으면 선택 오류.
- 모델 목록 조회
  - 입력: 엔드포인트 주소(`base_url`)와 키(있으면 Bearer).
  - 출력: 모델 id 문자열 목록.
  - 실패: HTTP 오류, 응답 최상위 `data` 배열이 없음, `data` 항목의 `id`가 문자열이 아님 → 형식 오류.
- 자동 발견
  - 입력: `kind`와 `base_url`(비어 있을 수 있음).
  - 출력: `base_url`가 채워진 주소, 또는 발견 실패(정상).

## 동작 규칙

### 선택 키

- 키는 `/` 하나로 나눈 앞쪽을 엔드포인트 이름, 뒤쪽을 모델 이름으로 본다. 빈 칸(앞·뒤가 비어 있음)은 선택 오류로 거부한다.
- 이름 비교는 설정 값의 trim 결과와 그대로 견준다(02-2 정규화 규칙을 따른다).
- 조립된 클라이언트는 `HttpTransport`(02-5)에 자격 키와 `http` 설정을 넣고, 02-6의 재시도 래퍼를 씌운 것이다.
- 조립 함수는 reqwest 타입을 밖에 드러내지 않는다. `LlmClient` 트레이트로만 돌려준다.

### 모델 목록 조회

- 경로는 `{base_url}/models`를 쓴다. `base_url`이 `/v1`으로 끝나면 `/v1`을 한 번만 붙여 `{base_url}/models`가 되도록 보정한다(이중 `/v1/v1` 방지).
- 요청은 GET, 인증은 키가 있을 때만 Bearer 헤더로 보낸다(02-5 규칙 그대로).
- 응답에서 최상위 `data` 배열의 각 항목 중 문자열 `id`만 모은다. `id`가 없거나 문자열이 아니면 형식 오류로 알린다.
- `object`·`created`·`owned_by`·`meta`·`architecture`·`pricing` 등 나머지 필드는 읽지 않고 버린다.
- 빈 `data` 배열은 정상(빈 목록)으로 돌려준다.

### 자동 발견

- 대상은 `kind`가 `ollama`·`lmstudio`이고 `base_url`이 비어 있는 경우만이다. 그 밖의 `kind`는 자동 발견하지 않고 설정 입력을 요구한다.
- 기본 주소는 `ollama` = `http://127.0.0.1:11434/v1`, `lmstudio` = `http://127.0.0.1:1234/v1` 상수로 둔다.
- 프로브는 한 번만 한다. 연결이 안 되면 발견 실패로 보고 재시도·상시 폴링·캐시를 하지 않는다.
- 발견한 주소로 모델 목록 조회를 이어간다.

### 가리기

- 선택 오류·형식 오류·조회 오류의 Display·Debug에 키 값과 base_url 호스트를 넣지 않는다.
- 서버 오류 본문은 02-5의 요약·가리기 규칙(Summary_MAX_CHARS·2차 가리기)을 그대로 쓴다.

## 오류 종류와 담는 것

| 오류 | 담는 것 | 담지 않는 것 |
|---|---|---|
| 선택 키 형식 오류 | 구분자 없음·빈 칸 사실만 | 모델·엔드포인트 원문 전체 |
| 선택 대상 없음 | 엔드포인트 이름, 모델 이름 | 키, base_url 호스트 |
| 목록 형식 오류 | `data` 배열 없음·`id` 타입 아님 사실 | 응답 본문 원문 전부 |
| 목록 조회 HTTP 오류 | 상태 코드, 가린 요약 | 키, base_url 호스트 |
| 자동 발견 실패 | 대상 `kind` | 키, base_url 호스트 |

## 기본값

- 자동 발견 기본 주소: Ollama 11434, LM Studio 1234. 상수 모듈(`consts/`)에 둔다.
- 시간·재시도 값은 02-2 `http` 기본값을 그대로 쓴다(목록 조회도 같은 전송 설정 사용).

## AC

1. Given 설정에 `name: local`, `models[].name: qwen` 엔드포인트가 있을 때, When 선택 키 `local/qwen`으로 조립하면, Then 재시도 래퍼가 씌워진 `LlmClient` 구현과 모델 id(`models[].id`)가 나온다.
2. Given 선택 키에 없는 엔드포인트 이름·모델 이름을 줄 때, When 조립하면, Then 선택 오류가 나고, 그 오류의 Display·Debug에 키 값과 base_url 호스트가 없다.
3. Given 모의 서버가 `data` 배열에 `id`·`object`·`created`·`owned_by`·`pricing`을 섞어 보내고, When 목록 조회를 하면, Then `id` 문자열 목록만 나오고 나머지 필드는 결과에 없다.
4. Given 모의 서버가 최상위에 `data` 배열을 두지 않은 응답을 보낼 때, When 목록 조회를 하면, Then 형식 오류가 나고 응답 원문 전체가 오류에 담기지 않는다.
5. Given `data` 항목의 `id`가 문자열이 아닌 값일 때, When 목록 조회를 하면, Then 형식 오류가 난다.
6. Given `base_url`이 `http://127.0.0.1:PORT/v1`일 때, When 목록 조회 요청 경로를 확인하면, Then 요청 경로가 `/v1/v1/models`가 아니고 `/v1/models`다.
7. Given `kind: ollama`이고 `base_url`가 비어 있으며 모의 서버가 11434에 서 있을 때, When 자동 발견하면, Then 기본 주소가 채워지고 목록 조회가 그 주소로 이어진다. 연결이 안 되는 주소에서는 발견 실패로 끝나고 재시도 요청이 늘지 않는다.
8. Given 목록 조회가 429·5xx로 끝날 때, When 조회하면, Then 02-4 판단이 재시도 후보로 본 경우에만 재시도되고, 오류 메시지에 키·호스트가 없다.

## 시험 계획

- 02-5 모의 서버 재료를 쓴다. `/v1/models` 응답을 정상·`data` 없음·`id` 타입 오류·HTTP 오류로 나눠 만든다.
- 자동 발견은 루프백(port 0) 모의 서버로 reachable/unreachable을 만들고, 상용 기본 포트 상수는 시험에서 값으로 주입해 확인한다.
- 시간 값은 짧은 시험용 값을 주고, 경과 시간은 넉넉한 하한·상한으로만 확인한다.
- 네트워크 없는 선택 키 해석은 단위 시험으로, 전송이 얽힌 목록 조회·발견은 모의 서버 통합 시험으로 확인한다.
