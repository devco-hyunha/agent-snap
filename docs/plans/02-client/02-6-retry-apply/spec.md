# 02-6 재시도 적용: 명세

- 상위 문서: [plan.md](plan.md)

## 입력과 출력
- 입력: [02-5 spec.md](../02-5-transport/spec.md)와 같은 요청, 취소 토큰, 엔드포인트 정보. 재시도 설정값([02-2 spec.md](../02-2-config/spec.md)의 `http`).
- 출력: 02-5와 같은 이벤트 스트림. 재시도는 호출한 쪽에 보이지 않고 최종 결과만 보인다.
- 실패하면 오류. 포기하는 경우 [02-4 spec.md](../02-4-retry/spec.md)의 포기 이유(재시도 대상 아님, 횟수 초과, `Retry-After` 상한 초과)를 오류에 담는다.

## 동작 규칙

### 재시도 범위
- 재시도는 응답 헤더를 받아 스트림이 시작되기 전까지의 실패에만 적용한다.
- 재시도 여부와 대기 시간은 [02-4](../02-4-retry/spec.md)의 판단을 따른다. 재시도 대상 연결 오류와 시도 횟수 세는 법도 02-4를 따른다(D14).
- 헤더 대기 시간 초과는 재시도하지 않는다(D14).

### 경우별 동작
정상
- 상한 이하의 `Retry-After`를 단 429 뒤에 성공하면 요청이 2회 가고 성공한다. 두 요청 사이 간격은 `Retry-After` 이상이다.

경계
- 헤더 없는 503만 주는 서버에는 최초 1회와 최대 재시도 횟수만큼 요청한 뒤 포기한다.
- 재시도 대기 중 취소하면 즉시 취소로 끝난다.

거부
- 상한을 넘는 `Retry-After`는 요청 1회로 끝난다(대기 초를 밝힌 포기).
- 그 밖의 4xx는 요청 1회로 끝난다.

오류
- 스트림이 시작된 뒤 끊기면 재시도하지 않고 요청 1회로 스트림 오류가 된다. 그때까지 받은 내용은 결과에 남긴다. 처리 방식은 작업 03에서 정한다.

## 오류 종류와 담는 것
오류 종류는 [02-5 spec.md](../02-5-transport/spec.md)와 02-4의 포기 이유를 그대로 쓴다. 새 오류 종류를 만들지 않는다.
- 담는 것: 포기 이유(상태 코드, 시도 횟수, 대기 초), 스트림 도중 끊김이면 그때까지 받은 내용.
- 담지 않는 것: 키, base_url 호스트.

## 기본값
[02-2 spec.md](../02-2-config/spec.md)의 `http` 기본값: 재시도 3회, 백오프 1~30초, `Retry-After` 상한 60초. 테스트는 짧은 시험용 값을 준다.

## AC
1. Given 상한 이하의 `Retry-After`를 단 429 뒤에 성공하는 모의 서버가 있을 때, Then 요청이 2회 가고 성공하며, 두 요청 사이 간격이 `Retry-After` 이상이다.
2. Given 헤더 없는 503만 주는 모의 서버가 있을 때, Then 최초 1회와 최대 재시도 횟수만큼 요청한 뒤 포기한다(요청 수로 확인).
3. 상한을 넘는 `Retry-After`와 그 밖의 4xx는 요청 1회로 끝난다.
4. 재시도 대기 중 취소하면 즉시 취소로 끝난다.
5. 스트림 시작 후 끊기면 요청 1회로 스트림 오류가 되고, 그때까지 받은 내용은 결과에 남는다.
