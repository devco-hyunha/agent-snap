# 02-6 재시도 적용: 상세 기획

- 상태: planned
- 상위 문서: [02-client.md](../../02-client.md)

## 목적
[02-4](../02-4-retry/plan.md)의 재시도 판단을 [02-5](../02-5-transport/plan.md) 전송에 연결한다. 재시도는 이 클라이언트 한 층에서만 하며(D13), 스트림이 시작되기 전의 실패에만 적용한다.

## 범위(In)
- 응답 헤더를 받아 스트림이 시작되기 전까지만 재시도한다.
- 재시도 대기 중 취소를 받는다.
- 스트림이 시작된 뒤 끊기면 재시도하지 않고, 받은 부분은 결과에 남긴다.

## 비범위(Out)
- 재시도 판단 규칙 자체: 02-4.
- 스트림이 시작된 뒤 끊겼을 때 처리 방식(받은 부분을 이어 갈지 등): 작업 03에서 정한다.
- 에이전트 루프 쪽의 LLM 요청 재시도(D13).
- 프로세스 단위 재시도 예산.
- 모델 목록 조회에 재시도를 적용하는 일(적용하지 않기로 정했다, D14. [02-7](../02-7-model-select/spec.md) 참조).

## 선행 세부 작업
[02-5 클라이언트 트레이트와 스트리밍 전송](../02-5-transport/plan.md).

## 참고 자료
- RESEARCH.md 작업 02 절
  - RFC 6585, 4절 429: 대기 시간이 상한을 넘으면 기다리지 않고 대기 초를 밝힌 오류로 알린다.
  - OpenRouter API Rate Limits: 헤더 우선, 없으면 지수 백오프, 최대 횟수.
  - Google SRE Book, Addressing Cascading Failures: 재시도는 한 층에서만, 재시도 가능한 오류만, 횟수 제한.
  - tokio-util CancellationToken: 재시도 대기 중 취소에 `cancelled()`를 쓴다(cancel-safe).
- DECISIONS D13: 재시도는 클라이언트 한 층에서만. 작업 03 기획에서 중복 재시도가 없는지 확인한다.
- 확인된 사실: OpenRouter 무료 모델은 429가 잦다. `Retry-After` 기준으로 재시도한다.

## 리스크
- 재시도 사이 간격을 시간으로 확인하는 테스트가 흔들릴 수 있다. 시험용 시간 값을 짧게 주고 하한만 넉넉히 확인한다.
- 스트림이 시작된 뒤 끊기면 부분 응답이 남는다. 처리 방식은 작업 03에서 정한다.
- 재시도가 상위 층에서 한 번 더 일어나면 시도가 곱으로 늘어난다. 작업 03 기획에서 확인한다(D13의 다시 볼 점).
