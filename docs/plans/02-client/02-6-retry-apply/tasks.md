# 02-6 재시도 적용: 작업 계획

- 상위 문서: [plan.md](plan.md), [spec.md](spec.md)
- 검증 명령과 공통 DoD는 [상위 문서](../../02-client.md)의 '세부 작업 공통 기준'을 따른다.

## 구현 단계
- [ ] 1. 전송이 헤더를 받는 시점까지를 재시도 대상 구간으로 나눈다. 스트림이 시작된 뒤의 실패는 재시도 구간 밖이다. 확인: 코드 품질 리뷰의 경계 확인과 6단계 시험.
- [ ] 2. [02-4](../02-4-retry/tasks.md)의 판단을 부르는 재시도 반복을 전송에 연결한다. 대기 시간과 시도 횟수는 판단 결과를 따른다. 확인: 429에 `Retry-After`를 달고 이어 성공하는 모의 서버로 요청 수 2회와 간격 하한을 확인하는 통합 테스트(AC 1).
- [ ] 3. 헤더 없는 503과 횟수 초과 포기를 확인한다. 확인: 항상 503만 주는 모의 서버의 요청 수가 최초 1회와 최대 재시도 횟수의 합임을 확인하는 통합 테스트(AC 2).
- [ ] 4. 상한 초과 `Retry-After`와 그 밖의 4xx가 요청 1회로 끝남을 확인한다. 확인: 통합 테스트(AC 3).
- [ ] 5. 재시도 대기 중 취소를 받는다. 확인: 긴 대기 중 취소하면 즉시 취소로 끝나는 통합 테스트(AC 4).
- [ ] 6. 스트림 시작 후 끊김은 재시도하지 않고 받은 부분을 결과에 남긴다. 확인: 본문 일부를 보낸 뒤 연결을 끊는 모의 서버로 요청 1회와 부분 결과를 확인하는 통합 테스트(AC 5).
- [ ] 7. `docs/RESEARCH.md` 작업 02 절의 RFC 6585, OpenRouter API Rate Limits, Google SRE, tokio-util 항목에 02-6 적용 위치를 갱신한다.

## 테스트 계획
- 종류: 로컬 모의 서버 통합 테스트. 요청 수와 요청 시각은 모의 서버가 기록한다.
- 주입할 것: 시험용 재시도·시간 값(짧게), 취소 토큰, 난수 공급(백오프 시험).
- 간격은 넉넉한 하한으로만 확인한다.
- 테스트 파일은 관심사별로 나눈다(재시도 성공, 포기, 취소, 스트림 중 끊김). 측정은 dev-principles 3절(DRY)·6절(이름과 함수)로 한다(`.agents/skills/dev-principles/SKILL.md`, Claude Code와 Cursor는 `.claude/skills/dev-principles/SKILL.md`).
