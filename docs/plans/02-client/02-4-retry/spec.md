# 02-4 재시도 판단: 명세

- 상위 문서: [plan.md](plan.md)

## 입력과 출력
- 입력
  - 실패의 종류: 응답 상태 코드와 헤더, 또는 연결 오류.
  - 지금까지의 시도 횟수.
  - 재시도 설정값: 최대 재시도 횟수, 백오프 기본값과 상한, `Retry-After` 상한(기본값은 [02-2](../02-2-config/spec.md)의 `http` 기본값).
  - 난수 공급(주입). HTTP 날짜를 대기 초로 바꾸려면 현재 시각도 주입받는다.
- 출력: 다음 중 하나의 판단.
  - 기다린 뒤 재시도: 대기 시간 포함.
  - 포기: 이유 포함(재시도 대상 아님, 횟수 초과, `Retry-After`가 상한 초과이며 대기 초 포함).

## 동작 규칙

### 재시도 대상 판별
- 재시도 대상: 429, 500, 502, 503, 504, 연결 오류.
- 재시도 대상 연결 오류는 응답 헤더를 받기 전의 실패(DNS 실패, 연결 거부, 연결 시간 초과, 헤더 전 연결 재설정)다. 헤더 대기 시간 초과는 재시도하지 않는다(이미 오래 기다렸다)(D14).
- 그 밖의 4xx는 바로 포기한다.

### 대기 시간 결정
정상
- 재시도 대상 상태에 상한 이하의 `Retry-After`가 있으면 그 시간만큼 기다리라고 판단한다. 초 형식과 HTTP 날짜 형식 모두 읽는다.
- 5xx에도 `Retry-After`를 따른다(RFC 9110).
- `Retry-After`가 없거나 연결 오류면 지수 백오프에 Full Jitter를 쓴다. 대기 시간은 0 이상이고, 백오프 상한과 `기본값 × 2^(시도-1)` 중 작은 값 이하다. 그 범위 안에서 균등 무작위로 정한다(D13).

경계
- `Retry-After`를 해석할 수 없으면 헤더가 없는 것으로 보고 백오프를 쓴다. 음수도 해석할 수 없는 값으로 본다(D14).
- `Retry-After`가 0이면 기다리지 않고 바로 다시 요청한다(D14).
- 과거의 HTTP 날짜는 0초로 본다(D14).
- 시도 횟수는 첫 요청을 1로 센다. 최대 재시도 3회면 요청은 최대 4번이다(D14).
- 시도 횟수가 최대 재시도 횟수를 넘으면 포기한다.

거부(포기)
- `Retry-After`가 상한을 넘으면 기다리지 않고, 대기 초를 밝혀 포기한다.
- 재시도 대상이 아닌 상태는 바로 포기한다.

## 오류 종류와 담는 것
이 세부 작업은 오류를 만들지 않고 판단만 돌려준다. 판단의 포기 이유에 담는 것은 다음과 같다.
| 포기 이유 | 담는 것 | 담지 않는 것 |
|---|---|---|
| 재시도 대상 아님 | 상태 코드 | 키, base_url 호스트, 응답 본문 |
| 횟수 초과 | 시도 횟수 | 키, base_url 호스트 |
| `Retry-After` 상한 초과 | 대기 초 | 키, base_url 호스트 |

## 기본값
[02-2 spec.md](../02-2-config/spec.md)의 `http` 기본값을 쓴다(재시도 3회, 백오프 1~30초, `Retry-After` 상한 60초).

## AC
1. Given 재시도 대상 상태와 상한 이하의 `Retry-After`(초, HTTP 날짜 각각)가 있을 때, Then 그 시간만큼 기다리라고 판단한다. 상한을 넘으면 대기 초를 밝힌 포기로 판단한다.
2. Given 헤더가 없거나 연결 오류일 때, Then 대기 시간이 0 이상, 백오프 상한과 `기본값 × 2^(시도-1)` 중 작은 값 이하이고(난수 고정으로 확인), 최대 횟수를 넘으면 포기한다.
3. 그 밖의 4xx는 바로 포기한다.
