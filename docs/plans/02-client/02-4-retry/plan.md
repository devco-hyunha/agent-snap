# 02-4 재시도 판단: 상세 기획

- 상태: done
- 상위 문서: [02-client.md](../../02-client.md)

## 목적
네트워크 없이 응답 상태, 헤더, 시도 횟수로 다시 시도할지와 대기 시간을 정한다. 판단을 전송과 나눠 두면 시간 의존 없이 단위 테스트로 확인할 수 있고, 적용([02-6](../02-6-retry-apply/plan.md))은 이 판단을 부르기만 한다.

## 범위(In)
- 재시도 대상: 429와 500/502/503/504, 헤더 전 연결 오류만(D14, D26).
- `Retry-After`: 초와 HTTP 날짜 두 형식을 읽는다. 해석할 수 없거나 음수이면 헤더가 없는 것으로 본다. 0과 과거 날짜는 대기 0초다(D14, D26).
- 상한을 넘는 `Retry-After`는 기다리지 않고 포기한다(대기 초를 밝힌다).
- 헤더가 없으면 지수 백오프에 Full Jitter를 쓴다. 난수는 주입받는다.
- 최대 횟수를 넘으면 포기한다. 횟수 초과와 `Retry-After` 상한 초과가 동시에 해당하면 횟수 초과를 포기 이유로 쓴다(D26).
- 그 밖의 4xx(429 제외)·목록 밖 5xx·402·408·425·헤더 대기 초과는 바로 포기한다(D26).

## 비범위(Out)
- 실제 대기와 재요청: [02-6](../02-6-retry-apply/plan.md).
- 시간·재시도 값의 설정 읽기: [02-2](../02-2-config/plan.md). 이 세부 작업은 값을 받아 판단만 한다.
- `X-RateLimit-Reset` 헤더(표준이 아니라 쓰지 않는다).
- OpenRouter **402**(크레딧·in-flight 등): 재시도하지 않는다(D26).
- **408**·**425**, 화이트리스트 밖 **5xx**(500/502/503/504 외): 재시도하지 않는다(D26).
- 프로세스 단위 재시도 예산(단일 사용자 에이전트라 지금 필요하지 않다).
- Decorrelated Jitter(Full보다 낫다는 결론이 없어 더 단순한 Full을 고른다).
- 에이전트 루프 쪽 재시도(D13).
- mid-stream 429(HTTP 200 SSE `error` 청크): 02-4 밖(02-3/02-6 경계).
- 공급자 멱등 키·POST 과금 중복 방지 장치(02-6 적용 시 일시 오류만 재시도; D26 다시 볼 점).

## 리스크
- OpenRouter 무료 모델의 일일 한도에 걸리면 `Retry-After`가 매우 길다. 상한을 넘으면 바로 포기하고 대기 초를 알린다.
- HTTP 날짜 형식 해석이 시계에 의존한다. 현재 시각도 주입받아야 시간 의존 없이 시험할 수 있다(spec.md 입력 참조).
- 경계는 D14·D26에서 정했다. `Retry-After` 0은 바로 재요청, 과거 날짜는 0초, 음수와 해석 불가는 헤더 없음으로 본다. 재시도 대상 연결 오류는 헤더 전 실패로 한정하고 헤더 대기 시간 초과는 제외한다. 시도 횟수는 첫 요청이 1이다.
- POST chat completions는 공급자 멱등 키 없이 일시 오류만 재시도하므로 과금 중복 잔여 리스크가 있다(D26 다시 볼 점).
