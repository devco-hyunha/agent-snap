# 코드 주석 짧게 정리: 명세

- 상위: [plan.md](plan.md)
- 성격: 기획 순번과 무관한 독립 정리

## 입력과 출력

- 입력: `crates/**/*.rs`의 기존 주석·독스트링.
- 출력: 같은 파일의 짧아진 주석. 동작·시험 본문은 그대로.

## 동작 규칙(주석 압축)

핵심 한 줄: 주석은 대상(함수·타입·필드)이 하는 일을 한 줄로만 밝힌다. 그 줄이 주석의 전부다.

어체 통일: 명사형 짧은 말투로 끝낸다. 예: 읽음·검증·반환·거부. 존댓말(`합니다`·`습니다`)과 서술형 기본형("읽는다"·"검증한다")은 쓰지 않는다. 한국어 PROJECT_RULES 43절은 유지하고 어체만 단일화한다. 예외: 코드에 안 드러나는 제약·수명일 때만 두 번째 줄 1개 허용.

1. 남긴다: 코드만으로 안 보이는 제약·수명·의도·이유 1~2문장.
2. 지운다: `리뷰 N차`·`보정` 이력, `AC n`·`spec`·`할 일 n`·`T2`·`라운드 n` 같은 작업 문서 참조, `D50 결정 7`·`D41`처럼 `docs/decisions/D*.md`를 가리키는 근거 포인터, 규칙 문구 나열, 코드가 이미 말하는 설명, 03-8처럼 다른 세부 작업 번호로 흐름을 설명하는 글.
2-1. 근거 포인터는 코드 주석에서 지우고 같은 내용·근거를 그 작업 T-파일의 근거 절로 옮긴다. 코드 주석은 제약·의도만 남긴다.
3. 공개 항목 문서 주석은 한국어·eli5-clarity를 지킨다.
4. 이력 문장을 지우기 전에 `docs/reviews/`·T-파일에 정본이 있는지 확인한다.
5. 주석 밖의 토큰(식별자·문자열·시험 이름)은 바꾸지 않는다.

## AC

1. 전수 후 코드에 라운드·보정 이력 표기와 작업 문서 참조(AC 번호·spec·할 일 번호·세부 작업 번호)가 없다. 타입·함수·필드 주석은 그 대상이 하는 일을 한 줄로 밝히고, 대상 밖에 있는 배경·경위·설계 이동을 설명으로 적지 않는다.
2. 주석 수정 중간(배치·T 단계)에는 게이트를 돌리지 않는다. 주석만 고치는 일이기 때문이다. 작업 단위 끝 검증은 `cargo clippy --all-targets -- -D warnings` 1회로 하고(문서 링크 손상까지 여기서 잡음), Windows·WSL 동등은 PR CI 매트릭스로 확인한다.
3. `#[test]`·`#[tokio::test]` 개수가 착수 전과 같다(265·156).
4. 각 T는 자기 모듈 경로만 고친다.
5. 지운 이력의 정본이 문서에 있다.
