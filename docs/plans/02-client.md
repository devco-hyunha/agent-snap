# 02 설정과 스트리밍 클라이언트

- 상태: planned

## 목적
설정을 읽고 OpenAI 호환 엔드포인트와 스트리밍으로 대화하는 클라이언트를 만든다. 이후 감시기가 스트림을 중간에 끊을 수 있어야 하고, 에이전트 루프(작업 03)는 이 클라이언트를 트레이트로만 받는다.

설정을 엔드포인트 목록과 모델 목록 구조로 바꾸고, 키를 `.local/.env` 또는 환경 변수에서 읽으며, 엔드포인트의 모델 목록을 조회하는 기능을 라이브러리에 둔다.

## 범위(In)
- config: `agent-snap.toml`(target_language 기본 `ko`, `[sampling]`, `[http]`)을 읽어 검증한다. `agent-snap.example.toml`에는 자리표시자만 둔다.
- 비밀 값 래퍼: 키는 Debug/Display에서 가리고, base_url도 Debug에서 가린다.
- llm: chat completions 스트리밍(SSE 직접 파싱). content, reasoning(`reasoning_content`와 `reasoning` 필드), tool_calls 델타를 복원한다. `:`로 시작하는 주석 줄(`: keep-alive`, `: OPENROUTER PROCESSING`)은 건너뛴다. CRLF·CR 줄 끝, 청크 경계에서 잘린 줄과 멀티바이트 문자를 처리한다. 모르는 델타 필드는 원문 JSON으로 보존한다.
- LLM 클라이언트를 트레이트로 노출한다(스트림 시작, 취소 지원). OpenAI 호환 구현을 하나 둔다.
- 취소 토큰으로 스트림을 즉시 중단하고 연결을 정리한다.
- 시간 초과: 연결, 헤더 대기, 스트림 유휴를 따로 둔다.
- 재시도: 429와 500/502/503/504는 `Retry-After`를 설정한 상한 안에서 따르고(상한을 넘으면 기다리지 않고 포기), 헤더가 없으면 지수 백오프. 연결 오류는 지수 백오프. 최대 횟수에서 포기한다. 스트림이 시작된 뒤에는 재시도하지 않는다.
- 잠정 기본값: 재시도 3회, 백오프 1~30초, Retry-After 상한 60초, 연결 10초·헤더 300초·유휴 120초.
- 설정 구조 변경과 검증: 엔드포인트(이름, base_url, 키 변수 이름)와 모델(id, 쓸 엔드포인트 이름, 모델별 샘플링). 엔드포인트 이름 중복, 중복 모델 이름, 없는 엔드포인트를 가리키는 모델을 거부한다.
- 모델 이름으로 클라이언트 만들기.
- `.local/.env` 읽기(형식 오류 처리). 없으면 환경 변수에서 찾는다.
- 엔드포인트의 모델 목록 조회(OpenAI 호환 `GET /v1/models`).
- `agent-snap.example.toml` 갱신(자리표시자만).
- 스트림 응답에서 서버가 주는 토큰 사용량과, 요청 시작·첫 토큰·마지막 토큰 시각을 호출 결과로 돌려준다. 서버가 사용량을 주지 않으면 "없음"으로 돌려준다.

## 비범위(Out)
- 에이전트 루프와 도구(작업 03), 대화형 CLI와 세션 로그(작업 04).
- `[extra]` 같은 임의 요청 매개변수 통과, `stream_options`, 비스트리밍 요청.
- 응답 형식이 다른 API(Responses API, Ollama 고유 API).
- CLI 명령. `ls` 같은 사용자 명령은 작업 04에서 다룬다.
- 옛 단일 엔드포인트 형식 호환(아직 쓰는 사용자가 없다).
- 엔드포인트 고유 매개변수.

## 조사
- 주제: 서버별 OpenAI 호환 스트리밍 차이(llama.cpp server, Ollama, vLLM, LM Studio, OpenRouter), reasoning 필드 관례, 429/Retry-After 관례(RFC 9110, RFC 6585), SSE 파싱 규칙(WHATWG).
- 기록: `docs/RESEARCH.md` 작업 02 절.
- 주제: OpenAI 호환 서버별 `/v1/models` 지원과 응답 형식(llama.cpp server, Ollama, vLLM, LM Studio, OpenRouter), `.env` 파일 형식 관례.
- 기록: `docs/RESEARCH.md` 작업 02 절. 링크는 직접 열어 확인한 것만 적는다.

## 확인된 사실
첫 시도에서 실측한 내용입니다.
- keep-alive 주석 줄과 reasoning 필드가 오고, CRLF 줄 끝과 청크 경계에서 잘리는 줄이 있다.
- OpenRouter 무료 모델은 429가 잦다 → `Retry-After` 기준으로 재시도한다.
- 엔드포인트의 키 변수 이름에 키 값을 넣으면 오류에 키가 찍혔다 → 변수 이름 형식이 아니면 값을 출력하지 않는다.
- 오류 메시지에 base_url과 키가 들어가면 안 된다.
- 헤더 대기와 스트림 유휴 시간 초과를 분리해야 한다.

## 지켜야 할 경계
- 상위 로직(작업 03 에이전트 루프)은 LLM 클라이언트를 트레이트로만 받는다. HTTP 라이브러리는 전송 구현 안에서만 쓴다.
- SSE 파싱, 델타 해석, tool_call 누적, 재시도 판단은 네트워크 없이 단위 테스트할 수 있게 전송과 분리한다.
- 키와 base_url은 오류 메시지·Debug·로그에 넣지 않고, 서버 오류 본문은 요약·길이 제한 후에만 담는다.
- 모듈 하나는 책임 하나이며, 파일·함수 크기와 오류 처리 규칙은 AGENTS.md 개발 규칙을 따른다.
- 파일 구성과 타입 이름은 구현하면서 정하고, 코드 품질 리뷰(dev-principles 2~10절)로 확인한다.
- 위 경계를 그대로 따른다: LLM 클라이언트는 트레이트로만 노출하고, HTTP 라이브러리는 전송 구현 안에서만 쓰며, 파싱·검증은 네트워크 없이 단위 테스트할 수 있게 전송과 분리한다.
- `.env` 값과 키, base_url은 Debug·오류·로그에 넣지 않는다.

## AC
1. **스트림 복원**: Given 모의 SSE 서버가 `: keep-alive` 주석 줄, CRLF 줄 끝, 청크 경계에서 잘린 줄과 멀티바이트 문자, `reasoning_content`와 `reasoning` 필드, 번갈아 오는 병렬 tool_call 델타, 모르는 델타 필드를 보낼 때, When 스트림을 끝까지 받아 하나의 응답으로 합치면, Then content·reasoning·tool_calls가 보낸 순서대로 복원되고, 주석 줄은 이벤트를 만들지 않으며, 모르는 필드는 원문 JSON으로 남는다. 스트림 중간의 `error` 청크는 스트림 오류로 끝난다.
2. **비밀 값**: (a) 키는 `Authorization: Bearer` 헤더에만 들어가고, 엔드포인트의 키 변수 이름이 없으면 Authorization 헤더 없이 요청한다. (b) 엔드포인트의 키 변수 이름이 가리키는 변수가 없거나 비어 있으면 변수 이름만 밝힌 오류를 낸다. (c) 엔드포인트의 키 변수 이름 값이 `^[A-Za-z_][A-Za-z0-9_]{0,63}$` 형식이 아니면 값을 출력하지 않고 "환경 변수 이름 형식이 아님"만 알린다. (d) 설정과 키의 Debug, 모든 설정 오류·LLM 오류의 Display/Debug(API 오류 본문이 키를 되돌려 주는 경우, 연결 실패 포함)에 키 값과 base_url 호스트가 없다(테스트).
3. **재시도**: (a) 429와 500/502/503/504에 `Retry-After`가 설정한 상한 이하이면 그만큼 기다린 뒤 다시 요청한다. 상한을 넘으면 재시도 없이 대기 초를 밝힌 오류로 포기한다. (b) `Retry-After` 없는 429와 500/502/503/504, 연결 오류는 지수 백오프로 다시 요청하고, 최초 1회 + 최대 재시도 횟수만큼 요청한 뒤 포기한다(요청 수로 확인). (c) 그 밖의 4xx는 재시도하지 않는다. (d) 재시도 대기 중 취소하면 즉시 취소로 끝난다.
4. **시간 초과와 취소**: (a) 헤더 대기 시간 초과와 스트림 유휴 시간 초과는 따로 동작한다: 헤더가 유휴 시간 설정보다 늦지만 헤더 대기 시간 설정 안에 오면 성공하고, 헤더가 끝내 오지 않으면 헤더 대기 시간 초과, 본문이 멈추면 유휴 시간 초과로 끝난다. (b) 스트림 도중 취소하면 500ms 안에 취소 오류 하나를 내고 스트림이 끝나며, 서버 쪽 연결이 3초 안에 닫힌다(테스트).
5. **구조와 품질**: 지켜야 할 경계를 따른다. 소스 파일 300줄 목표(500줄 초과 0), 함수 60줄 이하, 테스트 밖 unwrap/expect/panic 0, 공개 항목 한국어 문서 주석. dev-principles 2~10절 코드 품질 리뷰가 PASS한다.
6. **조사와 검사**: `docs/RESEARCH.md`에 작업 02 조사 항목과 적용 위치(또는 미적용 이유)가 있다. `bash scripts/check.sh`를 통과한다.
7. **엔드포인트·모델 선택**: Given 엔드포인트 2개와 모델 3개가 설정되어 있고 모의 서버 2개가 떠 있을 때, When 모델 이름으로 클라이언트를 만들어 요청하면, Then 그 모델이 가리키는 엔드포인트의 모의 서버로만 요청이 가고, 요청 본문에 그 모델의 id와 샘플링이 쓰인다.
8. **설정 검증**: Given 엔드포인트 이름 중복, 없는 엔드포인트를 가리키는 모델, 중복 모델 이름이 각각 설정되어 있을 때, When 설정을 읽으면, Then 각각 거부되고 오류에는 이름만 밝히며 값·주소·키는 없다(테스트).
9. **키 읽기**: Given `.local/.env`와 환경 변수가 있을 때, When 키를 찾으면, Then `.local/.env`에 있으면 그 값을, 없으면 환경 변수를 쓴다. 둘 다 없으면 변수 이름만 밝힌 오류를 낸다. `.env` 형식 오류는 줄 번호만 알린다. 키 값은 어떤 Debug·오류에도 없다(테스트).
10. **모델 목록 조회**: Given 모의 서버가 `GET /v1/models`에 응답할 때, When 엔드포인트의 모델 목록을 조회하면, Then 응답의 모델 id 목록을 돌려준다. 오류에는 키와 주소가 없고, 취소와 시간 초과는 AC 4와 같이 따른다(테스트).
11. **기존 동작 유지**: AC 1~6의 동작을 유지한다(설정 구조 변경에 따른 테스트 형태 갱신은 허용).
12. **구조·품질과 검사**: AC 5와 같은 기준(소스 파일 300줄 목표·500줄 초과 0, 함수 60줄 이하, 테스트 밖 unwrap/expect/panic 0, 공개 항목 한국어 문서 주석)을 지키고, dev-principles 2~10절 코드 품질 리뷰가 PASS한다. `bash scripts/check.sh`를 통과한다. `docs/RESEARCH.md`에 조사 항목(OpenAI 호환 `/v1/models` 서버별 지원, `.env` 형식 관례)과 적용 위치 또는 미적용 이유가 있다.
13. **사용량과 시각**: Given 모의 서버가 스트림 끝에 토큰 사용량을 줄 때와 주지 않을 때, When 스트림을 끝까지 받으면, Then 준 경우에는 그 값을, 주지 않은 경우에는 "없음"을 돌려주고, 요청 시작·첫 토큰·마지막 토큰 시각이 이 순서대로 기록된다(테스트).

## 리스크
- 서버마다 스트림 형식이 다르다 → 모르는 델타 필드를 보존해 나중에 처리한다. reasoning은 두 이름을 모두 받는다.
- OpenRouter 무료 모델의 일일 한도에 걸리면 `Retry-After`가 매우 길다 → 상한 초과 시 즉시 포기해 사용자에게 알린다.
- 모의 서버 테스트가 시간에 의존해 흔들릴 수 있다 → 시험용 시간 값을 짧게 주고, 경과 시간은 넉넉한 하한·상한으로만 확인한다.
- 스트림이 시작된 뒤의 끊김은 재시도하지 않으므로 부분 응답이 남는다 → 처리 방식은 작업 03에서 정한다.
- 일부 서버가 `/v1/models`를 지원하지 않거나 응답 형식이 다르다 → 조회 실패를 오류로 알리고, 설정은 수동으로 쓸 수 있게 한다.
- `.env` 형식 관례가 도구마다 달라 해석이 어긋날 수 있다 → 지원하는 형식을 조사 결과로 좁혀 문서에 적고, 벗어나면 줄 번호만 알리는 오류로 거부한다.
