# 03-8 호출 형식 3안 execute 브리지: 명세

- 상위 문서: [plan.md](plan.md), 상위 기획: [../../03-agent-loop-tools.md](../../03-agent-loop-tools.md), 선행: [03-3](../03-03-file-tools/plan.md), [03-6](../03-06-run-command/plan.md)

## 입력과 출력
- 입력: `execute` 도구 호출 1개. 인자는 스크립트 본문(글자) 1개.
- 출력: 스크립트 실행 결과 요약 1개(문자열). 중간 변수·순간 출력은 컨텍스트에 올리지 않는다.

## 도구 정의
- 이름: `execute`. 설명: "여러 도구 호출을 코드로 조립해 한 번에 실행한다".
- 인자 스키마: `{"script": {"type": "string"}` 1개만.
- `Tool` 트레이트로 등록하고, 03-2 루프가 처리하는 1안 경로의 일반 도구로 둔다(2안·감지 경로에서도 동일하게 동작).

## 스크립트 실행 규칙
- 런타임은 T1 엔진 선택 비교(4갈래: JS 엔진, Lua, JSON 호출 체인, Rust 임의 코드)로 정한다.
- JS 엔진을 고르면 `boa`(순수 Rust)·`rquickjs`(QuickJS C 바인딩, 저용량)·`deno_core`(V8, 무거움) 중 하나를 확정하고, 라이선스·의존성 크기를 메모에 남긴다. 모두 Rust 크레이프로 들어가 새 외부 런타임은 없다.
- 엔진 없이 JSON 호출 체인으로 가면 새 의존성 0개로 03-4 JSON 복원 경로를 재사용한다. 표현력은 순서·결과 전달만(분기·반복은 03-2 다중 호출로).
- wasm은 모델 생성 언어로 부적합(생성 난이도). Rust 스크립트는 eval 크레이트가 사실상 없어 컴파일 시간 부담이 커 후보에서 제외. 세부 근거는 엔진 선택 메모에 적는다.
- 스크립트에서 부르는 함수는 03-3·03-6의 `Tool` 구현 그대로다: `read_file(args)`, `grep(args)`, `glob(args)`, `listDir(args)`, `writeFile(args)`, `editFile(args)`, `runCommand(args)`. 매개·게이트·잘림 규칙은 같은 자리를 쓴다(재사용, 중복 구현 금지).
- 1차 허용 목록: `read_file`, `grep`, `glob`, `list_dir`. 쓰기·명령(`write_file`, `edit_file`, `run_command`)은 승인 게이트를 지난 뒤 개방한다(개방 순서는 03-4 안정화 후 결정, plan Out).

## 승인 게이트 (AC 2, AC 5)
- `execute` 도구 호출 자체는 승인 1회다(스크립트 전체에 대한 확인 1개).
- 스크립트 안에서 쓰기·명령 도구가 호출되면 각 호출마다 승인 게이트가 await로 대기한다. 승인 전까지 스크립트는 진행하지 못한다.
- 총 승인 수: `execute` 1개 + 안의 쓰기 호출 1개 = 2개. 승인 로그에 개수가 남는다.
- `for (const f of files) writeFile(f)`처럼 반복이 승인 1회로 여러 쓰기가 되는 구조를 금지한다(호출마다 게이트).

## 기록 (AC 3)
- 스크립트 안의 모든 도구 호출을 03-2 기록 규칙(`logs`)에 남긴다. 형식: `[execute][i/total] name(인자 요약) → 결과 요약(200자)`.
- 스크립트 자체 호출(`execute`)도 03-2 도구 호출 기록과 같은 자리에 남는다.

## 컨텍스트 전달 (AC 4)
- 컨텍스트에 올리는 것은 스크립트 실행 요약 1개(결과 반환값 또는 마지막 표현식)다.
- 중간 변수·console 출력·도구 원결과 전체는 컨텍스트에 올리지 않는다. 로그에는 남긴다.
- 잘림은 03-2 규칙(`…[truncated]`)을 쓴다.

## 실행 실패·타임아웃 (AC 6)
- 스크립트 실행 타임아웃은 03-6 `run_command` 규칙과 같은 게이트(기본 600초, 트리 정리)를 지난다.
- 런타임 오류(구문·실행 오류)는 오류 글자를 도구 결과로 돌려준다. 스크립트 원문은 로그에만 남기고 컨텍스트 오류 메시지에 통째로 넣지 않는다.

## AC
1. `execute` 1개 등록 후 스크립트 1개(read_file→grep 가공)가 모의 서버 테스트로 통과한다.
2. 스크립트가 쓰기·명령 도구를 부르면 게이트가 await되고 승인 전까지 진행하지 않는다.
3. 스크립트 안의 모든 호출이 03-2 기록 규칙으로 `logs`에 남는다.
4. 컨텍스트에는 요약 1개만 오르고 중간 변수가 오르지 않는다.
5. 승인 로그에 승인 2개가 확인된다.
6. 스크립트 실행 실패·타임아웃이 03-6 규칙과 같은 게이트를 지난다.
7. 검증 명령 3종 통과(공통 DoD).
