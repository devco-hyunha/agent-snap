# 03-8 호출 형식 3안 execute 브리지: 상세 기획

- 상태: planned
- 상위 문서: [../../03-agent-loop-tools.md](../../03-agent-loop-tools.md), 선행: [03-1](../03-01-tool-trait/plan.md), [03-3](../03-03-file-tools/plan.md), [03-6](../03-06-run-command/plan.md)
- `Tool` 트레이트 서명 정본: [03-1 spec.md](../03-01-tool-trait/spec.md)(이 문서가 쓰는 `Tool`·`ToolContext`·`ToolOutcome`·`executes_writes`는 03-1이 확정한 이름을 따른다).
- 근거: [12번 문서](../../../research/12-tool-calling-forms.md) 2절 3갈래·4절 ③행, OpenCode Code Mode `execute` (https://opencode.ai/docs/tools). 2026-11-08 사용자 결정(3형식 조합)의 3안.

## 목적
도구 호출을 코드로 조립하는 창구를 한 개만 둔다. `execute`라는 도구 하나로, 03이 만든 `Tool` 트레이트 도구(read_file·grep·glob·list_dir·write_file·edit_file·run_command)를 JS 같은 스크립트에서 부르게 한다. 도구 정의·실행 경로·승인 게이트는 03-2이 만든 그대로이고, 바뀌는 것은 "누가 몇 번 부를지 정하는 주체"가 모델의 코드라는 점뿐이다.

## 범위(In)
- `execute` 도구를 03-2의 `Tool` 트레이트로 등록한다. 도구가 스크립트를 받아 실행한다.
- 스크립트에서 부르는 함수는 `Tool` 트레이트 그대로(read_file(params)…). 매개는 `tools/`의 같은 게이트로 들어간다.
- 승인 게이트가 스크립트 안에서 await로 대기하게 둔다. 승인 없는 쓰기·명령 호출은 스크립트가 진행하지 못한다. `for (const f of files) writeFile(f)`가 승인 1회로 100번의 쓰기가 되지 않는다.
- 1차 범위: 읽기 전용 조합(read_file·grep·glob·list_dir)만 허용한다.
- 승인 단위: `execute` 도구 호출 자체는 1회 승인이고, 그 안에서 쓰기는 게이트 대기 1개가 추가된다. 총 승인 2개.
- 스크립트 결과 요약만 컨텍스트에 전달한다. 중간 값(변수·순간 출력)은 컨텍스트에 올리지 않는다.
- 도구 호출 기록은 03-2의 기록 규칙과 같은 자리를 쓴다(스크립트 안의 호출도 기록에 남는다).
- 런타임: T1 엔진 선택 비교로 정한다. 후보 4갈래: JS 엔진(`boa`·`rquickjs`·`deno_core`, 모두 Rust 크레이트), Lua(`mlua`), 엔진 없는 JSON 호출 체인(의존성 0), Rust 임의 코드(후보 제외). wasm은 모델 생성 언어로 부적합이라 후보가 아니다. 비교 항목: 라이선스·의존성 크기·M1 저사양 부합·승인 게이트(await)와 모델 코딩 학습성.

## 비범위(Out)
- 쓰기·명령(execute가 쓰는) 도구 1차 개방: 03-4가 안정화된 뒤 개방 순서로 정한다.
- 코드 모드 전용 승인 정책·세션 허용: 03 비범위(D22).
- 서버가 스크립트를 해석·실행하는 형태: 서버 의존성을 크게 하므로 04 이후 후보.
- 2안(03-4)과 3안을 한 모델 턴에서 섞는 정책: 06 실측 이후 판단.

## AC
1. `execute` 도구 1개 등록 후, 스크립트 1개로 read_file→grep 결과를 가공하는 흐름이 모의 서버 테스트로 확인된다.
2. 스크립트가 쓰기·명령 도구를 부르면 게이트가 await되고 승인 전까지 진행하지 않음을 확인한다.
3. 스크립트 안의 모든 도구 호출이 03-2 기록 규칙대로 기록에 남는다.
4. 컨텍스트에 전달되는 내용은 스크립트 요약 1개이고, 중간 변수가 컨텍스트에 안 오름을 확인한다.
5. 승인 2개 기준이 승인 로그에서 확인된다.
6. 스크립트 실행 실패·타임아웃은 03-6의 `run_command` 규칙(600초·트리 정리)과 같은 게이트를 지난다.

## 리스크
- 런타임 의존성 추가가 "M1 경량" 목표에 새 무게를 더한다. 엔진 1개와 크레이트 의존성 목록을 착수 전에 확정한다.
- 코드 모드의 조립은 모델이 코드를 쓰는 능력이다. 2609.07370의 소형 모델 준수율 표(5절)는 코드 모드에 약하고, 스냅의 로컬 소형 모델은 2안으로 돌리는 것이 설계다.
- 12번 문서 6절(코드 모드 보안 축)이 지적하는 "스크립트 단위 승인"과 03-6 승인 정책(명령마다 확인 L1)이 충돌한다 → 03-8은 L1 유지 + 게이트 2개로 설계한다.
- 콘텐츠 주입(파일 내용·출력→코드)이 스크립트 실행 표면이 된다 → 1차에서 read_file·grep만 여는 것으로 완화한다.
