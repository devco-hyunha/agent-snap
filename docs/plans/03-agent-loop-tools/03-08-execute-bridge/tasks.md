# 03-8 호출 형식 3안 execute 브리지: 작업 계획

- 상위 문서: [plan.md](plan.md), [spec.md](spec.md)
- 검증 명령과 공통 DoD는 [상위 문서](../../03-agent-loop-tools.md)의 '세부 작업 공통 기준'을 따른다.
- 선행: 03-3(파일 도구)·03-6(run_command) 완료 상태에서 착수한다.

## 구현 단계
- [ ] 1. JS 엔진을 하나 고른다. 후보 `boa`·`deno_core`·`rquickjs`를 비교하고, 의존성 크기·라이선스를 메모로 남긴다. 확인: 메모 파일(선택 근거·라이선스·의존성 목록). 선택 없이는 2단계로 가지 않는다.
- [ ] 2. `execute` 도구를 `Tool` 트레이트로 등록한다(인자 `script` 1개). 확인: 03-2 루프 등록 목록에 `execute`가 뜨는지 모의 서버 테스트.
- [ ] 3. 스크립트와 `Tool` 트레이트를 연결한다. `read_file`·`grep`·`glob`·`list_dir`을 스크립트 함수로 노출(1차 읽기 전용). 게이트·매개는 03-3 구현을 그대로 재사용한다. 확인: 스크립트 1개(read_file→grep 가공) 왕복 테스트(spec AC 1).
- [ ] 4. 승인 게이트를 await로 연결한다. `execute` 호출 1회 승인 + 안의 쓰기·명령 호출마다 게이트 1개 추가. 확인: 게이트 대기 전까지 스크립트가 진행하지 않는 테스트(spec AC 2), 승인 2개가 승인 로그에 남는 테스트(spec AC 5).
- [ ] 5. 호출 기록을 03-2 기록 규칙 자리에 남긴다. 형식: `[execute][i/total] name(인자 요약) → 결과 요약(200자)`. 확인: `logs` 내용 테스트(spec AC 3).
- [ ] 6. 요약만 컨텍스트에 올인다. 중간 변수·출력 생략, 4,000자 잘림(`…[truncated]`) 재사용. 확인: 컨텍스트에 요약 1개만 오르는 테스트(spec AC 4).
- [ ] 7. 타임아웃·실행 실패를 03-6 규칙 게이트로 연결한다(600초·트리 정리). 확인: 타임아웃·구문 오류가 짧은 오류 글자로 돌아오는 테스트(spec AC 6).

## 테스트 계획
- 종류: 모의 서버 통합 테스트 + 엔진 단위 테스트(스크립트 왕복).
- 엔진 선택 메모가 없으면 스킵(`skip`)을 두고, 선택 후 테스트를 채운다.
- 승인 게이트 테스트는 승인자 좌석을 가짜(승인 즉시·승인 보류)로 두고, 시간 값은 짧게 준다.
- 반복 쓰기가 승인 1회로 여러 쓰기가 되지 않음을 확인하는 테스트(`for` 예제)를 넣는다.
