# 03-2 에이전트 루프: 명세

- 상위 문서: [plan.md](plan.md), 상위 기획: [../../03-agent-loop-tools.md](../../03-agent-loop-tools.md)

## 입력과 출력
- 루프 입력: 사용자 메시지 한 장, 설정(선택 키·`tool_call` 프로파일), 시스템 프롬프트 문자열, 도구 등록 목록(이름·설명·인자 형식), 도구 실행 결과 목록.
- 루프 출력: 최종 답 텍스트, 도구 호출 기록(이름·인자·결과·실행 시각), 턴 수.
- 도구 등록 입력: 도구 트레이트 객체. 출력: OpenAI `tools` 배열 한 자리(이름·설명·인자 JSON schema).

## 동작 규칙

### 루프 종료 (AC 1)
1. 응답에 `tool_calls`가 있으면 도구를 실행하고 결과를 붙여 다음 요청을 만든다.
2. 반복 상한(기본 32, 설정)에 걸리면 상한 초과로 끝낸다.
3. `finish_reason=stop`이면 종료로 끝낸다.
4. 미승인·거부 결과를 도구 결과로 모델에 알리고, 다음 턴에 같은 도구·인자로 재시도하지 않는다.
5. 응답의 내용·도구 호출을 이어 쓰되, 재시도는 02-6 한 층에서만 한다(D13).

### 도구 이름·인자 JSON
- 이름: 등록 목록에 등록하고, `tool_calls`의 이름과 비교한다.
- 인자 JSON이 등록한 형식에 맞으면 도구를 부른다.
- 형식이 어긋나면 짧은 오류("형식 오류)를 도구 결과로 돌려준다.
- 이름이 없으면 "도구 없음" 오류로 모델에 알리고, 같은 이름 재시도는 없다.

### 낮은 온도·`tool_call` 프로파일 (AC 7)
- 설정 `tool_call` 프로파일을 모델 `extra`에 합쳐 보낸다.
- 프로파일에는 `temperature`만 담고, `model`·`messages`·`stream`·`tools`를 덮어쓰려 하면 설정 오류(D15).

### 도구 결과 자르기 (AC 5)
- 도구 결과가 길면 기본 4,000자 앞을 자른다. 도구 출력은 모델 응답에 직접 들어가는 자리가 아니라, `agent-snap`이 만드는 `tools` 배열에 담는 결과 문자열만 자른다.
- 잘린 결과에 `…[truncated]`을 붙인다.

### 시스템 프롬프트 조립 (AC 6)
- `agent/system_prompt.txt` 내용을 앞머리에 두고, AGENTS.md를 [03-5](../03-05-agents-md/plan.md)에서 읽은 내용으로 합쳐 넣는다.
- 규칙 파일·색인·메모리는 넣지 않는다.

## AC (상위 문서 AC 1, 4, 5, 6과 연결)
1. 모의 서버에서 `tool_calls`→도구 결과→`stop` 경로가 AC 1(상위) 그대로 끝까지 돈다.
2. 반복 상한 초과 턴을 테스트로 확인한다.
3. 인자 JSON이 어긋난 도구 호출을 모델이 부르면 짧은 오류로 돌아간다(모의 서버 테스트).
4. 도구 호출을 못 하는 모델이면 이유가 담긴 오류로 끝난다. 폴백은 03-4가 담당하고, 03-2은 1안(OpenAI) 경로만 처리하며 미지원 감지를 모델 프로필 폴백 연결 지점으로 남긴다(2026-11-08 순서 보정). 2026-11-10 첨삭(D50): 텍스트 1회 응답은 AC 1의 정상 종료로 끝난다. 2회 연속 판정과 2안으로의 형식 전환은 03-2 루프의 `ToolCallFormat` 상태를 소비하는 03-4가 구현한다. "오류로 끝난다"는 1안 요청이 4xx로 거부된 자리(단일 왕복) 기준으로 유지한다.
5. 도구 결과가 길 때 4,000자로 잘림을 테스트로 확인한다.
6. 시스템 프롬프트에 `agent/system_prompt.txt` 앞머리가 있고 AGENTS.md가 합쳐진다(03-5 AC).
7. `tool_call` 프로파일 `extra` 합쳐 보내기를 확인한다(모의 서버).
