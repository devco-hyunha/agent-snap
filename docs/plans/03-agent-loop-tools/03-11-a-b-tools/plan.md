# 03-11 (a)(b) 배치 이관 1차: 계획 모드·3단계 승인 규칙·ask_user

- 상태: planned
- 상위 문서: [../03-agent-loop-tools.md](../03-agent-loop-tools.md), 선행: 03-2, 03-6
- 근거: [기능 목록](../../../research/agent-feature-inventory-2026-11-07.md) (a) 계획 모드·(b) 승인 3단계, DECISIONS D43 2차 개정(2026-11-09).

## 목적
코딩 한 바퀴에 필요한 골격 기능 3가지(계획 모드, 3단계 승인 규칙, 사용자 질문)를 03에 넣는다. 도구 추가 없이 루프·승인자 골격만 확장한다.

## 범위(In)
- 계획 모드 도구(`plan_list`): 항목 추가·갱신·완료 표시를 하나의 파일 도구로 둔다. 항목은 세션 기록에 남기고 시스템 프롬프트에 목록을 반영한다.
- 3단계 승인 규칙(allow/ask/deny): 승인자 인터페이스에 규칙 표를 추가한다. L1 기본(매 확인)은 03-6 규칙 그대로 두고, 규칙 표로 허용·거부·확인을 고른다. 규칙 파일 위치·형식은 03-11에서 확정한다.
- `ask_user` 도구: 모델이 사용자에게 한 줄 질문을 보내고 답을 받아 다음 턴에 넣는다. 답변 없으면 진행 금지(거부로 기록).

## 비범위(Out)
- 세션 허용 UI·패턴 자동 허용 L2·L3: D22 정본대로 06 이후.
- 메모리 계층·슬래시 커맨드·출력 표시: 04.

## AC
1. 계획 모드 도구로 항목 3개 이상을 만들고 완료 표시하는 것을 모의 서버 테스트로 확인한다.
2. 승인 규칙 표로 allow·ask·deny 3종이 동작함을 테스트로 확인한다.
3. `ask_user` 호출 시 답이 없으면 다음 턴이 진행되지 않음을 테스트로 확인한다.
4. 검증 명령 3종 통과.

## 리스크
- 승인 규칙 표가 D22 L1 기본을 약화시키지 않도록 한다. 규칙 기본값은 ask로 둔다.
- 계획 모드 목록이 길면 프롬프트가 늘어난다. 잘림 규칙(03-2)과 같은 상한을 적용한다.
