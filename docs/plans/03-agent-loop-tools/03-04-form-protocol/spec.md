# 03-4 호출 형식 2안 텍스트 프로토콜 폴백: 명세

- 상위 문서: [plan.md](plan.md), 상위 기획: [../../03-agent-loop-tools.md](../../03-agent-loop-tools.md), 선행: [03-2](../03-02-agent-loop/plan.md)

## 입력과 출력
- 입력: 03-2 루프가 1안(OpenAI `tools`)로 보낸 요청이 4xx이거나 도구 호출 없는 일반 텍스트로 온다.
- 출력: 모델이 쓴 글자에서 JSON 객체를 복원하고, 도구 실행 후 결과를 2안 규격 글자로 messages에 붙인다.
- 전환 기록: 03-2 AC 1의 도구 호출 기록과 같은 자리(`ToolCallRecord.format`·`LoopResult.fallback_point`)에 "턴 N에서 2안 전환(사유 4xx·2회 연속 텍스트)", "턴 N에서 1안 복귀"를 한 줄씩 남긴다. 파일 로그 기록은 04(세션 로그) 배치라 이 작업 범위 밖이다(D50).

## 감지 기준 (AC 1)
- 전환 형식은 선언 → 감지 순으로 정한다. 설정 `tool_call_form`이 `openai`·`text`면 선언대로만 쓰고 감지를 하지 않는다. `auto`일 때만 아래 감지를 쓴다(업계 관례가 사전 선언형 기본 — 12번 문서 8절, D50).
- HTTP 4xx(400·404·405·406·415·422·501, `agent/fallback.rs`의 미지원 후보 표)를 받으면 2안으로 전환한다. 도구 정의 요청이 거부된 경우다. 서버마다 상태 코드·`type`이 제각각이므로 본문 글자는 판별에 쓰지 않는다(D28 유지).
- 200 응답에 `tool_calls`가 없고 텍스트만 오는 경우: 1회는 전환하지 않고 전환 후보로만 기록한 뒤 1안으로 한 번 더 보낸다. 2회 연속 텍스트가 오면 그때 2안으로 전환한다(03-2는 텍스트 1회 응답을 AC 1의 정상 종료로 본다).
- 전환 후 이어쓰기: 1안 왕복에서 쌓은 messages(시스템·user·assistant·tool)를 그대로 두고 2안 줄만 새로 붙인다. 2안 assistant 줄은 `tool_calls` 없이 내용만 담고, 도구 결과는 `role: user` 글자로 붙인다(결과 전달 규격과 같음). 2안 왕복에도 같은 요청 재시도는 02-6 한 층만 거친다(D13).
- 전환·복귀는 요청 형식(도구 배열 넣기·빼기)을 바꾸는 일이고, 03-2 루프 안의 `ToolCallFormat` 상태가 이를 고른다. 2안 조립·복원·전달 모듈은 03-4가 만든다(2026-11-10 기획 보정, D50).
- 전환 판단은 응답 헤더·상태 코드만 보는 순수 함수로 두고, 네트워크 재시도는 02-6 계층에서만 쓴다(D13).

## 프롬프트 조립 (AC 2)
- 시스템 프롬프트 끝에 "도구 호출 형식" 블록을 붙인다. 형식은 한 도구당 최대 3줄로 쓴다:
  `name`, 인자 필드 이름과 타입, 호출 예시 JSON 1개.
- 등록 도구 전부를 프롬프트에 넣는다. 잘림 규칙(03-2의 4,000자)과 같은 기준으로 총 길이를 잰다.
- 모델에게 "답에는 JSON 객체 하나만 쓴다"를 지시문에 포함한다.
- OpenAI 공식 함수 호출 안내(한 번에 노출하는 함수는 20개 미만, 인자마다 설명, "언제 쓰는가"를 시스템 프롬프트에 명시)를 기준대로 두고, 지시문에 "JSON" 글자를 명시한다(12번 문서 8절).
- 스키마 글자 압축(TSCG 2605.04107, 읽는 쪽 절감)은 06 실측 후 후보로 두고 이번 AC에는 넣지 않는다(12번 8절).

## 응답 복원 (AC 3)
- 2안 복원은 assistant 내용 글자 전체에서 시작한다. 순서: ① Markdown 코드블럭 둘레 제거 → ② 여는 중괄호부터 닫는 중괄호까지 객체 찾아내기 → ③ 파싱 → ④ 파싱에 실패하면 `crates/snap-core/src/agent/args.rs`의 `recover_arguments`(닫힘 기호 1회 복구)에 넘겨 복구 → ⑤ 스키마 검증 → ⑥ 모호하면 거부하고 짧은 오류로 알린다(2609.07370 5·7절 권고).
- ①·②는 현재 코드에 없는 단계라 03-4가 새 파일에서 만들고, ④는 `recover_arguments`를 그대로 부른다(중복 구현 금지). 이 문서의 옛 포인터 `provider/args.rs`는 실재하지 않는 경로라 `agent/args.rs`로 정정한다(2026-11-10 점검, D50).
- 복원된 값에 `name`과 `arguments`가 있으면 도구 호출로 처리한다.
- 복원이 실패하면 짧은 오류 글자("JSON을 찾지 못했어. 형식대로 다시 써줘")를 도구 결과 자리에 넣어 모델에게 돌려준다.

## 스키마 검증 (AC 4)
- 복원한 인자를 `Tool::parameters_schema` 기준으로 검사한다. 필수 누락·타입 어긋남은 도구 실행 전에 "인자 형식이 어긋났어(필요한 것: …)" 한 줄 오류로 돌려준다.
- 미등록 도구 이름은 "등록되지 않은 도구야(사용 가능: …)"로 돌려준다.

## 결과 전달 규격
- 도구 결과는 messages에 `role: user` 글자로 붙인다. 형식: `도구 결과 [name]` 줄과 내용, 4,000자 잘림은 03-2 규칙과 동일.
- 2안에서 여러 호출이 한 번에 오면(2개) 첫 호출만 실행하고 나머지는 "한 번에 하나만 호출" 오류로 돌려준다(범위 Out).

## 설정 (모델 프로필)
- 모델 프로필에 `tool_call_form` 필드를 더한다: `openai`(기본)·`text`·`auto`. `openai`·`text`는 선언대로만 쓰고 감지하지 않는다. `auto`일 때만 위 감지 규칙을 쓴다(업계 관례는 사전 선언형 기본 — 12번 8절, D50).
- 읽기(`config/read/parse.rs`)·저장(`config/save/check.rs`·`config/save/config.rs`)·기본값·예시 파일(`agent-snap.example.jsonc`)을 같은 작업에서 함께 고친다(D29 `context_window`가 지난 자리 규칙과 같음).
- 감지로 정한 값은 전환 기록에만 남긴다. `state.json` 형식 변경은 허용하지 않는다(D22).

## AC
1. 모의 서버가 4xx(400·404·422)를 내는 상황에서 2안 전환이 확인된다. 텍스트 1회는 전환 후보로만 남고 2회 연속에서 전환이 확정되는 것도 함께 확인한다.
2. 2안 시스템 프롬프트에 등록된 도구 이름과 인자 형식 글자가 포함된다.
3. Markdown 둘레·접두사·잘린 JSON을 복원하는 단위 테스트가 통과한다.
4. 스키마 불일치 인자가 도구 실행 전에 짧은 오류로 돌아간다.
5. 전환·복귀 기록이 03-2 AC 1의 도구 호출 기록 자리(`ToolCallRecord.format`·`LoopResult.fallback_point`)에 남는다.
6. 검증 명령 3종 통과(공통 DoD).
7. 설정 `tool_call_form`이 `text`로 선언된 모델은 감지를 거치지 않고 2안 조립으로 요청이 나감을 모의 서버로 확인한다(선언 우선 규칙).
