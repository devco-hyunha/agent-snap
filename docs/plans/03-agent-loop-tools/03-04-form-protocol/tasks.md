# 03-4 호출 형식 2안 텍스트 프로토콜 폴백: 작업 계획

- 상위 문서: [plan.md](plan.md), [spec.md](spec.md)
- 검증 명령과 공통 DoD는 [상위 문서](../../03-agent-loop-tools.md)의 '세부 작업 공통 기준'을 따른다.
- 선행: 03-2(루프 골격·`ToolsUnsupported` 지점) 완료 상태에서 착수한다.

## 구현 단계
- [ ] 1. 감지 함수를 만든다. 4xx 코드 수신, 도구 호출 없는 텍스트 2회 연속 기준을 순수 함수로 구현한다. 확인: 모의 서버가 4xx를 낼 때 폴백으로 전환되는 통합 테스트(spec AC 1).
- [ ] 2. 2안 시스템 프롬프트 조립을 만든다. 등록 도구의 이름·인자 형식·호출 예시를 글자로 넣는 조립 함수. 확인: 프롬프트 문자열에 도구 이름과 인자 필드가 포함되는 단위 테스트(spec AC 2).
- [ ] 3. 응답 복원을 `args.rs` 재사용으로 연결한다. Markdown 둘레·접두사·잘린 JSON 복원 순서 재사용(중복 구현 금지). 확인: 3종 입력 복원 단위 테스트(spec AC 3).
- [ ] 4. 스키마 검증을 넣는다. `Tool::parameters_schema` 대조, 필수 누락·타입 어긋남·미등록 이름을 도구 실행 전 짧은 오류로 반환. 확인: 오류 글자 단위 테스트(spec AC 4).
- [ ] 5. 결과 전달 규격을 만든다. `도구 결과 [name]` 형식 messages 부춤, 4,000자 잘림(`…[truncated]`) 재사용. 확인: 왕복 테스트에서 결과 형식 확인.
- [ ] 6. 전환·복귀 기록을 `logs`에 남긴다(03-2 AC 1 출력과 같은 자리). 확인: 로그 줄 존재 테스트(spec AC 5).
- [ ] 7. 모델 프로필에 `tool_call_form`(`openai`·`text`·`auto`)을 넣는다. `config.rs`에 필드 추가, `auto`는 감지 결과로 정한다. 확인: 프로필 설정 시 요청 조립이 알맞는 형식으로 되는지 모의 서버 테스트.

## 테스트 계획
- 종류: 모의 서버 통합 테스트(02-5·02-6 패턴 재사용) + 네트워크 없는 단위 테스트.
- 4xx 모의 서버 응답을 여러 코드(400·404·422)로 두고, 텍스트 응답을 1회·2회 연속으로 낸 응답을 따로 둔다.
- 복원 테스트 입력은 2609.07370 표 2 규칙의 예제(코드블럭·접두사·잘린 JSON)를 쓴다.
- 여러 도구 등록 프롬프트 총 길이를 상한으로 재는 테스트(06에서 값 확정)는 값 없는 자리로 `skip`을 둔다.
