# 03-4 호출 형식 2안 텍스트 프로토콜 폴백: 작업 계획

- 상위 문서: [plan.md](plan.md), [spec.md](spec.md)
- 검증 명령과 공통 DoD는 [상위 문서](../../03-agent-loop-tools.md)의 '세부 작업 공통 기준'을 따른다.
- 선행: 03-2(루프 골격·`FallbackPoint`·`LoopError::Unsupported` 지점) 완료 상태에서 착수한다(2026-11-10 정정: 문서의 옛 `ToolsUnsupported`라는 이름은 코드에 없고 `agent/fallback.rs`가 그 자리다).

## 구현 단계
- [ ] 1. 감지 함수를 만든다. 4xx 코드 수신, 도구 호출 없는 텍스트 2회 연속 기준을 순수 함수로 구현한다. 텍스트 1회는 전환 후보 표시로만 남기고 전환 확정은 2회 연속에서 한다(03-2 루프의 `ToolCallFormat` 상태를 소비하는 자리, spec 감지 기준). 확인: 모의 서버가 4xx를 낼 때 2안으로 전환되고, 텍스트 1회는 후보로만 기록되는 통합 테스트(spec AC 1).
- [ ] 2. 2안 시스템 프롬프트 조립을 만든다. 등록 도구의 이름·인자 형식·호출 예시를 글자로 넣는 조립 함수. 확인: 프롬프트 문자열에 도구 이름과 인자 필드가 포함되는 단위 테스트(spec AC 2).
- [ ] 3. 응답 복원 순서를 연결한다. assistant 내용에서 Markdown 둘레 제거 → 중괄호 추출(신규) → `agent/args.rs`의 `recover_arguments` 1회 복구 재사용 → 스키마 검증 → 모호 시 거부. 확인: 3종 입력(코드블럭·접두사·잘린 JSON) 복원 단위 테스트(spec AC 3).
- [ ] 3a. 루프의 형식 전환 상태를 만든다. `agent/runner.rs`가 `ToolCallFormat`(1안·2안)을 왕복 조립에서 고르고, 4x·2회 연속 텍스트에 `tools` 배열을 빼고 2안 조립을 붙인다. messages는 이어쓰고 같은 요청 재시도는 02-6 한 층만(D13). 확인: 1안→2안→도구 호출 왕복 통합 테스트.
- [ ] 4. 스키마 검증을 넣는다. `Tool::parameters_schema` 대조, 필수 누락·타입 어긋남·미등록 이름을 도구 실행 전 짧은 오류로 반환. 확인: 오류 글자 단위 테스트(spec AC 4).
- [ ] 5. 결과 전달 규격을 만든다. `도구 결과 [name]` 형식 messages 부춤, 4,000자 잘림(`…[truncated]`) 재사용. 확인: 왕복 테스트에서 결과 형식 확인.
- [ ] 6. 전환·복귀 기록을 `ToolCallRecord.format`·`LoopResult.fallback_point` 자리에 남긴다(파일 로그 기록은 04 배치라 범위 밖, D50). 확인: 기록 항목에 2안 형식 값이 채워지는지 테스트(spec AC 5).
- [ ] 7. 모델 프로필에 `tool_call_form`(`openai`·`text`·`auto`)을 넣는다. 읽기(`config/read/parse.rs`)·저장(`config/save/check.rs`·`config/save/config.rs`)·기본값·예시 파일(`agent-snap.example.jsonc`)을 같은 작업에서 고치고, D20 정본 선택 목록에 갱신한다. 선언 값(`openai`·`text`)은 감지 없이 쓰고 `auto`만 감지한다. 확인: `text` 선언 모델이 2안 조립으로 나가는 모의 서버 테스트와 설정 왕복 테스트.

## 테스트 계획
- 종류: 모의 서버 통합 테스트(02-5·02-6 패턴 재사용) + 네트워크 없는 단위 테스트.
- 4xx 모의 서버 응답을 여러 코드(400·404·422)로 두고, 텍스트 응답을 1회·2회 연속으로 낸 응답을 따로 둔다.
- 복원 테스트 입력은 2609.07370 표 2 규칙의 예제(코드블럭·접두사·잘린 JSON)를 쓴다.
- 여러 도구 등록 프롬프트 총 길이를 상한으로 재는 테스트(06에서 값 확정)는 값 없는 자리로 `skip`을 둔다.
