# 03-4 호출 형식 2안 텍스트 프로토콜 폴백: 상세 기획

- 상태: 완료 (T1 2안 폴백 경로, 독립 리뷰 2차 PASS 2026-11-11)
- 상위 문서: [../../03-agent-loop-tools.md](../../03-agent-loop-tools.md), 선행: [03-2](../03-02-agent-loop/plan.md)
- 근거: [12번 문서](../../../research/12-tool-calling-forms.md) 2절 2갈래, 5절 llama.cpp 기록, 8절(2026-11-10 추가 조사: 업계 관례·TSCG·감사 주의). 2026-11-08 사용자 결정(3형식 조합)의 2안. 설계 확정: D46·[D50 정본](../../../decisions/D50-form-switch-detection.md).

## 목적
OpenAI `tools`/`tool_calls`를 쓰지 못하는 로컬 모델(llama.cpp 템플릿 미지원, 4xx로 떨어지는 서버)에서 도구 호출이 계속 이어지게 한다. 03-2가 남긴 폴백 연결 지점(`agent/fallback.rs`의 `FallbackPoint`·`LoopError::Unsupported`, 2026-11-10 정정: 문서의 옛 `ToolsUnsupported`라는 이름은 코드에 없다)을 2안 경로로 잇는다.

## 범위(In)
- 폴백 트리: 03-2 루프가 1안으로 요청을 보냈을 때 4xx나 도구 호출 없는 일반 텍스트가 오면 2안 경로로 전환한다. 텍스트 1회는 전환 후보로만 남기고 2회 연속에서 전환을 확정한다(03-2이 남긴 `FallbackPoint`·`ToolCallFormat`을 03-4가 소비하고, 형식 전환은 루프 안의 상태로 둔다 — D50).
- 2안 조립: 시스템 프롬프트에 도구 이름·인자 JSON 형식을 글자로 적어 넣는다(스키마를 프롬프트에 박는다).
- 응답 회수: 모델 답에서 JSON 객체를 복원한다. 복원 순서는 Markdown 둘레 제거 → 중괄호 추출 → 파싱 → `agent/args.rs`의 `recover_arguments`(닫힘 기호 1회 복구) 재사용 → 스키마 검증 → 모호 시 거부(spec 응답 복원 절, D50). 복원 실패·스키마 불일치는 짧은 오류로 모델에 알린다.
- 결과 전달: 도구 결과를 2안 규격(모델이 읽는 글자 형식)으로 messages에 덧붙인다.
- 전환·복귀 기록: 어떤 턴에서 2안으로 갔고 언제 1안으로 돌아갔는지 03-2 도구 호출 기록 자리(`ToolCallRecord.format`·`LoopResult.fallback_point`)에 남긴다. 파일 로그 기록은 04 배치라 범위 밖(D50).
- 설정: 모델 프로필에 호출 형식 필드를 두고(`openai`·`text`·`auto`), 선언 값은 감지 없이 쓰고 auto만 감지로 고른다. 읽기·저장·기본값·예시 파일을 함께 고친다(D50).

## 비범위(Out)
- 코드 모드(execute): 03-8.
- 제약 생성(grammar constrained decoding) 서버 연동: 서버 의존성이 커져 범위 밖(04 후보).
- 다중 호출(글자 형식의 여러 호출) 파싱이 3개 이상: 1안은 한 응답 여러 호출을 쓰므로 2안은 1개 호출부터. 2개 이상은 06 실측 후 판단.

## AC
1. 4xx(도구 미지원)를 모의 서버로 만들어 2안 경로로 전환되는 것을 테스트로 확인한다.
2. 2안 프롬프트에 등록된 도구 이름과 인자 형식이 글자로 들어가는 것을 확인한다.
3. 복원 파싱이 Markdown 둘레·접두사를 뭉개고 JSON 객체를 찾아내는 것을 테스트로 확인한다(2609.07370 표 2 규칙).
4. 스키마에 안 맞는 인자는 도구 실행 전에 짧은 오류로 돌아간다.
5. 전환·복귀 기록이 도구 호출 기록(03-2 AC 1의 출력)에 남는다.
6. 설정 `tool_call_form` 선언(`text`)이면 감지 없이 2안 조립으로 나간다(spec AC 7).

## 리스크
- 2609.07370은 2안 경로 기준 준수율이 모델마다 0%~79%로 벌어진다(5절). 로컬 모델 선택이 준수율을 정하고, 형식 선택은 정하지 못한다 → 설정 모델 프로필에 권장 모델·온도를 적는다.
- 2안 프롬프트가 길어져 토큰이 든다(4절 ②행). 시스템 프롬프트가 이미 8줄인 03-2과 합쳐 길이를 잰다(06 스모크).
- llama.cpp Generic 토큰 증가가 같은 경로에서 겹친다 → `--jinja`·템플릿 확인(/props)을 안내 문서에 적는다.
- llama.cpp 실무 함정(12번 8절): 서버가 준 `tool_call_id`를 다음 턴에 재투입하면 템플릿 검증에 걸려 400(이슈 #26359, Ministral은 9자리 규칙). 과도한 KV 양자화(`-ctk q4_0`)는 도구 호출 성능을 깎는다 → id 생성 규칙과 안내는 03-4에서 잡고 실측 확인은 06.
- 스키마 글자 압축(TSCG 2605.04107: 읽는 쪽 스키마를 압축하면 준수율 0→84.4, 토큰 52~57% 절감)은 준수율 개선을 노리는 근거이나 답은 JSON 유지가 원칙 → 읽기 쪽만 압축하는 방식은 06 실측 후 후보. 2026-11-10 보정 조사(12번 9절 (b)): 소형 모델 이득은 압축이 아니라 JSON→글자 형식 변환에서 나오고 순수 압축 이득은 0에 가까우며, 2605.26165는 8K에서 JSON 스키마가 창을 넘쳐 정답률 2.6% → 절감 시 +20.5pp로 프롬프트 길이 리스크를 뒷받침한다.
- 2609.07370 인용 주의(12번 8절): 4.4절의 실패 658개는 표 2 합계와 계산이 어긋난다는 외부 감사가 있다 → 준수율 인용은 표 2·표 3만 쓴다.
- 복원 실패 시 짧은 오류로 한 번 되알리는 권고(12번 9절 (a): 표 3 기준 파서 부담이 복원 실패에 집중) → 03-4는 오류 안내 1회까지만 허용하고, 재시도 누적은 02-6 한 층만 쓴다.
