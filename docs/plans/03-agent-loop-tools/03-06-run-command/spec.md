# 03-6 run_command·승인자 주입·deadline: 명세

- 상위 문서: [plan.md](plan.md), 상위 기획: [../../03-agent-loop-tools.md](../../03-agent-loop-tools.md)

## 입력과 출력
- run_command 입력: 명령 문자열, 작업 폴더, 승인자, 설정(실행 600초·승인 300초), cancel 토큰.
- run_command 출력: 표준 출력·표준 오류(잘림 표시 가능), 종료 코드, 상태(완료·미완료·거부·중단).
- 승인자 입력: 명령 문자열과 설명. 출력: 승인·거부.

## 동작 규칙

### 승인자 (AC 9)
- CLI가 승인자를 주입한다. M1 기본은 명령마다 확인(L1).
- 승인자가 없거나 비대화형이면 즉시 거부한다(거부 표시, 300초 대기 아님).
- 승인 응답을 300초 안에 받지 못하면 거부로 처리한다.
- 거부는 거부 이유를 모델에 도구 결과로 전달한다.
- 같은 명령을 같은 인자로 재시도하지 않는다(03-2 규칙).

### 실행 (AC 8)
- 승인된 명령만 실행한다.
- 600초 안에 끝나면 종료 코드를 전달한다.
- 600초가 지나면 미완료를 도구 결과로 전달한다.
- 600초와 300초는 02 설정에 `agent` 섹션 `run_command_deadline`·`approval_deadline`로 넣는다.
- cancel 시도를 02 토큰으로 연결한다.

### 경로 (AC 2)
- 작업 폴더 안에서 실행한다.
- `run_command`로 작업 폴더 밖 절대 경로·심볼릭 링크는 승인자·경계 검사를 통과한다.
- `run_command`로 비밀 파일 읽기 우회는 이름 검사로 막지 못함을 기록한다.
- 03-6 구현은 03-3의 경로 검사 헬퍼를 `run_command`에 재사용한다.

## AC (상위 문서 AC 8·9와 연결)
1. 승인된 명령만 실행한다. 승인 미주입·비대화형이면 즉시 거부한다(테스트).
2. 승인 응답 deadline 300초 만료 시 거부로 기록한다(테스트).
3. 실행 deadline 600초 만료 시 미완료를 확인한다(테스트).
4. cancel 시 02의 cancel 토큰으로 연결된다.
5. 03-3 경로 검사 헬퍼를 사용한다.
6. 검증 명령 3종 통과(공통 DoD).
