# 04 대화형 CLI, 세션, 맥락 관리

- 상태: planned

## 목적
매일 쓸 수 있는 대화형 에이전트로 만든다.

같은 프로젝트의 다른 세션과 다른 프로젝트의 세션을 `#`·`@`처럼 지목해 호출한다.

## 범위(In)
- 대화형 모드: 스트리밍 표시, reasoning 구분 표시, Ctrl+C로 현재 턴만 취소, 명령 승인 프롬프트.
- session: 세션을 `.agent-snap/sessions/`에 jsonl로 저장하고 다시 이어 간다. base_url과 키는 저장하지 않는다. 세션 jsonl에 턴마다 시작·끝 시각과 생성 토큰 수를 남긴다. 서버가 사용량을 주지 않으면 context의 토큰 추정값을 쓰고 추정값임을 표시한다.
- 세션 기록 가리기(Claude Code 비밀 유출 사건 교훈, 2026-11-10): 세션 jsonl에 기록하기 전에 도구 출력·대화 텍스트를 가린다. `SecretScrub`(02-5, 알고 있는 키·base_url 재가리기)과 어림 가리기(02-5 `redact` 규칙)를 기록 지점에도 재사용하고, `.env` 평문·`PGPASSWORD=`·`sshpass -p`·헤더에 붙은 비밀번호처럼 제공업체 키가 아닌 형태는 어림 규칙(글자 16 이상 + 숫자와 알파가 섞임, `sk-`·Bearer 접두)로 추가 가린다. 키·base_url 자체는 저장하지 않는다는 위 규칙을 유지하면서, 명령 출력(`cat`·`curl`이 뱉은 값)이 평문으로 세션에 남지 않게 하는 것이 목적이다. 로그 파일(`logs/`, git 추적 제외)도 같은 가리기를 지난 뒤 기록한다.
- 용어: "대화"는 사용자 입력 하나부터 그 응답이 끝날 때까지(도구 호출 반복 포함), "세션"은 jsonl 세션 하나 전체다.
- context: 토큰 추정, **선택한 모델의 `context_window`**(생략 시 65536, D29) 한도 안에서 오래된 도구 출력 줄이기와 요약을 한다. `max_tokens`는 생성 길이라 이 한도로 쓰지 않는다.
- 작업 폴더의 `AGENTS.md`를 프로젝트 지시로 읽는다.
- 대화용 세션은 작업용 단발 호출(작업 03)과 병행해 쓸 수 있다. 단발 호출 명세 규칙은 작업 03을 따른다.
- /models: 설정의 모델 목록과 엔드포인트에서 조회한 모델 목록을 보여 주고, 대화 중 모델을 바꾼다. 바꿔도 대화 기록은 이어진다.
- 같은 프로젝트의 다른 세션을 지목해 호출한다.
- 다른 프로젝트의 세션을 지목해 호출한다.
- 지목하는 표기와 호출 결과를 받는 방식은 착수 시 사용자와 확정한다.
- (확장 후보, 2026-11-07 조사 반영 제안) 서브 세션 열기와 브리프 전달: 부모가 새 세션을 열고 하네스 브리프(포인터 샌드위치)를 담아 위임한다. 부모→자식 중간 지시 전달, 자식→부모 보고를 지원한다. 조사: [research 03 멀티 세션·서브세션 비교](../research/03-agent-loop-tools.md#멀티-세션·서브세션-기능-비교-타-에이전트)
- (확장 후보) 사이드 대화: 본 세션을 건드리지 않고 곁가지 대화를 따로 연다(Prospero `/side`, Cursor 사이드 채팅 참고).
- (확장 후보) `/new`: 새 세션을 열고 브리프를 전달한다. 타 에이전트는 새 세션 열기와 브리프 전달이 분리되어 있어 둘을 묶은 명령으로 설계한다.
- (확장 후보, 2026-11-07 사용자 요구) 서브 세션 위임은 위임 프롬프트와 작업 문서·산출물만 전달한다. 부모 대화를 서브 세션에 주기적으로 통째로 보내는 방식은 금지한다. 근거: Claude Code는 부모 대화를 서브에 계속 흘려보내 토큰을 낭비하는 문제가 알려짐(2026-11-07 사용자 지적). 부모→자식 추가 지시가 필요할 때는 짧은 지시문 한 줄만 보내서 이룬다(Prospero `send_message`, Codex `codex queue` 참고). 자식→부모 보고는 고정 형식(결과 1줄·불릿 5개 이내·경로)으로 받고, 장문을 부모 컨텍스트에 쌓지 않는다.
- (배치 확정, 2026-11-07 D43 → 2026-11-09 2차 개정으로 조정) 웹 검색·열람 도구(web_search·web_fetch), ask_user(모델이 사용자에게 묻기), 계획 모드(to-do 목록), 체크포인트(git 연동), 심볼 도구 1차(네이티브, D33), 훅 연결 지점(hooks), MCP 연결은 03-11~13에서 만든다(D43 2차 개정). 04에 남는 것은 슬래시 커맨드(/new·/compact·/side 설계와 함께)·메모리 계층·규칙 계층·세션 허용 UI·출력 표시·상태 라인이다. 우선순위는 [기능 목록](../research/agent-feature-inventory-2026-11-07.md)과 대조해 착수 시 확정한다. 05·06으로 넘기지 않는다.
- (사용자 관찰 2026-11-07) 모델 교체 시 토큰 낭비 문제: Claude는 대화 중 모델을 바꾸면 대화 내용을 통째로 다시 넣어야 한다며 경고한다. snap은 04에서 이 경우를 줄인다. 설계 방향: `/models`로 교체할 때 전송 맥락을 통째 재전송하지 않고, (1) 1차 압축(오래된 도구 출력 가리기) + 2차 LLM 요약(컴팩트)으로 줄인 기록, (2) 세션 임시 문서(현재 상태만 담는 문서, D36 4번), (3) 규칙·경로·명령의 규칙 추출 보존(2610.31710)을 조합해 새 모델에 넘긴다. RAG·OKF 상태 쪽(D36)이 발판이고, 상세는 04 착수 시 확정.
- (지시 파일 색인 관리, 2026-11-07 사용자 제안·2026-11-08 3차 교정) 에이전트가 스킬·하네스 규칙·AGENTS.md·CLAUDE.md·rules·프롬프트 파일의 목록·요약·경로를 담는 관리 파일을 하나 다룬다. 여러 파일을 열지 않고 관리 파일 하나로 필요한 스킬과 규칙을 파악하고, 필요한 파일만 다시 읽는다. Claude의 "파일마다 앞 100줄 열기" 방식을 없애는 것이 목적이다. 요약은 파일 내용에서 만들고, frontmatter는 보조 신호로만 쓴다(frontmatter 유무로 스킬을 걸러내지 않는다). 전달 우선순위: 사용자가 지정한 규칙은 색인 우선순위와 별개로 항상 1순위로 필수 전달한다. 변경 감지는 git 비교가 아니라 snap이 파일 목록을 조회해 기록한 mtime·크기·해시를 비교해서 한다(2026-11-08 지적 3, git 의존 폐기). 추가·삭제·수정이 감지되면 그 파일을 읽어서 색인 항목을 갱신한다(표시만 남기지 않는다). 형식은 jsonc 확정, 스캔 주기는 04 착수 시 확정(세션 시작 + 읽기 직전 vs 주기 스케줄). 토글은 2층으로 둔다(2026-11-08 4차 교정): 색인에는 파일 기본값(`always`·`on-demand`·`off`)만 담고, 세션마다 지정하는 강제 토글(`user-pinned` 강제 1순위·`off` 예외)은 세션 기록에 담는다. 우선순위는 세션 지정이 색인 기본값보다 위다. 상세: [research 11번 5절](../research/11-rag-okf-memory-skills.md#5-지시-파일-색인-관리-설계-제안-2026-11-07-사용자-제안-2026-11-08-3차-교정까지-반영)·[5-1 효과 검토](../research/11-rag-okf-memory-skills.md#5-1-효과-검토-2026-11-08-사용자-요청)

## 반영할 연구
- 1차 맥락 압축은 오래된 도구 출력 가리기, LLM 요약은 2차로 둔다(2508.21433).
- 경로, 오류, 명령은 규칙으로 추출해 압축 후에도 보존한다(2610.31710).
- 지시와 규칙은 맥락 처음과 끝에 둔다(2307.03172).
- 세션·감시 이력을 파일로 남겨 06의 실패 진단에 쓴다(2603.28052).

## AC
1. Ctrl+C가 현재 스트림만 끊고 세션은 유지된다(테스트 또는 기록).
2. 세션을 저장하고 이어 가면 대화가 이어진다(테스트).
3. 긴 모의 세션에서 전송 맥락이 해당 모델의 `context_window`(생략 시 65536)를 넘지 않는다(테스트, D29).
4. 실제 엔드포인트로 20턴 이상 이어진 세션 기록이 `docs/reports/04-session.md`에 있다.
5. RESEARCH.md에 조사 항목과 적용 위치가 있다. 검증 명령(`cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`)을 통과한다.
6. 대화 세션과 단발 호출이 병행해 동작한다(테스트).
7. /models로 모델을 바꾼 뒤 다음 요청이 새 모델로 가고 대화 기록이 유지된다(모의 서버 테스트).
8. 같은 프로젝트의 다른 세션을 지목해 호출하면 해당 세션이 응답한다(테스트).
9. 다른 프로젝트의 세션을 지목해 호출하면 해당 세션이 응답한다(테스트).
10. 검증 명령(`cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`)을 통과한다.
11. 세션 기록만으로 대화별 초당 평균 생성 토큰·대화 시간과, 세션별 초당 평균 토큰·작업 시간·이어진 턴 수를 계산할 수 있다(테스트).
12. 세션 jsonl 기록 지점에서 키·base_url 문자열과 어림 가리기 규칙(글자 16 이상 + 숫자와 알파가 섞임, `sk-`·Bearer 접두)에 걸리는 비밀 조각이 가려져 평문이 남지 않음을 테스트로 확인한다(범위(In) 세션 기록 가리기 항목).
