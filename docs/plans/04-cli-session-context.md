# 04 대화형 CLI, 세션, 맥락 관리

- 상태: planned

## 목적
매일 쓸 수 있는 대화형 에이전트로 만든다.

같은 프로젝트의 다른 세션과 다른 프로젝트의 세션을 `#`·`@`처럼 지목해 호출한다.

## 범위(In)
- 대화형 모드: 스트리밍 표시, reasoning 구분 표시, Ctrl+C로 현재 턴만 취소, 명령 승인 프롬프트.
- session: 세션을 `.agent-snap/sessions/`에 jsonl로 저장하고 다시 이어 간다. base_url과 키는 저장하지 않는다. 세션 jsonl에 턴마다 시작·끝 시각과 생성 토큰 수를 남긴다. 서버가 사용량을 주지 않으면 context의 토큰 추정값을 쓰고 추정값임을 표시한다.
- 용어: "대화"는 사용자 입력 하나부터 그 응답이 끝날 때까지(도구 호출 반복 포함), "세션"은 jsonl 세션 하나 전체다.
- context: 토큰 추정, 설정한 맥락 한도 안에서 오래된 도구 출력 줄이기와 요약을 한다.
- 작업 폴더의 `AGENTS.md`를 프로젝트 지시로 읽는다.
- 대화용 세션은 작업용 단발 호출(작업 03)과 병행해 쓸 수 있다. 단발 호출 명세 규칙은 작업 03을 따른다.
- /models: 설정의 모델 목록과 엔드포인트에서 조회한 모델 목록을 보여 주고, 대화 중 모델을 바꾼다. 바꿔도 대화 기록은 이어진다.
- 같은 프로젝트의 다른 세션을 지목해 호출한다.
- 다른 프로젝트의 세션을 지목해 호출한다.
- 지목하는 표기와 호출 결과를 받는 방식은 착수 시 사용자와 확정한다.

## 비범위(Out)
감시와 교정, 앱.
- 전송 방법과 형식(착수 시 사용자와 확정한다).

## 조사
- 주제: 에이전트 맥락 관리(관찰 결과 가리기와 요약 비교), 긴 세션의 성능 저하.
- 참고 설계: Project Think(Cloudflare, MIT)의 트리형 세션(parent_id, 분기), 비파괴 압축, 세션 검색, 컨텍스트 블록(모델이 읽고 고치는 영속 구역). Flue의 append-only 이벤트 로그와 마지막 단계부터 재개.
- 주제: 에이전트 간 세션 참조와 호출 방식. 기록은 `docs/RESEARCH.md` 작업 04 절에 남기고, 링크는 직접 열어 확인한 것만 적는다.

## 반영할 연구
- 1차 맥락 압축은 오래된 도구 출력 가리기, LLM 요약은 2차로 둔다(2508.21433).
- 경로, 오류, 명령은 규칙으로 추출해 압축 후에도 보존한다(2610.31710).
- 지시와 규칙은 맥락 처음과 끝에 둔다(2307.03172).
- 세션·감시 이력을 파일로 남겨 06의 실패 진단에 쓴다(2603.28052).

## AC
1. Ctrl+C가 현재 스트림만 끊고 세션은 유지된다(테스트 또는 기록).
2. 세션을 저장하고 이어 가면 대화가 이어진다(테스트).
3. 긴 모의 세션에서 전송 맥락이 설정 한도를 넘지 않는다(테스트).
4. 실제 엔드포인트로 20턴 이상 이어진 세션 기록이 `docs/reports/04-session.md`에 있다.
5. RESEARCH.md에 조사 항목과 적용 위치가 있다. 검증 명령(`cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`)을 통과한다.
6. 대화 세션과 단발 호출이 병행해 동작한다(테스트).
7. /models로 모델을 바꾼 뒤 다음 요청이 새 모델로 가고 대화 기록이 유지된다(모의 서버 테스트).
8. 같은 프로젝트의 다른 세션을 지목해 호출하면 해당 세션이 응답한다(테스트).
9. 다른 프로젝트의 세션을 지목해 호출하면 해당 세션이 응답한다(테스트).
10. 검증 명령(`cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`)을 통과한다.
11. 세션 기록만으로 대화별 초당 평균 생성 토큰·대화 시간과, 세션별 초당 평균 토큰·작업 시간·이어진 턴 수를 계산할 수 있다(테스트).

## 테스트 계획
검증 명령(`cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`), 실제 엔드포인트 세션.

## 리스크
서버마다 토크나이저가 달라 토큰 추정이 어긋난다. 여유분을 두고 설정으로 조정한다.
- 다른 프로젝트의 세션을 읽거나 부르는 일은 접근 범위를 넓힌다 → 착수 시 사용자와 허용 범위를 확정하고, 새 권한이므로 승인 없이 진행하지 않는다.
