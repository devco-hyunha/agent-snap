# 04 대화형 CLI, 세션, 맥락 관리

- 상태: 계획

## 근거(선행 계획 잔여)
- 03 `tasks.md`의 `## 잔여` 절과 03 계획의 인계 절을 포인터로 따라간다. 03 잔여 PASS 뒤에 착수한다.
- 03 산출물 계승: `Tool` 트레이트와 도구들, AGENTS.md 읽기 최소 경로, 승인자 인터페이스, 단발 run 경로. 이름·경로를 바꾸면 옮긴 자리의 설명을 함께 고친다. 03이 넘긴 규칙 계층·세션 상태 관리 항목을 이 계획이 받는다.

## 목적
매일 쓸 수 있는 대화형 에이전트로 만든다. 같은 프로젝트의 다른 세션과 다른 프로젝트의 세션을 지목해 호출한다.

## 범위(In)
- 대화형 모드: 스트리밍 표시, reasoning 구분 표시, Ctrl+C로 현재 턴만 취소, 명령 승인 프롬프트.
- session: 세션을 `.snap/sessions/`에 jsonl로 저장하고 다시 이어 간다. base_url과 키는 저장하지 않는다. 세션 jsonl에 턴마다 시작·끝 시각과 생성 토큰 수를 남긴다. 서버가 사용량을 주지 않으면 context의 토큰 추정값을 쓰고 추정값임을 표시한다.
- 세션 기록 가리기: 세션 jsonl에 기록하기 전에 도구 출력·대화 텍스트를 가린다. 알고 있는 키·base_url 재가리기와 어림 가리기 규칙을 기록 지점에도 재사용하고, `.env` 평문·`PASSWORD=`·`sshpass -p`·헤더에 붙은 비밀번호처럼 제공업체 키가 아닌 형태는 어림 규칙(글자 16 이상 + 숫자와 알파가 섞임, 접두 표식)로 추가 가린다. 키·base_url 자체는 저장하지 않는 규칙을 유지하면서, 명령 출력이 평문으로 세션에 남지 않게 한다. 로그 파일도 같은 가리기를 지난 뒤 기록한다.
- 용어: "대화"는 사용자 입력 하나부터 그 응답이 끝날 때까지(도구 호출 반복 포함), "세션"은 jsonl 세션 하나 전체다.
- context: 토큰 추정, 선택한 모델의 `context_window`(생략 시 65536) 한도 안에서 오래된 도구 출력 줄이기와 요약을 한다. `max_tokens`는 생성 길이라 이 한도로 쓰지 않는다.
- 작업 폴더의 `AGENTS.md`를 프로젝트 지시로 읽는다(03의 최소 읽기에서 계층 확장).
- 대화용 세션은 작업용 단발 호출(작업 03)과 병행해 쓸 수 있다. 단발 호출 명세 규칙은 작업 03을 따른다.
- /models: 설정의 모델 목록과 엔드포인트에서 조회한 모델 목록을 보여 주고, 대화 중 모델을 바꾼다. 바꿔도 대화 기록은 이어진다.
- 같은 프로젝트·다른 프로젝트의 세션을 지목해 호출한다. 지목 표기와 호출 결과를 받는 방식은 착수 시 사용자와 확정한다.
- 확장 후보: 서브 세션 열기와 브리프 전달(부모→자식 중간 지시 한 줄, 자식→부모는 고정 형식 보고), 사이드 대화, `/new`. 부모 대화를 서브에 주기적으로 통째로 보내는 방식은 금지한다.
- 배치로 03-11~13에 넘긴 항목(웹 도구·계획 모드·체크포인트·심볼·훅·MCP)은 04 범위 밖이고, 04에 남는 것은 슬래시 커맨드·메모리 계층·규칙 계층·세션 허용 UI·출력 표시·상태 라인이다.
- 모델 교체 시 토큰 낭비 줄이기: 전송 맥락을 통째 재전송하지 않고, 오래된 도구 출력 가리기 + LLM 요약으로 줄인 기록, 세션 임시 문서(현재 상태만 담는 문서), 규칙·경로·명령의 규칙 추출 보존을 조합해 새 모델에 넘긴다. 상세는 착수 시 확정.
- 상수·텍스트 배치: 대화형 표시·승인 프롬프트·슬래시 커맨드 안내 문구는 로케일 모듈(locale 폴더 구조)에, 기본 맥락 한도·토글 기본값 같은 상수는 상수 모듈에 모은다. 함수에서 즉석 문자열을 만들지 않는다(01 뼈대 자리 사용).
- 서버 계층 배치(04-4): 서버 코드는 `snap-core/src/server/`에 두고 HTTP 전용(라우트·인증·신호 변환)만 담는다. 로직은 03·04 모듈을 그대로 부르고 서버에 복사하지 않는다. `snap-cli`는 서버를 켜는 진입만 맡는다.
- 지시 파일 색인 관리: 에이전트가 스킬·규칙·AGENTS.md·rules·프롬프트 파일의 목록·요약·경로를 담는 관리 파일 하나를 둔다. 요약은 파일 내용에서 만들고 frontmatter는 보조 신호로만 쓴다. 변경 감지는 git이 아니라 snap이 파일 목록을 조회해 기록한 mtime·크기·해시 비교로 한다. 토글은 2층(파일 기본값, 세션 강제 토글). 상세는 착수 시 확정.

## 비범위(Out)
감시와 교정, 앱. 전송 방법과 형식은 착수 시 사용자와 확정한다. 서버 층 TLS·계정 관리 방식은 04-4 착수 시 확정한다.

## 조사
- 주제: 에이전트 맥락 관리(관찰 결과 가리기와 요약 비교), 긴 세션의 성능 저하, 에이전트 간 세션 참조·호출 방식, 타 에이전트의 서브 세션·세션 간 대화·요약(컴팩트) 기능, RAG·메모리 계층·스킬 점진 공개. 상세는 `docs/research/`에 남기고 링크는 직접 열어 확인한 것만 적는다.

## 반영할 연구
- 1차 맥락 압축은 오래된 도구 출력 가리기, LLM 요약은 2차로 둔다(2508.21433).
- 경로, 오류, 명령은 규칙으로 추출해 압축 후에도 보존한다(2610.31710).
- 지시와 규칙은 맥락 처음과 끝에 둔다(2307.03172).
- 세션·감시 이력을 파일로 남겨 06의 실패 진단에 쓴다(2603.28052).

## 세부 작업
세부 작업은 4갈래로 나눈다. 순서는 04-1 → 04-4 → 04-2 → 04-3이고, 선행이 겹치지 않는 항목은 병렬로 둔다. 04-4는 04-1의 세션 저장·승인자 인터페이스가 끝난 뒤에 착수한다. 착수 시 각 세부 작업마다 plan.md·spec.md·tasks.md를 `docs/plans/04-cli-session-context/<세부>/`에 작성한다.
- 04-1 대화형 CLI·세션 저장: 대화형 모드 표시, session jsonl 저장·이어가기, /models 교체, 지목 호출, AGENTS.md 계층 확장, 세션 기록 지표.
- 04-2 컨텍스트·메모리·색인: /compact 압축, 모델 교체 시 토큰 절약 조합, 메모리 계층, 지시 파일 색인·2층 토글.
- 04-3 슬래시 커맨드·상태 라인·출력 형식.
- 04-4 서버 층(04-1 뒤에 착수): axum 기반 HTTP 서버로 세션 이어가기·승인 요청·스트리밍 표시를 외부 접속에서 쓰게 한다. 서버가 받아들이는 주소와 포트는 `snap.jsonc` 설정에 두고, 계정(ID)과 비밀번호는 사용자 설정 폴더의 자격 파일(`credentials.jsonc`)에만 두고, 런타임에는 환경 변수로 주입한다. 기본 수신 주소는 로컬 루프백(127.0.0.1)이고, 외부(IP·도메인)로 여는 것은 설정으로 켠 때만 허용하고 인증을 거친다. 서버 모듈은 `snap-core/src/server/`에 자리만 잡아 두고, 모듈 목록 정본(`harness/PROJECT_RULES.md`와 `docs/plans/01-foundation.md`)에 `server`를 함께 적는다. 세부 설계(라우트·인증 세션 유지·TLS)는 04-4 착수 시 plan.md·spec.md·tasks.md를 `docs/plans/04-cli-session-context/server/`에 작성해 확정한다.

## AC
1. Ctrl+C가 현재 스트림만 끊고 세션은 유지된다(테스트 또는 기록).
2. 세션을 저장하고 이어 가면 대화가 이어진다(테스트).
3. 긴 모의 세션에서 전송 맥락이 해당 모델의 `context_window`(생략 시 65536)를 넘지 않는다(테스트).
4. 실제 엔드포인트로 20턴 이상 이어진 세션 기록이 `docs/reports/04-session.md`에 있다.
5. RESEARCH.md에 조사 항목과 적용 위치가 있고, 검증 명령(게이트 3종)을 통과한다.
6. 대화 세션과 단발 호출이 병행해 동작한다(테스트).
7. /models로 모델을 바꾼 뒤 다음 요청이 새 모델로 가고 대화 기록이 유지된다(모의 서버 테스트).
8. 같은 프로젝트·다른 프로젝트의 세션을 지목해 호출하면 해당 세션이 응답한다(테스트).
9. 세션 기록만으로 대화별 초당 평균 생성 토큰·대화 시간, 세션별 초당 평균 토큰·작업 시간·이어진 턴 수를 계산할 수 있다(테스트).
10. 세션 jsonl 기록 지점에서 키·base_url 문자열과 어림 가리기 규칙에 걸리는 비밀 조각이 가려져 평문이 남지 않음을 테스트로 확인한다.
