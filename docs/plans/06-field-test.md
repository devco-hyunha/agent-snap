# 06 실사용 과제 점검

- 상태: planned

## 목적
실제 엔드포인트로 코딩 과제를 수행해 에이전트가 쓸 만한지 확인한다. 이 세션 출력을 M2 평가 자료로 쌓는다.

## 범위(In)
- `eval/tasks/`: 자동 검증 명령(테스트)이 있는 코딩 과제 10~15개. 한국어 지시, 영어 자료가 섞인 과제, 긴 과제를 포함한다.
- 규칙 감시를 끈 경우와 켠 경우로 각 2회 실행한다. 세션 로그를 `eval/sessions/`에 저장하고 커밋한다(키와 주소 제외).
- 라벨 지침 `docs/eval/LABELING.md`: 코드와 기술 용어 원문은 이탈이 아니다. 문장 안의 한자·가나는 혼합이다. 같은 내용이 3회 이상 이어지면 반복이다. 말만 바꾼 반복도 포함한다.
- 라벨링: 라벨링 서브에이전트가 출력에 라벨을 달고, 독립 서브에이전트가 20%를 다시 라벨링한다.
- 분할: dev/test를 고정하고 test 라벨 해시를 기록한다.
- 보고서 `docs/reports/06-field.md`: 과제 성공률, 범주별 문제 사례 수, 규칙 감시의 적중·오탐, 대화당 초당 평균 생성 토큰과 대화 시간, 세션당 초당 평균 토큰·작업 시간·이어진 턴 수.

## 비범위(Out)
판정 모델.

## 반영할 연구
- 실패 세션을 진단해 목표가 분명한 수정으로 이어 간다(AutoSaddler 2608.23041).
- 감시 규칙 변경은 고정 실패 세트와 정상 세트 회귀를 통과해야 반영한다(2609.40169).
- 과제 성공률과 토큰 사용량을 함께 보고한다(Meta-Harness 2603.28052).

## AC
1. 모든 과제에 자동 검증 명령이 있고, 성공률을 감시 끔과 켬으로 나눠 보고한다.
2. 범주별 문제 사례 수를 보고한다. 적으면 유도 설정(높은 온도, 긴 맥락)으로 더 모으고, 그래도 적으면 적은 그대로 보고한다. 합성 데이터로 채우지 않는다.
3. 재라벨 부분의 범주별 Cohen's kappa를 보고하고, 0.7 미만이면 지침을 보정한다.
4. dev/test 분할과 test 해시를 기록한다.
5. 발견된 에이전트 결함을 목록으로 남기고, 고칠 것은 이 작업에서 고치거나 새 작업 문서로 올린다.
6. 보고서에 대화당 초당 평균 생성 토큰·대화 시간과 세션당 초당 평균 토큰·작업 시간·이어진 턴 수를 감시 끔과 켬으로 나눠 싣는다. 추정값으로 계산한 지표는 추정이라고 표시한다.
