## 목적
도구를 써서 실제 코딩 작업을 끝까지 수행하는 에이전트 루프를 만든다.

## 범위(In)
- agent: 시스템 프롬프트, 메시지 기록, 도구 호출, 도구 결과 전달, 반복 상한, 종료 조건.
- 도구 호출 형식은 모델 프로필로 고른다: 기본은 OpenAI `tools`/`tool_calls`, 로컬 미지원 모델은 텍스트 프로토콜 폴백, `execute`(코드 모드)는 도구 목록을 한 자리에 몰아 넣는 브리지로 둔다.
- tools(`Tool` 트레이트, 도구당 파일 하나): read_file, write_file, edit_file(정확한 문자열 교체, 일치가 하나가 아니면 이유를 담아 실패), list_dir, glob, grep, run_command.
- 작업 폴더 경계: `..`, 절대 경로, 심볼릭 링크로 작업 폴더 밖에 쓰는 것을 거부한다.
- 승인·실행은 CLI가 주입하는 승인자 인터페이스로 분리한다(이후 자동화 단계 교체 가능). 기본 승인자는 명령마다 확인한다. 승인 요청은 도구 이름이 아니라 동작 단위(명령 실행·stdin 쓰기·파일 수정·도구 호출)로 쪼개서 밝힌다. (근거: `docs/research/01-coding-agent-survey.md`)
- 셸/`run_command` 실행 deadline(기본 600초, 설정으로 변경 가능).
- 대화형 승인 응답 deadline(기본 300초, 만료 시 거부).
- 명령 중단·deadline 만료 시 프로세스 트리 종료(플랫폼별; Windows Job Object 우선).
- 도구 출력이 길면 잘라서 전달한다.
- 작은 로컬 모델에 맞춘 짧은 시스템 프롬프트를 쓴다.
- `snap run "<과제>"` 단발 실행.
- 단발 호출의 작업 명세는 사용자 원문을 보존하고 목표·입력·완료 조건만 담는다.
- 작업 명세의 완료 조건에 검증 명령이 있으면 에이전트가 끝난 뒤 그 명령을 실행해 성공 여부를 확인하고, 실패하면 실패를 드러낸다.
- 모델 선택: `run`은 `--model <이름>`으로 고른다. 지정하지 않으면 설정의 모델 목록에서 골라 실행한다. 입력을 받을 수 없으면 모델 이름 목록을 담은 오류로 끝낸다.
- 작업 폴더의 `AGENTS.md`를 읽어 프로젝트 지시로 시스템 프롬프트에 조립한다. 04 세션의 규칙 파일 사용과 같은 규칙이고, 03은 04 규칙 계층 설계에 앞서 최소 형태만 쓴다.
- 비밀 파일 차단: 파일 도구는 사용자 설정 폴더와 작업 폴더(하위 폴더 포함)의 `snap.jsonc`와 `credentials.jsonc`를 읽거나 쓰지 않고 목록·검색 결과로도 내보내지 않는다.
- 도구 호출 인자: 인자 JSON을 해석하고, 깨진 JSON은 복구를 시도하며, 실패하면 모델에 짧은 오류를 돌려준다.
- 상수 배치: 승인·실행 deadline 기본값(600초·300초)과 반복 상한 같은 상수는 상수 모듈 한곳에 모은다.
- 텍스트 배치: 화면 표시 문구·도구 결과 문구·거부 사유·승인 요청 문구 같은 사용자 노출 텍스트는 로케일 모듈(locale 폴더 구조)에 모은다. 함수에서 즉석 문자열을 만들지 않는다. 01 뼈대가 정한 `consts/`·`locale/` 자리를 따라 쓴다.

## 비범위(Out)
대화형 화면, 세션 저장, 감시.
- 자동화 단계(승인 단계 확장)·세션 동안 허용·패턴 자동 허용·무인.
- 실행 격리.
- 실행 시간 상한이 지난 명령의 백그라운드 전환과 주기 확인은 03-9에서 다룬다. 대화형 세션에서 이어지는 상태 관리는 04에서 다룬다.

## 조사
- 주제: 언어 모델용 도구 인터페이스 설계(에이전트-컴퓨터 인터페이스), 코드 편집 형식별 성공률, 작은 모델의 도구 호출 안정성.
- opencode, Codex CLI의 편집 도구와 명령 승인 설계를 참고한다.
- Pi 코딩 에이전트(Flue의 기반 하네스)의 짧은 시스템 프롬프트와 최소 도구 구성을 확인해 참고한다.

## 반영할 연구
- 도구는 최소·구조화하고 실패 시 짧은 오류를 돌려준다(SWE-agent 2405.15793).
- 도구 호출 파서는 JSON 복구와 재시도를 하고, 도구 호출 턴은 낮은 온도로 둔다(2609.07370).
- 편집은 검색-치환을 기본으로 하고, 형식별 실패율은 06에서 잰다(2604.27296).
- 셸·승인 시간 상한, 프로세스 트리 종료(Job Object), 백그라운드 전환 방식을 참고한다.

## AC
1. 모의 서버 시나리오에서 도구 호출 → 결과 전달 → 최종 답 루프가 끝까지 돈다.
2. 작업 폴더 밖 쓰기 거부, run_command 미승인 시 미실행, edit_file 다중 일치 실패를 테스트로 확인한다. 사용자 설정 폴더와 작업 폴더의 `snap.jsonc`, `credentials.jsonc` 파일을 파일 도구가 다루지 않음을 테스트로 확인한다.
3. 실제 엔드포인트로 과제 3개(파일 만들기, 수정, 테스트 실행)를 수행한 기록이 `docs/reports/03-smoke.md`에 있다.
4. 도구 호출을 지원하지 않는 모델이면 이유가 담긴 오류를 낸다. 모델을 지정하지 않으면 목록에서 고른 모델로 실행하고, 입력을 받을 수 없으면 모델 이름 목록을 담은 오류를 낸다. 설정 폴더 위치가 정해진다(테스트, 폴더 환경 정보는 주입).
5. RESEARCH.md에 조사 항목과 적용 위치가 있다. 검증 명령을 통과한다.
6. 단발 호출 작업 명세에 사용자 원문이 보존되고 목표·입력·완료 조건만 담김을 테스트로 확인한다.
7. 작업 명세의 완료 조건에 검증 명령이 있으면 에이전트가 끝난 뒤 그 명령을 실행하고, 실패하면 0이 아닌 종료 코드와 실패 이유를 낸다(모의 서버 테스트).
8. `run_command`가 deadline 만료 시 명령을 끝내지 않고 백그라운드로 옮겼다는 표시를 도구 결과로 내고, wake로 완료 결과를 받음을 확인한다. 백그라운드 명령도 프로그램 종료에 자식 프로세스가 테스트에서 남지 않음을 확인한다(플랫폼 가능 범위, 기본값 600초·설정 가능).
9. 승인 응답 deadline 만료 시 명령이 실행되지 않고 거부로 기록됨을 테스트로 확인한다(기본값 300초·설정 가능). 승인자 미주입/비대화형은 즉시 거부.
10. (완료 시 인계) 잔여 항목을 `tasks.md`의 `## 잔여` 절에 남기고, 04·05에 넘길 항목(세션 상태 관리, 규칙 계층)을 근거로 넘긴다.

## 리스크
로컬 모델의 도구 호출 품질이 낮을 수 있다. 결과를 보고하고, 텍스트 프로토콜 대안은 필요하면 별도 작업으로 기획한다.
- `run_command`로 비밀 파일을 읽는 우회는 이름 규칙으로 다 막을 수 없다. 실행 전 사용자 확인으로 막고 스모크 보고에 한계로 적는다.
- 승인 timeout과 무인 계속을 혼동하지 않는다. 만료=거부는 자동화 단계가 아니다.
