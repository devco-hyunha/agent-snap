# D41 두 파일 저장 순서는 검증 → 자격 교체 → 설정 교체 (2026-11-06)

- 상태: recorded (2026-11-06 사용자 승인)
- 요약 인덱스: [docs/DECISIONS.md](../DECISIONS.md#d41-두-파일-저장-순서는-검증--자격-교체--설정-교체)
- 이 문서가 해당 결정의 상세 정본. DECISIONS.md에는 요약과 링크만.
- 관련: [D40](D40-save-editor.md), [02-8 spec](../plans/02-client/02-8-config-save/spec.md), [작업 4](../tasks/02-8-config-save-4-atomic-save.md)

## 결정

- 결정: 두 파일을 함께 고치는 저장(이름 바꾸기·삭제)의 순서를 **검증 → 자격 교체 → 설정 교체**로 정한다.
- 검증은 자격 파일을 쓰기 전에 마친다. 02-2 검증에 걸리는 입력(이름 중복, `extra` 예약 키)은 자격 파일을 쓰기 전에 거부가 끝나 어느 파일도 바뀌지 않는다(AC 2 정본 유지).
- 자격 교체를 마친 뒤 설정 파일을 교체한다(D40 규칙 3). 설정 파일 교체 실패는 자격 파일이 이미 바뀐 상태이고, 오류가 그 상태를 밝힌다.
- AC 1 문구 보정: 교체 실패 시험은 "그 파일의 기존 내용은 그대로, 임시 파일 남지 않음"이 기준이고, 두 파일 저장에서 설정 파일만 실패한 시험은 자격 파일이 바뀐 상태를 오류가 밝히는 것이 정본이다.

## 근거

- 근거: 검증 우선은 spec의 "쓰기 전에 검증 통과" 규칙과 AC 2의 정본이다. 거부가 자격 교체 뒤에 있으면 자격 파일만 바뀐 채로 거부되어 AC 2가 깨진다. 검증→자격→설정 순서는 D40 규칙 3(자격 먼저→설정 나중)을 지키면서 검사 위치만 앞으로 옮기는 최소 변경이다.

## 다시 볼 점

- 다시 볼 점: 설정 파일 쪽 검사(이름 중복)와 자격 파일 쪽 검사(02-1 해석)가 한 파일 저장을 두 번 읽는 경로라, 필요하면 검증 한 번으로 합치는 안을 02-8 작업 5에서 검토한다.

## 구현 후 확인 메모 (2026-11-06, 02-8 작업 4~5)

- 두 번 읽기 검증을 한 번으로 합치지 않았다. 정본 순서(검증 → 자격 교체 → 설정 교체)를 유지한 채, 설정 파일 검증은 편집 결과를 메모리에 만드는 `save_config.rs`의 `prepared_rename_text`·`prepared_remove_text`에서 끝나고, 교체를 맡기는 `write_checked_text`는 검증을 다시 하지 않는다. 즉 설정 파일 저장은 검증 한 번(02-2 해석 한 번)만 거친다.
- 자격 파일 쪽 검증(02-1 해석·이름 규칙)은 자격 저장이 자기 파일을 쓰기 전에 막으므로, 거부는 자격 파일 교체가 시작하기 전에 끝난다. 따라서 어느 검증 거부도 파일을 건드리지 않는다(AC 2 정본). `config/tests/save_atomic.rs`의 `validation_failure_leaves_both_files_untouched`·`duplicate_name_rename_rejects_before_touching_files`가 이를 확인한다.
- 검증 한 번으로 합치기 검토의 결론: 두 검증은 읽는 파일이 서로 다르고(설정 파일과 자격 파일), 02-8 작업 5가 맡한 항목(오류 가리기 모음)이 아니므로 02-8에서는 그대로 둔다.
