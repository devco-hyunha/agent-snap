## 1. 용어 (고정 정의)

| 용어 | 정의 |
|------|------|
| **신뢰성 (reliability)** | 에이전트·셸·승인·네트워크 경로가 **무한 대기(Never wait forever)** 하지 않고, 명령 중단·만료 시 **프로세스 트리**가 정리되는 실행 보장. Prospero식 deadline·Job Object 정리 등. **무인(L3)과 무관**하게 M1/작업 03에서 **항상 켜짐**. |
| **자율성 (autonomy)** | `run_command` 등 위험 행동 전 **사람 확인·허용 범위**를 얼마나 자동으로 넘길지의 **단계(L1~L3)**. M1 **기본은 L1**(명령마다 확인). L2·L3는 **06 이후** 별도 기획·승인 후 설정으로 켜고 끌 수 있게 하는 **옵션** (지금 구현하지 않음). |
| **체크포인트 (checkpoint)** | 사람 간섭이 **필요하거나 권장되는 지점**. 예: 명령 실행, 작업 폴더 밖 접근, 비밀·파괴적 작업 등. **정확한 목록·설정 키는 06 이후 기획에서 확정** (본 문서는 골격만 고정). |
| **CommandApprover (가칭)** | CLI가 주입하는 **승인자 인터페이스**. L1은 매 `run_command` 전 호출; L2·L3는 동일 주입 지점에서 다른 구현으로 교체 가능하게 **03은 인터페이스만** 둠. |
| **실행 deadline** | `run_command`(및 셸) **실행 중** 시간 상한. 기본 **600초**(설정으로 변경 가능, 가칭 키 `tools.run_command_seconds`, 03-2에서 확정). 만료 시 미완료로 끝나고 **프로세스 트리 종료** 대상. |
| **승인 deadline** | 대화형 **승인 응답 대기** 시간 상한. 기본 **300초**(설정으로 변경 가능, 가칭 키 `tools.approval_wait_seconds`). 만료 시 **거부**(명령 미실행). 비대화형·승인자 미주입은 Codex식 **즉시 거부**. |
| **프로세스 트리** | 부모 셸과 그 자식·손자 프로세스 전체. 중단·실행 deadline 만료 시 **트리 전체** 종료 (Windows: Job Object 우선 검토). |
| **L1** | **명령마다 확인**(기본). Prospero식 기본 무인 **아님**. |
| **L2** | 체크포인트·세션/패턴 허용 등 **중간 자동화**. 03 **비범위**, 06 이후 기획. |
| **L3** | **무인** 옵션(허용 목록 자동 또는 승인 timeout 후 계속 등). 03 **비범위**, 06 이후 기획. **M1에서 승인 timeout 만료 ≠ L3**. |
| **실행 격리 (D9)** | AppContainer, 제한 토큰, Docker 등 **권한·범위 격리**. D9 **보류** 유지. |
| **자식 정리 (D22 신뢰성)** | Job Object 등으로 **수명·종료만** 맞추는 것. 격리와 **목적·범위가 다름**. |

## 2. 해야 한다 / 하지 않는다

### 2.1 신뢰성

**MUST**

- 셸·도구·**승인 대기**·네트워크(HTTP는 D20)에 **무한 대기를 두지 않는다** (Never wait forever).
- `run_command`에 **실행 deadline**을 둔다. 기본 **600초**, 설정으로 변경 가능(가칭 `tools.run_command_seconds`, 03-2에서 확정).
- 대화형 **승인 응답 deadline**을 둔다. 기본 **300초**, 설정으로 변경 가능(가칭 `tools.approval_wait_seconds`). 만료 시 **거부**로 처리한다.
- 명령 **중단·실행 deadline 만료** 시 **프로세스 트리 전체**를 종료한다 (플랫폼별; Windows Job Object 우선 검토).
- M1 및 **작업 03** 범위에서 위 항목을 **항상** 만족한다 (토글로 끄지 않음).

**MUST NOT**

- 승인 deadline 만료를 **L3 무인 계속**으로 해석하거나, 만료 후 명령을 **자동 실행**하지 않는다 (M1/L1).
- HTTP deadline·재시도 정책을 D20과 **어긋나게** 바꾸지 않는다 (신뢰성은 D20과 **병행**).
- Job Object **자식 정리**를 D9 **실행 격리**가 이미 적용된 것처럼 문서화하거나, AppContainer 보류를 이유로 **트리 정리·deadline**까지 미루지 않는다.

### 2.2 자율성

**MUST**

- M1 **기본**은 **L1** (`run_command` 실행 전 확인).
- 작업 **03**은 **CommandApprover(가칭) 승인자 주입**만 두어 이후 L2·L3 구현이 **같은 경계**에서 가능하게 한다.
- L2·L3·Prospero식 **기본 무인**은 **06 이후** 별도 기획·사용자 승인 없이는 구현하지 않는다.

**MUST NOT**

- M1에서 L2·L3를 **기본값**으로 켜지 않는다.
- RESEARCH·opencode allow/ask/deny·Anthropic 체크포인트 권고만 보고 **단계 정의를 03 기획 문서에서 재작성**하지 않는다 (정본은 이 문서).
- 승인 timeout 거부 후 **에이전트가 알아서 같은 명령을 재시도·무인 실행**하는 것을 L1 정책으로 두지 않는다 (L3는 별도 명시적 옵션).

### 2.3 격리 (D9와의 관계)

**MUST**

- D9 **보류** 유지: 작업 03은 작업 폴더 경계, 비밀 파일 차단, **run_command 실행 전 확인(L1)** 유지.
- Job Object를 **「자식 정리」** 용으로 쓰는 것과 AppContainer 등 **「권한 격리」** 를 **문서·구현 의도에서 분리**한다.

**MUST NOT**

- D22 신뢰성( deadline·트리 정리 )를 이유로 D9 격리 **보류를 해제**한다고 해석하지 않는다.
- 격리 후보 조사(D9 다시 볼 점)를 **L1 승인 생략** 근거로 쓰지 않는다.

## 3. 혼동 방지 표

| A (자주 혼동) | B (실제 정책) | 구분 요약 |
|---------------|---------------|-----------|
| 승인 **deadline 만료** (L1) | **L3 무인** | L1/M1: 만료 = **거부**, 명령 **미실행**. L3는 06 이후 **명시적** 무인 옵션. |
| Job Object **자식 정리** | AppContainer 등 **실행 격리** (D9) | 정리 = 수명·kill; 격리 = 권한·범위. D9 격리는 **보류**, D22 정리는 **03 신뢰성**. |
| **실행 deadline** (`run_command`) | **승인 deadline** (승인자 UI/CLI) | 실행 중 시간 상한 vs **승인 대기** 시간 상한. 만료 결과도 다름(미완료+kill vs 거부). |
| RESEARCH Prospero·자동화 **조사** | **이 문서 (D22 정본)** | RESEARCH는 출처·비교; MUST/단계/L1 기본은 **정본만**. |

## 4. 신뢰성 상세

### 4.1 Never wait forever

- **네트워크**: D20 유지 — connect **10초**, header_wait **300초**, stream_idle **120초** (여기서 숫자를 바꾸지 않음). 03에서 중복 정의하지 않음.
- **`run_command` / 셸**: 실행 **deadline** 필수. 기본 **600초** (`tools.run_command_seconds`, 03-2에서 확정).
- **승인 대기**: 대화형 응답 **deadline** 기본 **300초** (`tools.approval_wait_seconds`); 만료 시 **거부**. 비대화형·승인자 없음 → **즉시 거부** (Codex식).

### 4.2 프로세스 트리

- 사용자·에이전트가 중단하거나 **실행 deadline**이 지나면, 플랫폼이 허용하는 범위에서 **자식 포함** 종료.
- Windows: **Job Object** 우선 검토 (D9 격리 후보와 **별개**로 「정리」 목적).
- AC8(03): deadline 만료 시 미완료, 테스트에서 **자식 프로세스 잔존 없음** (플랫폼 가능 범위).

### 4.3 timeout → 백그라운드 (후보)

- Prospero: 셸 timeout 후 **비동기 백그라운드** + 주기 wake.
- snap: **03-4 후보**. 범위가 AC를 비대하게 하면 **03 이후 별도 세부 작업**으로 분리 (DECISIONS·03 리스크와 동일).
- **분리 조건**: 03-2·03-3(승인·실행 deadline, 트리 종료) **선행**; 백그라운드 전환은 **신뢰성 보완**이지 L3 무인 **아님**.

### 4.4 M1/03에서 항상 켜짐

- 신뢰성 항목은 **설정으로 끄는 옵션을 M1에 두지 않음** (자율성 L2/L3와 대비).

## 5. 자율성 상세

### 5.1 단계 골격

| 단계 | 의미 | M1/03 |
|------|------|--------|
| **L1** | **명령마다 확인** (기본) | **구현 대상** — 기본 승인자 동작 |
| **L2** | 체크포인트·세션/패턴 허용 | **비범위** — 06 이후 기획 |
| **L3** | 무인(허용 목록 자동, 또는 승인 timeout 후 **계속** 등) | **비범위** — 06 이후 기획; **기본값 아님** |

### 5.2 체크포인트 (예시, 목록 미확정)

- 명령 실행 (`run_command`)
- 작업 폴더 밖 읽기/쓰기
- 비밀·파괴적 작업
- RESEARCH 「문 유형·자율성」 및 Anthropic 체크포인트 권고와 **정렬 가능**하나, **허용 목록·키 이름은 06 이후** 확정.

### 5.3 작업 03의 역할

- **승인자 주입** (`CommandApprover` 가칭)만 구현.
- L1 기본 승인자: 매 `run_command` 전 확인.
- L2·L3 승인자 구현·설정 UI/키: **06 이후** 별도 기획·승인.

### 5.4 근거 방향 (정책 변경 없음)

- Prospero: deadline·프로세스 트리는 **무인과 무관한 신뢰성**.
- 무인 토글만 있으면 **거칠고**, 체크포인트만 있으면 **무인 옵션이 빠짐** → **자동화 단계 + 체크포인트** 골격 (RESEARCH 자동화 검토 절과 동일 방향).
- 경량 목표(D9)와 맞추기 위해 **L2·L3 구현은 미룸**.

## 8. 다시 볼 점

- 실행 deadline 기본 **600초**·승인 deadline 기본 **300초**가 실사용(작업 **06**)에서 짧거나 길면 **설정 기본값만** 재검토한다(무한 대기 금지·만료 시 kill/거부 등 **정책 구조는 유지**).
- L2/L3의 **정확한 허용 목록·체크포인트 목록·설정 키 이름**은 **06 이후 기획**에서 정한다.
- timeout → 백그라운드가 **03 AC**를 비대하게 하면 **별도 세부 작업**으로 분리한다.
- Job Object **Home 에디션·Rust 바인딩 라이선스**(D9 다시 볼 점)는 **03-3 구현 전**에 확인한다.
- 승인 timeout과 「무인 계속」**혼동** — M1은 만료 = **거부** 후 해당 도구 결과만 모델에 전달; **L3 아님** (03 리스크와 동일).
