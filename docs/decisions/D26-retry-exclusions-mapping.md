## 결정

- 결정: 02-4 재시도 판단의 비대상·경계·입력 매핑을 다음과 같이 정한다.
  - OpenRouter **402**(크레딧 부족·in-flight 등)는 **재시도하지 않는다**. Out과 결정에 명시한다. `Retry-After`가 있어도 재시도 후보가 아니다.
  - AC 경계: `Retry-After` 0·과거 HTTP 날짜 → 대기 0초. 음수·해석 불가 → 헤더 없음(백오프). 헤더 대기 초과 → 비재시도. 목록 밖 5xx(500/502/503/504 외)·408·425·그 밖의 4xx(429 제외) → 즉시 포기.
  - [02-5](../plans/02-client/02-5-transport/spec.md) 오류 → 02-4 입력 매핑 표를 spec에 고정한다. 실제 호출·적용은 02-6이고, 02-4는 입력 종류만 정의한다.
    - 재시도 후보: DNS 실패, 연결 거부, 연결 시간 초과, 헤더 전 연결 재설정, TLS, 프록시(`PreHeaderConnectKind` 전부).
    - 비재시도 입력: 헤더 대기 시간 초과.
    - 02-5 오류 표에 TLS·프록시 행을 두고, 모두 **헤더 전 연결 오류** 후보로 매핑한다.
  - POST chat completions는 공급자 멱등 키 없이 **일시 오류만** 재시도한다(적용은 02-6).
  - 판정 우선순위: 횟수 초과를 `Retry-After` 상한 초과보다 **먼저** 본다. 동시에 해당하면 포기 이유는 횟수 초과다.

## 근거

- 근거: 잔액·예산·크레딧은 사용자 조치가 필요하고, in-flight 예외만 따로 두는 것은 YAGNI로 보류한다. 경계 AC를 쪼개 두면 단위 테스트로 확인하기 쉽다. 02-5와 02-4의 입력 이름을 표로 고정하면 02-6이 매핑을 임의로 바꾸지 못한다. 횟수 상한이 먼저면 긴 `Retry-After`와 겹칠 때 대기 초만으로 포기하는 모호함을 줄인다.

## 다시 볼 점

- 다시 볼 점: OpenRouter in-flight 402를 짧은 대기 후 재시도하는 예외가 실사용에서 필요해지면 다시 본다. POST 재시도로 과금이 중복될 여지가 남으면 공급자 멱등 키나 재시도 범위를 다시 본다. 헤더 대기 초과 재시도가 필요하면 D14와 함께 재검토한다.
