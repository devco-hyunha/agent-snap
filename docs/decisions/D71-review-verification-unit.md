## 결정

- 결정 1 (확인 단위 표): 리뷰에서 확인할 항목을 아래 표로 고정한다. 표에 없는 단위를 확인하는 건 금지한다(표가 곧 지정 단위 목록이다).

| 확인 단위 | 무엇을 확인하는가 | 측정 방법 |
|---|---|---|
| 파일 실재 | 작업 문서가 지정한 산출물 파일이 실제로 있는지 | 경로 목록과 크기 확인 |
| 변경 범위 | 작업 문서에 적힌 파일만 바뀌었는지 (범위 밖 파일 0건) | `git status --porcelain` |
| 이동 정의 | 코드·주석·테스트·모듈 연결을 옮긴 파일에서 그 항목이 1개로 줄었는지 | 이동 심볼을 파일 하나에 적어 `rg -l <심볼> crates`로 실행 파일 1개 확인 |
| 게이트 3종 | `cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test` 종료 코드 0 | 로그에 남인 세 명령의 종료 코드 |
| 대상 SHA256 | 검증한 파일의 해시 목록 | 로그에 남인 파일 해시 |
| 시험 수 | `#[test]` 개수가 표에 적힌 개수와 같은지 | 로그에 남인 개수 |
| 주석·문서 이동 잔여 | 옮긴 코드·문서에 남은 설명(파일:줄, 파일)이 없는지 | 아래 결정 4의 전수 확인 절차 |

- 결정 2 (측정 절차): 라운드가 끝날 때마다 위 표를 순서대로 확인하고, 결과를 로그 파일에 남긴다. 로그에 없는 항목 측정은 미측정으로 본다.
- 결정 3 (정합 항목 목록): "확인 항목을 새로 정할 때"는 항목을 열거하지 않고 아래 목록을 기준으로 삼는다. 목록에 없는 항목을 확인 대상으로 새로 만들지 않는다.
  - 정합 항목 목록 = 위 표 7줄 + review-harness 체크리스트 7항목
  - 지정 단위 목록 지시: 리뷰 위임 프롬프트에는 확인 단위를 직접 적지 않고 이 문서 경로를 넣는다.
  - 미기록 시 major: 표에 있고 이번 리뷰에서 확인하지 않은 단위는 major로 본다.
- 결정 4 (전수 확인 정론): 이동 잔여를 확인할 때는 목록을 사람이 열거하지 않고 grep으로 전수 확인한다. 절차: (1) 이번 라운드 변경 목록(`git status --porcelain`)에서 코드·주석·테스트를 옮긴 파일을 고른다. (2) 그 파일에서 옮긴 항목을 하나만 찾는다(주석이면 그 자리에서 옮겨진 글자). (3) `rg -l <찾은 글자> crates`로 실행 파일 1개를 확인한다. (4) 1개 아니면 잔여로 본다. 이동 심볼 30종처럼 목록을 직접 만들어 돌리는 grep 절차는 쓰지 않는다.
- 결정 5 (정합 목록 정론): 정합 항목 목록과 전수 확인 정론은 이 문서가 정본이고, 스킬·개발 규칙에는 이 문서 경로만 짧게 넣는다. 정론에 없는 규칙을 개발 규칙·스킬에 새로 만들지 않는다.
- 결정 6 (판정 규칙): 미측정·미기록 항목은 major로 본다. critical은 없다. 미달 판정 뒤 같은 지적의 보정이 2번 끝나도 미달이면 멈추고 보고한다(하네스 5절 2번). 하네스 9절의 재리뷰 범위 규칙은 그대로 두고, 확인 단위 표만 더한다.

## 측정 절차 (라운드마다 순서)

1. 변경 파일 목록을 확인한다(위 표 2번째 줄).
2. 게이트 3종을 라운드마다 실행하고 로그에 남긴다.
3. 산출물 파일을 실재 확인한다.
4. 코드·주석·테스트·모듈 연결의 이동 잔여를 전수 확인한다(결정 4).
5. 결과를 라운드 로그에 표 순서대로 남긴다.

## 근거 (03-6 라운드 사례)

- 03-6 T5 통합 리뷰 1차에서 minor 4건 중 2건이 라운드 리뷰에서 안 잡히고 통합 리뷰에서 발견됐다: 주석 잔여 `crates/snap-core/src/civil_date.rs:3`(원위치에 남은 설명 1건), `crates/snap-core/src/llm/transport/fetch_models.rs:6`(원위치에 남은 설명 1건). 라운드 리뷰가 주석 잔여 확인 단위를 표에 두지 않아서 생긴 문제다.
- 같은 지적이 R2·R3·R4에서 반복됐다. 이동 정의 30종 목록을 메인이 열거할 때만 greps가 돌았고, 라운드 리뷰에는 greps가 안 돌았다. 라운드마다 도는 확인 절차가 아니라 목록 열거에 기대는 절차가 문제의 원인이다.
- R2, R3, R4에서 반복된 라운드 리뷰는 같은 지적을 피하기 위해 그 라운드 미달 항목과 그 라운드 파일만 봤다. 주석 잔여는 이동 단위 전체를 grep으로 봐야 잡힌다.
- 03-6 T5 R5 하네스 라운드에서 게이트 3종 로그 `.local/logs/gate03_06_t5_R5_harness.log`에 대상 9개 파일 SHA256을 남긴 것을 확인 단위 측정 기록의 기준으로 삼는다.

## 다시 볼 점

- 확인 단위 표에 새 줄이 필요한지는 라운드 로그 미측정 항목이 나올 때마다 본다.
- 전수 확인 grep이 못 잡는 형태(주석 글자가 짧은 경우)가 나오면 측정 방법을 조정한다.
- 정합 항목 목록에 없는 항목을 확인해야 하는 요청이 오면 정합 목록 정론(결정 5)을 먼저 지키고, 목록을 넓히는 건 이 문서를 고친다.
