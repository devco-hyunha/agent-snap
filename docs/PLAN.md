# agent-snap 기획 개요

- 상태: approved (2026-10-28 사용자 승인)
- 작성일: 2026-10-28 (2차: 에이전트 우선으로 재구성)

## 목표

판정 모델을 얹은, 로컬 LLM용 독립 코딩 에이전트를 만든다(CLI 먼저, 이후 앱). 순서는 다음과 같다.

1. 혼자서 실제 코딩 작업을 해내는 에이전트를 만든다.
2. 그 스트림 경로에 감시·교정 지점을 둔다.
3. 마지막에 CPU에서 도는 1GB 이하 판정 모델을 얹는다.

판정 모델만 검토하는 프로젝트가 아니다.

## 이전 시도에서 얻은 교훈

이전 Snap 폴더의 코드와 문서는 참조하지 않는다. 교훈만 반영한다.

- 에이전트 바탕 없이 판정 모델을 더미 데이터로만 검토하다가 한도를 썼다.
  - 에이전트가 먼저다.
  - 판정은 실제 에이전트 세션 출력으로만 평가한다.
  - 모의 서버는 동작 테스트에만 쓴다.
- 논문을 조사하라고 했지만 적용된 것이 하나도 없었다.
  - 작업마다 조사 결과를 `docs/RESEARCH.md`에 남긴다.
  - 적용 위치나 미적용 이유를 AC로 확인한다.
- 개발 규칙 없이 한 파일에 몰아넣었다. 개발 규칙을 작업 01에서 정하고, 검사 스크립트와 리뷰로 확인한다.
- 측정하지 않은 수치를 확정처럼 썼다. 측정 전 수치는 "잠정"으로 표시한다.

## 사용자 답변으로 확정된 전제

- 판정 모델은 CPU에서 돌린다.
- 모델 엔드포인트는 OpenAI 호환 방식으로 다루고, 엔드포인트 목록과 모델 목록으로 설정한다(2026-10-28 변경). 로컬, LAN, 원격을 구분하지 않는다.
- 앱은 Tauri + SolidJS로 가볍게 만든다(이번 기획 범위 밖).
- Hugging Face 모델은 용량과 라이선스 목록을 사용자가 승인한 뒤에 받는다.

## 결정 (작업 01에서 docs/DECISIONS.md로 옮김)

- 백엔드는 Rust로 한다.
  - 근거: rustc 1.99.1과 MSVC Build Tools가 설치되어 있다. Tauri 백엔드가 Rust라서 앱이 코어 크레이트를 그대로 쓴다. 실행 파일 하나로 배포된다.
  - 다시 볼 점: 판정 모델 런타임의 Windows 빌드가 막히면 다시 검토한다.
- 대상 언어는 기본 한국어이고 설정으로 바꾼다.
- 설정 파일 `agent-snap.jsonc`(엔드포인트 목록과 모델 목록, 주석 허용 JSON)는 git에서 제외한다. 키는 설정 파일과 별도로 사용자 설정 폴더(Windows `%APPDATA%\agent-snap\`)의 자격 파일 `credentials.jsonc`의 `api_keys`에서 엔드포인트 이름으로 읽고, 없으면 키 없이 요청한다. 설정 파일 엔드포인트에 `api_key`가 있으면 거부한다. 예시 파일에는 자리표시자만 둔다. 세션 로그에는 base_url과 키를 남기지 않는다.
- AGENTS.md의 마커 블록은 템플릿 원문 그대로 둔다. 이 PC의 하네스 경로 차이는 마커 밖에 적는다.
- 기존 에이전트를 포크하지 않고 새로 짠다.
  - opencode(MIT), Codex CLI(Apache-2.0), Hermes Agent(MIT)의 설계는 참고한다. 코드를 가져오면 출처와 라이선스를 표기한다.
  - Claude Code와 Cursor는 동작만 참고한다.
- 에이전트(M1)를 먼저 만들고 판정 모델(M2)은 나중에 얹는다. 판정 평가는 M1이 실제 과제를 수행한 뒤에 그 세션 출력으로만 한다.

## 사용자가 해 주셔야 할 설정

1. 이 PC에서 닿는 OpenAI 호환 서버를 준비한다.
2. `agent-snap.jsonc`에 엔드포인트(`name`, `base_url`, 서버 종류 `kind`)와 모델(id, 쓸 엔드포인트)을 적는다.
3. 설정 파일 `agent-snap.jsonc`와 자격 파일 `credentials.jsonc`는 같은 사용자 설정 폴더(Windows `%APPDATA%\agent-snap\`)에 둔다. 키가 필요한 서버라면 키를 `credentials.jsonc`의 `api_keys` 아래에 엔드포인트 이름으로 적는다.
4. 작업 07이 끝나면 판정 모델 후보 목록을 승인한다.

도메인, 터널, 계정, 확장 프로그램은 필요 없다.

## 동작 기준과 측정 환경

- 동작 기준은 GPU 없는 저사양 PC이고, 로컬 LLM은 외부 PC에 둔다.
- 측정 환경은 둘로 구분해 적는다: 노트북(VRAM 4GB, RAM 16GB), 원격 테스트 PC(RTX 3060 12GB, RAM 16GB).
- 최소 사양 수치는 측정 전이라 정하지 않는다. M2에서 측정한 뒤 정한다.

## 잠정 목표 수치 (M2에서 사용)

수치를 바꾸는 것은 제품 결과 변경이므로 사용자 확인을 받는다.

| 항목 | 목표 |
|---|---|
| 언어 혼합 | 재현율 ≥ 0.95, 오탐률 ≤ 1% |
| 언어 이탈 | 재현율 ≥ 0.90, 오탐률 ≤ 3% |
| ailoop | 재현율 ≥ 0.90, 오탐률 ≤ 2% |
| 판정 CPU 지연 | 판정 창 하나당 p95 ≤ 100ms |
| 판정 모델 | 파일 ≤ 1GB, 실행 메모리 ≤ 1.5GB |
| 교정 효과 | 최종 출력 문제 발생률 상대 80% 이상 감소 |
| 교정 비용 | 추가 토큰 ≤ 30%, 과제 성공률 하락 없음 |

## 공통 규칙

- 작업마다 먼저 관련 논문과 자료를 조사한다. 링크를 열어 실제로 있는지 확인한 뒤 `docs/RESEARCH.md`에 기록한다. 적용 위치(파일, 함수) 또는 미적용 이유를 남긴다.
- 작업마다 개발 규칙(AGENTS.md)을 지키고 검증 명령(`cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`)을 통과해야 한다.
- DoD: AC 충족, 검증 통과, 리뷰 PASS. 리뷰 PASS 후 자동으로 커밋하고, 푸시와 병합은 허락을 받는다.
- 문서에는 테스트 개수 같은 변하는 수치나 절대 경로를 적지 않는다.
