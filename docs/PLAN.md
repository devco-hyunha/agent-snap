# snap 기획 개요

- 상태: 진행 (2026-11-23 01 기반 완료. 02부터 계획 순서로 착수)
- 기획 승인 전에는 구현 코드를 쓰지 않습니다. 이 문서는 뼈대이고, 각 항목 채팅은 사용자 승인 뒤에 채웁니다.

## 목표

로컬 LLM용 독립 코딩 에이전트를 만든다. 순서는 다음과 같다.

1. 혼자서 실제 코딩 작업을 해내는 에이전트를 만든다.
2. 그 스트림 경로에 감시·교정 지점을 둔다.
3. 마지막에 CPU에서 도는 1GB 이하 판정 모델을 얹는다.

판정 모델만 검토하는 프로젝트가 아니다.

## 전제

- 판정 모델은 CPU에서 돌린다.
- 모델 엔드포인트는 OpenAI 호환 방식으로 다루고, 엔드포인트 목록과 모델 목록으로 설정한다. 로컬, LAN, 원격을 구분하지 않는다.
- 백엔드는 Rust로 한다.
- 대상 언어는 기본 한국어이고 설정으로 바꾼다.
- 설정 파일 `snap.jsonc`와 자격 파일 `credentials.jsonc`는 git에서 제외한다. 키는 사용자 설정 폴더의 자격 파일에서만 읽고 설정 파일에 키를 넣지 않는다.
- 에이전트(M1)를 먼저 만들고 판정 모델(M2)은 나중에 얹는다.
- 최소 사양·측정 수치는 측정 전에는 "잠정"으로 표시한다.

## 공통 규칙

- 작업마다 먼저 관련 논문과 자료를 조사한다. 링크를 열어 확인한 뒤 `docs/RESEARCH.md`에 기록하고 적용 위치 또는 미적용 이유를 남긴다.
- 작업마다 개발 규칙(AGENTS.md, harness/PROJECT_RULES.md)을 지키고 검사 명령(`cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`)을 통과한다.
- DoD: AC 충족, 검증 통과, 리뷰 PASS. 커밋은 작업 단위 리뷰 PASS 보고 뒤에 사용자 허락으로 한다.
- 문서에는 변하는 수치(시험 개수 등)나 절대 경로를 적지 않는다.
