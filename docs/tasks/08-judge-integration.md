# 08 판정 모델 통합과 평가

- 상태: planned

## 목적
승인된 후보를 `Monitor` 구현으로 에이전트에 얹고, 작업 06의 dev 세션 출력으로 평가해 선정한다.

## 범위(In)
- 승인 목록만 `models/`(git 제외)에 받는다. 실행은 CPU로 고정한다.
- 후보마다 먼저 알려진 예시 몇 개로 호출 방식이 맞는지 확인한 뒤 본 평가를 한다.
- 생성형 판정기의 질문 문장은 dev에서만 고르고 고정한다.
- `agent-snap judge-eval`: 저장된 세션 청크를 재생해 판정을 흉내 낸다.
- 보고서 `docs/reports/08-judge.md`: 범주별 정밀도, 재현율, 오탐률, 감지 지연, CPU p50/p95, 최대 메모리. 말만 바꾼 반복은 따로 낸다. 규칙 감시기와 비교한다.

## 반영할 연구
- 판정기는 자기 일관성이 아니라 독립 라벨과의 일치로만 평가한다(2609.13824).

## AC
1. 후보와 규칙 기준선의 지표 표가 있고, GPU를 쓰지 않았음을 로그로 보인다.
2. 선정안의 dev 결과를 잠정 목표 대비로 적는다. 미달이면 미달로 보고하고 목표를 낮추지 않는다.
3. 선정 모델이 에이전트에 통합되어 설정으로 켜고 끌 수 있다.
4. test 분할을 읽으려 하면 오류가 난다(테스트).
5. RESEARCH.md에 조사 항목과 적용 위치가 있다. `scripts/check.sh`를 통과한다.

## 리스크
모델이 규칙보다 못하면 결과를 그대로 보고하고, 모델을 뺄지는 사용자에게 묻는다(제품 결과 변경).

## DoD
AC 충족, 검증 통과, 리뷰 PASS.
