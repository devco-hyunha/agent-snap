# 05 감시 지점, 규칙 감시, 교정 루프

- 상태: planned

## 목적
에이전트의 스트림 경로에 감시·교정 지점을 만든다. 규칙 기반 감시기로 먼저 동작시킨다. 판정 모델은 작업 08에서 같은 지점에 얹는다.

## 범위(In)
- monitor: `Monitor` 트레이트(청크를 받아 감지 결과를 돌려준다). content와 reasoning을 모두 본다. 화면 출력을 막지 않게 별도 태스크로 돈다.
- 규칙 감시기(코드 블록, 인라인 코드, 경로는 제외)
  - 언어 혼합: 대상 언어 문장 안의 한자·가나.
  - 언어 이탈: 서술 문장의 문자 체계 비율.
  - 글자 반복: 정규화한 n-gram이나 접미 반복.
  - 도구 호출 반복: 같은 도구를 같은 인자로 연달아 부르는 경우(스텝 단위).
- 교정 루프: 감지 → 스트림 중단 → 전략 적용 → 재시도 상한
  - 깨끗한 지점까지 잘라 교정 지시를 붙여 이어 쓰기
  - 교정 지시를 붙여 다시 생성하기
  - 샘플링 조정(온도, frequency/presence penalty)
  - 반복 지적 메시지 넣기
- 범주별 전략과 감시기 켜기·끄기는 설정으로 한다. 감지·교정 이벤트는 세션 로그에 남긴다.

## 비범위(Out)
판정 모델, 효과 평가(작업 06, 09).

## 조사
- 주제: LLM 언어 혼동(language confusion)의 원인과 완화, 반복·퇴화 생성의 탐지와 디코딩 대책.
- 참고 설계: Project Think의 턴·스텝 훅(`beforeTurn`, `beforeToolCall`, `afterToolCall`, `onStepFinish`). 스트림 감시를 보완하는 스텝 단위 감시 지점으로 쓴다.

## 반영할 연구
- 언어 혼합·이탈은 줄 단위 언어 일치율로 잰다. 교정 1순위는 온도 낮추기, 서버가 지원하면 `logit_bias`(2406.20052, 2606.08994).
- 서버가 지원하면 DRY 샘플러 설정을 넘기는 옵션을 두고, DRY가 놓치는 짧은 구분자 반복과 코드·JSON 반복은 자체 감지기로 따로 본다(2608.22761, 2610.24715, 2505.10402).
- 스텝 감시와 "마지막 안전 지점으로 되돌려 재생성" 교정 구조를 쓴다(2608.02464).
- 추론 반복에는 사고 예산 상한을 두고, 반복 시 온도를 올려 재생성하는 전략을 후보로 둔다. 반복 점수 누적합(CUSUM)을 감지 신호 후보로 둔다(2512.12895, 2601.05693).
- 추론 조기 중단(DEER, EAT)은 logprobs 지원과 비용을 확인한 뒤 검토한다.

## AC
1. 감시기마다 양성·음성 단위 테스트가 있고, 코드 블록 안의 한자·영어는 감지하지 않는다.
2. 모의 서버로 감지 → 중단 → 교정 → 재생성 흐름과 재시도 상한을 확인한다.
3. 감시가 스트림 표시를 막지 않음을 측정값으로 보인다.
4. 판정 모델이 같은 트레이트로 들어올 수 있게 인터페이스 문서 주석이 있다.
5. RESEARCH.md에 조사 항목과 적용 위치가 있다. `scripts/check.sh`를 통과한다.
