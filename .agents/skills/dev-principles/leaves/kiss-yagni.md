# 4. KISS와 YAGNI

- 정의: 지금 필요한 만큼만 단순하게 만든다.
- 기준: 요청되지 않은 추상화(불필요한 인터페이스 계층, 팩토리, 플러그인 레지스트리, 미래 대비 설정 옵션)는 만들지 않는다. **단, YAGNI와 KISS는 '쓰지 않는 미래 기능·과잉 추상화'를 막는 원칙이지, 요청된 작업·검증·에러 처리를 생략하거나 SRP(책임별 파일·함수 분리)나 모듈화를 거부하는 핑계가 아니다.** 사용처가 하나뿐이더라도 책임이 다르면 별도 함수·별도 파일로 분리한다(충돌 시 SRP가 우선한다). 「한곳」정본·「한 파일」해석 금지는 `leaves/solid.md`.
- 위반: 사용처가 하나뿐인데 팩토리, 플러그인 레지스트리, 설정 옵션을 미리 만든다. 반대로, **YAGNI·KISS를 이유로 들어 서로 다른 책임의 코드와 함수들을 한 파일·한 함수에 뭉뚱그려 넣는다(SRP 회피 금지).**
