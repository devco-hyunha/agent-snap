# review-harness (리뷰)

결론: 독립 리뷰 세션 1회가 확인과 리뷰를 함께 한다. 별도의 확인 전용 서브는 없다.

## 원칙
- 리뷰는 구현 세션과 분리된 새 세션에서 한다. 구현 맥락이 없는 새 읽기 전용 서브를 뜻한다. 서브가 없는 도구는 새 대화다.
- 메인은 포인터 샌드위치 프롬프트(작업 문서 경로·작업 번호·dev-principles 경로·직전 지적)를 보낸다. 템플릿은 delegation-brief다. 리뷰어는 이 스킬의 체크리스트 7항목과 하네스 문서 7절 판정 기준을 직접 읽고, 검증 명령은 작업 문서에서 찾는다.
- 리뷰어는 파일을 수정하지 않는다. 문제만 기록한다.
- 서브의 보고를 믿지 않는다. 검증 명령을 직접 다시 실행하고, 산출물이 실제로 있는지 확인한 뒤 체크리스트를 본다.
- 리뷰 대상은 작업 단위다. 표준 작업은 크기로 나누지 않는다.
- 소규모 Fast-track(단일 파일·20줄 이하 단순 수정 또는 하네스 설치·업데이트 동기화, 보안·비가역 제외)은 메인이 직접 수행하고 인라인 검증과 셀프 체크로 확인한다. 별도 리뷰 세션은 열지 않는다(하네스 문서 9절).

## 체크리스트
1. 작업 문서의 AC(인수 조건) 충족 여부
2. 금지 사항 위반 여부 (작업 문서의 금지 사항 섹션 기준)
3. 검증 명령 직접 재실행 결과·산출물 실재·로그 근거
4. 에러 처리·보안 기본·함수 중복(DRY) 확인 (dev-principles 기준)
5. 문서 동기화 여부, 코드 주석·문서의 사용자 언어 순수성(한자·외국어·U+FFFD 0건)과 eli5-clarity 준수(주석은 의도·이유만, 결론 먼저)
6. 범위 밖 변경 여부
7. 제품 소스에 테스트 본문 동거 없음 · 한 파일에 제품 책임이 둘 이상 섞이지 않음 (dev-principles)

신규 동거·책임 혼재 확대는 major, 레거시만이면 minor+이전(또는 후속 분리) 메모.

## 산출물
- 보고 형식(delegation-brief): 결과 1줄 / 불릿 ≤5 / 경로 / 다음 1줄. 서론 금지.
- 문제 목록: 파일:라인, 심각도(critical / major / minor), 내용.
- 판정: PASS 또는 미달. 판정은 리뷰 세션이 한다. 기준은 하네스 문서 7절이다.

## 리뷰 범위 규칙
1. 재리뷰 범위는 하네스 문서 9절을 따른다.
2. 재리뷰 프롬프트에 직전 리뷰의 통과 항목 목록, 미달 항목과 지적 목록(파일:라인, 심각도), 바뀐 파일 목록을 넣는다.

프로젝트 규칙 우선은 하네스 문서 1절을 따른다. 승인·안전 규칙은 하네스 문서 5절을 따른다. (하네스 문서: harness/HARNESS.md)
