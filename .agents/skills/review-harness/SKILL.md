# review-harness (리뷰)

결론: 독립 리뷰 세션 1회가 확인과 리뷰를 함께 한다. 별도의 확인 전용 서브는 없다.

## 원칙
- 리뷰는 구현 세션과 분리된 새 세션에서 한다. 구현 맥락이 없는 새 읽기 전용 서브를 뜻한다. 서브가 없는 도구는 새 대화다.
- 메인은 서브 호출 전 delegation-brief를 읽고 개발 하네스(가드레일·자기점검(목록) + harness/HARNESS.md·AGENTS.md·오버레이·dev-principles 색인·해당 플레이북 경로·지정 잎)을 포함한 포인터 샌드위치 프롬프트(500자 이하)를 보낸다. 리뷰어는 전달받은 가드레일과 규칙 문서(harness/HARNESS.md·AGENTS.md·오버레이·dev-principles 색인·해당 플레이북)를 먼저 읽고, 플레이북 호출 표의 지정 잎만 추가 Read한다. 이 스킬의 체크리스트 7항목과 하네스 문서 7절 판정 기준을 직접 읽으며 검증 명령은 작업 문서에서 찾는다.
- 리뷰어는 파일을 수정하지 않는다. 문제만 기록한다.
- 서브의 보고를 믿지 않는다. 검증 명령을 직접 다시 실행하고, 산출물이 실제로 있는지 확인한 뒤 체크리스트를 본다.
- 리뷰 대상은 작업 단위다. 표준 작업은 크기로 나누지 않는다.
- 소규모 Fast-track(단일 파일·20줄 이하 단순 수정 또는 하네스 설치·업데이트 동기화, 보안·비가역 제외)은 메인이 직접 수행하고 인라인 검증과 셀프 체크로 확인한다. 별도 리뷰 세션은 열지 않는다(하네스 문서 9절).
- 질문 포인터: 배치로 이어서·개수로 끝 아님·선택지 무제한·답 후 즉시 구현 금지(plan-harness·하네스 1절).

## 주석만 변경 분기
- In: 주석·독스트링만, 실행·시그니처·설정·런타임 문자열·동작 불변. Out: 로직·API·런타임 문자열·절차 변경 → 기존 7대. `.md`만은 문서 연쇄+문서·언어 리뷰(주석만 아님).
- 체크: 동작 불변 diff, 언어·eli5, 문서 연쇄·반영 목록, 금지 표현. 개발 코드/API 항목은 적용하지 않는다.
- PASS: Fast-track이면 메인 셀프, 아니면 이 세션. 리뷰 없이 PASS 금지(원칙 5).

## 체크리스트
1. 작업 문서의 AC(인수 조건) 충족 여부
2. 금지 사항 위반 여부(작업 문서의 금지 사항 섹션 기준) 및 파일 삭제가 있는 경우 해당 파일·삭제 이유·근거 설명 여부
3. 검증 명령 직접 재실행 결과·산출물 실재·로그 근거
4. 플레이북 지정 잎 준수·확인(지정 잎 목록 + 각 1줄. 기존 함수 검색·재사용, 폴더 내 역할별 파일 분리 포함). 「전 항목」거짓 보고 금지
5. 문서 연쇄(연결 검색→추가·수정·삭제 또는 즉시 후속 완료)·반영 목록·코드 주석·문서의 사용자 언어 순수성(한자·외국어·U+FFFD 0건)과 eli5-clarity 준수(주석은 쉬운 명사형 한 줄·선택 둘째 줄). 한쪽만·후속 미완이면 미달
6. 범위 밖 변경 여부
7. 제품 소스에 시험 본문 동거 없음(분리 예외 없음)·변경·신규 책임마다 시험 전용 트리의 책임용 시험·통합·간접만으로 testing PASS 금지 · 한곳=폴더 응집(≠한 파일)·역할별 파일 분리(YAGNI·KISS·「단일 사용처라 한 파일」핑계로 SRP 회피 금지) · 시험 전용 파일도 SRP 검토 대상(「시험 파일이라 대상 아님」 PASS 금지·혼재·비대=major) · 플랫폼 분기(cfg 등) 한 파일 동거=major, 잎 solid·testing·dry·kiss-yagni·separation·naming

신규 동거=major. 변경 책임에 책임용 시험 없이 간접만=major. 「단일 사용처라 한 파일」핑계의 신규 동거·책임 혼재 확대는 major. 플랫폼 분기 한 파일 동거=major. 레거시만이면 minor+이전(또는 후속 분리) 메모. 상수·사람 문구 분리(`constants-locale`): 권고 미준수=minor, locale 사용 중 사람 문구를 로직에 그대로 둠=major.

## 산출물
- 보고 형식(delegation-brief): 결과 1줄 / 불릿 ≤5 / 경로 / 다음 1줄. 서론 금지. 문서 반영 목록 포함.
- 문제 목록: 파일:라인(그 시점 스냅샷·보정으로 줄이 밀려도 숫자 갱신 금지), 심각도(critical / major / minor), 내용.
- 판정: PASS 또는 미달(미달(minor) 포함). 지적 0건만 PASS. 판정은 리뷰 세션이 한다. 기준은 하네스 문서 7절이다. 줄 번호만 다르고 경로+내용(원문/식별자)이 같으면 동일 지적. 줄 불일치만으로 미달 금지.

## 리뷰 범위 규칙
1. 재리뷰 범위는 하네스 문서 9절을 따른다. 직전 통과 항목은 다시 보지 않는다.
2. 재리뷰 프롬프트에 직전 미달 항목·지적 목록(파일:라인 스냅샷, 심각도)과 바뀐 파일 목록을 넣는다. 통과 항목은 넣지 않거나 참고용만 둔다. 동일 지적은 경로+내용으로 본다.

프로젝트 규칙 우선은 하네스 문서 1절을 따른다. 승인·안전 규칙은 하네스 문서 5절을 따른다. (하네스 문서: harness/HARNESS.md)
