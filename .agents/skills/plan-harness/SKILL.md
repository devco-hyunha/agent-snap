# plan-harness (기획)

## 절차
1. 프로젝트 규칙 문서(AGENTS.md, CLAUDE.md, docs/INDEX.md 등)가 있는지 서브에이전트에 확인을 맡기고, 결과를 받아 규칙을 반영한다.
2. 요구 수렴: 결론을 바꾸는 질문만 최대 3개 한다. 나머지는 가정으로 적고 진행한다.
3. 작업 문서를 쓴다(메인이 내용을 정하고 서브에이전트가 기록). 프로젝트에 정해진 위치가 있으면 그곳을 따르고, 없으면 `docs/tasks/<순번>-<작업명>.md`.
4. 작업을 나눌 때는 각 작업에 DoD(완료 정의: AC 충족, 검증 통과, 리뷰 PASS를 모두 만족한 상태)를 부여한다.
5. 기획 승인 전에는 코드를 쓰지 않는다.

## 기획용 작업 문서 필드
위임용 작업 문서(delegation-brief)와 다른 문서이며, 위임용 문서의 바탕이 된다.
- 목적
- 범위(In)
- 비범위(Out)
- 설계 요약
- AC(인수 조건): 체크 가능한 조건 3~7개. Given/When/Then 또는 EARS 형식.
- 테스트 계획
- 문서 영향 (갱신해야 할 문서)
- 리스크
- 상태: planned / in-progress / done

## 작업 단위
작업 단위는 작업 문서 하나다. 크기로 나누지 않고 모든 계획을 같은 방식으로 작업 단위로 나눈다.
