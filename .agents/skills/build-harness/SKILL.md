# build-harness (개발)

## 절차
1. 승인된 작업 문서와 AC(인수 조건)를 확인한다. 승인이 없으면 중단하고 plan-harness로 돌아간다.
2. 한 번에 작업 하나만 진행한다.
3. 구현은 서브에이전트에 위임한다. 요청은 delegation-brief 규격으로 작성한다.
4. 구현 서브도 검증 명령을 실행해 보고하고, 확인 전용 서브가 다시 실행해 확인하고 산출물 실재를 확인한다. 확인 서브가 산출물 실재도 확인해 보고하면, 메인은 그 보고를 받아 판단한다.
5. review-harness로 새 리뷰 세션(구현 맥락이 없는 새 읽기 전용 서브)을 실행한다.
6. 미달이면 보정 작업을 하고 재리뷰한다. 같은 지적으로 보정을 2회 한 뒤에도 미달이면 멈추고 사용자에게 보고한다(하네스 문서 5절 2번).
7. 첫 작업을 위임할 때 상태를 in-progress로, 작업 단위 전체 리뷰가 PASS하면 done으로 갱신한다(서브에이전트가 기록한다).
8. 커밋, 푸시, 병합은 사용자가 허락해야 한다. 커밋은 작업 단위 전체 리뷰가 PASS한 뒤 사용자 허락을 받아 한다. 메인이 직접 실행한다.

서브에이전트가 없는 도구는 하네스 문서 3절의 대체 규칙을 따른다.

## 리뷰 범위 규칙
재리뷰 범위는 하네스 문서 9절을 따른다.

## 멈추는 조건
멈추는 조건은 하네스 문서 5절 2번을 따른다.

## 실패 처리
서브가 중간에 끊기거나 실패하면 기존 서브를 이어 쓰지 않고(resume 금지) 새 서브를 연다. 새 서브 요청에는 실패 원인과 현재 파일 상태를 포함한다.

## 작업 분배 범위
위임 범위와 메인 역할은 하네스 문서 3절(위임 범위, 진행 표시)을 따른다.

프로젝트 규칙 우선은 하네스 문서 1절을 따른다. 승인·안전 규칙은 하네스 문서 5절을 따른다. (하네스 문서: harness/HARNESS.md)
