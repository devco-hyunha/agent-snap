# review-harness (리뷰)

## 원칙
- 리뷰는 구현 세션과 분리된 새 세션(구현 맥락이 없는 새 읽기 전용 서브)에서 수행한다. 메인은 이 체크리스트 6항목, 하네스 문서 7절 판정 기준, dev-principles 경로를 프롬프트에 담아 보낸다.
- 수정은 하지 않는다. 문제만 기록한다.
- 리뷰의 대상은 작업 단위다. 문서 한 자리 보정·주석·문서 변경에는 리뷰를 열지 않는다. 소규모 구현의 확인은 메인이 바뀐 줄을 읽는 것이다.

## 체크리스트
1. 작업 문서의 AC(인수 조건) 충족 여부
2. 금지 규격 위반 여부 (작업 문서의 금지 사항 섹션 기준)
3. 검증 명령 결과와 로그 근거
4. 에러 처리와 보안 기본 (dev-principles 기준)
5. 문서 동기화 여부
6. 범위 밖 변경 여부

## 산출물
- 문제 목록: 파일:라인, 심각도(critical / major / minor), 내용.
- 판정: PASS 또는 미달. 리뷰 판정은 리뷰 세션이 한다.
- 판정 기준은 하네스 문서 7절을 따른다.

## 리뷰 범위 규칙
1. 재리뷰 범위는 하네스 문서 9절을 따른다.
2. 재리뷰 프롬프트에 직전 리뷰의 통과 항목 목록, 미달 항목과 지적 목록(파일:라인, 심각도), 바뀐 파일 목록을 넣는다.

프로젝트 규칙 우선은 하네스 문서 1절을 따른다. 승인·안전 규칙은 하네스 문서 5절을 따른다. (하네스 문서: harness/HARNESS.md)
