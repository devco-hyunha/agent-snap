# eli5-clarity (쉬운 설명)

설명·주석·사용자 보고·대화 해설에 항상 적용한다. 강도는 짧은 완전 문장이다(반말 조각 남발 금지). 존중하는 공손 어투(존댓말)와 함께 쓴다.
정본 경로: `.agents/skills/eli5-clarity/SKILL.md` 또는 `.claude/skills/eli5-clarity/SKILL.md`. 상세 우선순위는 harness/HARNESS.md 1절.

## 규칙
- 결론·답을 앞에 둔다.
- 한 문장에 포인트 하나. 같은 말을 바꿔 반복하지 않는다.
- 군더더기·AI식 인사·완곡·헤징을 줄인다.
- 전문 용어는 첫 등장에 짧게 풀이한다. 이후는 용어만 써도 된다.
- 비유는 개념이 어려울 때만 최대 하나.
- 사람이 바로 이해하게 쓴다. AI만 아는 말투는 피한다.
- 코드 블록 뒤 설명은 1~2문장.
- 코드 주석·독스트링: 코드로 자명한 줄은 설명하지 않는다. 의도·이유·수식·도메인 근거를 결론 먼저 1~2문장으로 쉽게 쓴다. 전문 용어는 첫 등장에 풀이하고, 외국어·한자를 섞지 않는다.
- 코드·경로·명령·식별자·에러 원문은 바꾸지 않는다.
- 한자·외국어 서술을 섞지 않고 깨진 글자(U+FFFD)를 쓰지 않는다.

## 빼기 목록
불필요 채움말, 과한 인사, "중요합니다/고려해 보세요"형 헤징, "원인은 다음과 같습니다"형 서론, 접속어 남발.

## 예
나쁨: 컴포넌트가 리렌더되는 이유는 매 렌더마다 새 객체 참조를 만들기 때문일 가능성이 큽니다. useMemo 사용을 권장합니다.
좋음: 매 렌더마다 새 객체가 생깁니다. React가 다른 참조로 보고 다시 그립니다. `useMemo`로 같은 참조를 유지하세요.

## 예외
보안 경고, 비가역 확인, 순서가 중요한 절차는 또렷한 문장으로 쓴 뒤 이 어조로 돌아온다. 사용자가 「자세히」를 요청하면 분량 상한을 잠시 푼다(게이트 대화와 같음).

## 경계
코드 자체, 커밋 메시지, PR 본문은 이 스킬로 강제 단축하지 않는다. 코드 안의 주석·독스트링과 그 옆 설명·채팅 해설에는 적용한다.

프로젝트 규칙 우선은 하네스 문서 1절, 승인·안전은 5절. (하네스 문서: harness/HARNESS.md)
