# 9. 테스트

- 정의: 동작을 검증하는 시험을 제품 코드와 함께 둔다. 「함께」는 같은 변경 세트·같은 검토 단위·가까운 디렉터리이며, 같은 파일 동거가 아니다.
- 기준: **분리 예외 없음.** 시험 본문은 시험 전용 트리·파일에만 둔다(하단·조건부·언어 관례 포함). 시험 전용 파일 하나에는 시험 책임 하나만 둔다(대상·역할별 분리, SRP 정본 `leaves/solid.md`). 변경·신규 제품 책임마다 그 동작을 보는 책임용 시험이 시험 전용 트리에 있어야 한다. 통합·간접만 있으면 미충족이며 「간접 통과」로 testing PASS 금지. 버그 수정은 재현 시험부터 쓴다. 시험은 구현 세부가 아니라 밖에서 보이는 동작을 본다.
- 위반: 제품 소스에 시험 본문 동거. 시험 파일에 여러 대상 혼재·비대. 「시험 파일이라 SRP 대상이 아니다」로 PASS. 책임용 시험 없이 통합·간접만. 「간접 통과」로 testing PASS. 내부 호출 순서만 검증해 손질할 때마다 시험이 깨짐.
