# 3. DRY (중복 금지와 함수 재사용)

- 정의: 같은 지식·동작은 단일 정본(해당 역할의 모듈이나 공용 폴더 안의 개별 파일)으로 두고 import해 재사용한다. 「한곳」=폴더 응집(≠한 파일) 정본은 `leaves/solid.md` SRP.
- 기준: 새 코드를 쓰기 전에 아래 재사용 사다리를 위에서부터 따른다. **사다리는 요청된 기능·AC·검증·에러 처리·보안·시험을 생략(작업 회피)하거나 한 파일에 몰아넣는 구실이 아니다. 충돌 시 요구사항 완수와 SRP가 우선한다.**
  1) 코드베이스에 같은 목적의 헬퍼·컴포넌트·패턴이 있으면 그 방식으로 재사용한다. (새 함수를 만들기 전에 프로젝트·범위 안을 먼저 검색한다.)
  2) 표준 라이브러리·플랫폼 기능을 쓴다. 단, 프로젝트 자체 컴포넌트가 있으면 그쪽을 우선한다.
  3) 이미 설치된 의존성을 쓴다. **몇 줄 때문에 새 의존성을 추가하지 않는다.**
  4) 그다음에야 최소 신규 코드를 쓴다.
  한쪽을 고치면 다른 쪽도 고쳐야 하는 중복은 역할별 파일로 분리해 합치고, SRP를 깨면서 한 파일에 여러 함수를 우겨 넣지 않는다. (※ 함수·컴포넌트 안의 서로 다른 **책임 분리(SRP)**는 중복 횟수와 무관하게 즉시 분리한다.)
- 위반: 기존 함수를 찾지 않고 파일마다 비슷한 헬퍼 함수를 새로 만든다. 몇 줄짜리 기능을 위해 새 패키지를 추가한다. 또는 중복을 없앤다며 서로 다른 책임의 함수들을 거대한 단일 파일(`utils` 한 파일 등)에 다 몰아넣는다.
