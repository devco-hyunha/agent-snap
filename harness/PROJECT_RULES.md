# snap 프로젝트 오버레이

- 역할: 에이전트 하네스(`harness/HARNESS.md`·AGENTS 마커 블록) 위의 프로젝트 오버레이. 하네스 정본이 아니다.
- 위치: `harness/PROJECT_RULES.md`. AGENTS.md `## 프로젝트 오버레이`는 이 파일을 가리킨다.
- 적용: snap에만. 베이스는 읽기 전용. 여기에는 고유·더 엄격한 항목만 둔다.

## 프로젝트 오버레이

[안전 예외 승인: 3번 커밋 — 작업 단위 전체 리뷰 PASS 기록이 있을 때만 로컬 커밋 허용(푸시·병합은 사용자 허락 필수)]

- 엔드포인트 주소를 코드와 문서에 넣지 않는다. 키는 사용자 설정 폴더의 `credentials.jsonc`로만 받고 어디에도 값을 남기지 않는다.
- Hugging Face 모델은 용량·라이선스 목록 승인 후에만 받는다.
- 에이전트(M1)를 먼저 완성한다. 판정 모델 작업은 M1 이후, 실제 세션 출력으로만 평가한다.
- 작업마다 논문·자료를 조사해 `docs/RESEARCH.md`(및 단일 작업 문서 `## 리서치 및 설계 근거`)에 기록하고, 적용 위치나 미적용 이유를 남긴다. 링크는 직접 열어 실제로 있는지 확인한 것만 적는다.
- 작업을 시작할 때 관련 논문을 찾아 참고하고, 작업을 기능별 세부 작업으로 나눠 진행한다. 기획 정본은 `docs/plans/`에 두고, 위임용 상세 작업 문서는 `docs/tasks/`에 둔다. 작업 문서에 참고 논문 절과 세부 작업 절이 채워져 있어야 승인을 요청하고, 구현은 세부 작업 하나씩 위임한다.
- 논문 원문과 번역 전문은 `.local/research/`(git 제외, 플랜별 폴더)에 두고, 공개 문서에는 링크와 요약만 둔다.
- 번역은 미리 모아두지 않는다. 플랜 착수 시점에 그 플랜이 채택·채택예정인 논문을 한 편씩 순차로 번역한다(eli5-clarity 문체, 첫머리 300자 요약). 번역이 기획을 막지 않게, 기획·구현 진행을 우선한다.

## 서브에이전트 호출 규격 (프로젝트 보충)

- 순차 실행: `run_in_background: false`. 메인 기본 모델과 서브 모델은 사용자가 지정한 범위로만 고른다. resume 금지. 새 세션 첫 동작은 Write 도구 호출.
- AskQuestion 선택지는 id·label 객체 배열(문자열 금지). prompt 안 큰따옴표는 \", 경로 역슬래시는 \\\.
- 부모의 직접 허용 작업: docs 작성, 게이트 재확인, 실측 조사, 하네스 동기화.
- 작업 파일에는 범위·근거 커밋 SHA·파일:라인·산출물·금지·검증·보고 형식을 둔다. 위임 문안은 delegation-brief(포인터 샌드위치·500자 이하)를 따른다.

## 개발 규칙

- 상수·문자열 배치 규칙: 기본값·한도·설정의 기본 수치 같은 상수는 상수 모듈(`consts/` 폴더) 한곳에 모은다. 화면·도구 결과·승인 문구·오류 메시지 같은 사용자 노출 텍스트는 로케일 모듈(`locale/` 폴더) 한곳에 모은다. 함수 안에 텍스트를 즉석으로 쓰지 않는다. 언어 전환·문구 변경이 한 파일 수정으로 끝나게 하는 것이 목적이다. 텍스트와 상수를 섞지 않고 각각의 정본 파일에 둔다.
- locale 구조: 로케일 모듈은 locale 폴더(`locale/ko/`, `locale/en/`)로 언어를 나누고, locale 공통 키(함수·상수 이름)는 `locale/mod.rs`에 둔다. locale 폴더는 도메인별 파일로 나눈다. 언어 전환은 locale 선택 한 줄과 설정 키 한 칸으로 끝난다. locale 파일을 새로 추가하는 방식으로 확장하고, 문구를 코드에 직접 박지 않는다.
- 한 파일에 동작을 쌓지 않는다. 같은 변경 이유(책임)가 둘 이상이면 파일로 나눈다. 한 함수가 여러 동작(전송 처리·형식 전환·상한 검사·실행·조립)을 동시에 하면 함수를 나눈다. 한 함수는 100줄을 넘기지 않는다.
- OS 고유 코드는 제품 소스 한복판에 `#[cfg(windows)]`·`#[cfg(unix)]`로 섞지 않는다. OS별 파일(`mod.rs` + `unix.rs` + `windows.rs`)로 분리한다. 지원 대상은 Windows와 Linux 동등이고 같은 커밋에서 서로 한 번씩 검증한다.
- 시험에도 같은 기준을 적용한다. 시험 파일은 변경 이유 기준으로 나눈다. 한 시험 파일에 왕복·쓰기 규칙·거부·보존·가리기 같은 서로 다른 요구를 몰아넣지 않는다. 한 파일이 300줄을 넘으면 책임을 먼저 가른다.
- SRP을 명목으로 과도하게 쪼개지 않는다. 순수 forwarding·순수 재수출·함수 1개 전용 파일을 새 파일로 만들지 않는다. 호출부가 직접 부를 쓰게 한다. 같은 관심사 파일이 둘 이상일 때만 하위 폴더를 만들고, 파일 하나짜리를 폴더로 감싸지 않는다.
- SRP·한곳(응집)·테스트 배치는 하네스 정본(HARNESS 10절과 dev-principles leaves)을 따른다.
- 크레이트: `snap-core`(라이브러리, 모든 로직)와 `snap-cli`(입출력만 맡는 얇은 실행 파일).
- 모듈은 하나의 책임만 맡는다: config, llm, agent, tools, monitor, session, context, server(04-4에서 추가 예정, HTTP 전용 코드만 다룬다). 도구는 `Tool` 트레이트 구현 하나당 파일 하나.
- 작업 전·중에 관련 `docs/plans/`·`docs/tasks/`를 확인한다. 착수 때 `in-progress`, 단계 끝에 plans `tasks.md`·T-파일 상태, 작업 단위 전체 리뷰 PASS 뒤 `done`(또는 완료)으로 맞춘다.
- 오류: 라이브러리는 `thiserror`, 실행 파일만 `anyhow`. 테스트 밖 `unwrap`/`expect` 금지.
- 비밀 값은 Debug 출력에서 가리는 래퍼 타입으로 다룬다.
- 공개 항목 문서 주석은 한국어. 코드 주석·독스트링 어체 정본은 `.agents/skills/eli5-clarity/SKILL.md`.
- 모든 기능에 단위 테스트를 두고, 네트워크 경로는 모의 서버 통합 테스트로 확인한다.
- 지시·리뷰에 스킬 경로를 명시한다: `.agents/skills/dev-principles/SKILL.md`(Claude Code·Cursor는 `.claude/skills/…`). 본문은 플레이북 호출 표의 지정 잎만 Read한다.
- 리뷰 확인 단위는 정합 항목 목록(확인 단위 표 + review-harness 체크리스트 7항목)을 기준으로 삼는다. 미기록 시 major. 메인은 리뷰 근거의 파일:라인·수치를 직접 확인하고, minor까지 고칠지 판단한 뒤 재리뷰한다.
- 경로·이름·참조를 옮긴 뒤에는 옮긴 자리의 설명(주석·독스트링·문서 참조·작업 지시)을 함께 고친다. 옮기기만 하고 설명을 안 고치면 major.
- 문서 연쇄 확인 대상: `docs/INDEX.md`, `docs/PLAN.md`, `docs/DECISIONS.md`, `docs/RESEARCH.md`, `docs/plans/**`, `docs/tasks/**`, `harness/PROJECT_RULES.md`, `.cursor/rules/*.mdc`, `AGENTS.md`(마커 바깥 오버레이). 길어지면 `docs/decisions/` 또는 `docs/plans/<기획>/`로 분리한다.

## 병합(머지) 규칙

- 세부 작업 착수 전 기본 브랜치를 최신으로 갱신한 뒤 `feature/<작업명>` 브랜치를 만들고 그 브랜치에서 구현한다. 잔여·보정 작업은 같은 브랜치에서 이어간다. 잔여 작업이 끝나지 않은 상태에서 새 브랜치·새 계획 번호를 만들지 않는다.
- 브랜치 이름에는 계획·작업 번호를 넣지 않는다. 예: `feature/foundation`, `feature/config-save`. 작업 성격을 밝히는 이름만 쓴다.
- 커밋 메시지 형식과 절차 정본은 하네스 잎 `.agents/skills/dev-principles/leaves/commit.md`를 따른다 (유형 접두·왜 초점·허락 후 실행).
- 커밋 메시지는 먼저 `.local/commit-message.txt`(git 제외)에 파일로 작성한다. 그 파일을 읽어서 오타·한자·외국어·U+FFFD·번호 포함·유형 접두 여부를 확인한 뒤, 확인된 내용을 `git commit -F`로 그대로 사용한다. 커밋이 끝난 뒤에는 그 파일을 삭제한다.
- 커밋 개수는 사용자가 지시한 대로 따른다. 지시 없이 임의로 나누거나 합치지 않는다.
- 커밋 전에 리뷰 PASS 기록을 먼저 확인한다. 코드뿐 아니라 `.md`만 바뀐 문서 변경도 독립 리뷰 대상이다. 순서: 리뷰 PASS → 지시한 커밋 개수 → 메시지 파일 → `git commit -F`.
- 브랜치 흐름: `feature/<작업명>` → `develop` 병합(PASS·CI 초록), `develop` → `main` 승격은 계획 단위 작업이 모두 끝난 시점에만 한다. 기획 문서는 `main`을 기준으로 삼고, 코드는 `develop`에서 이어간다.
- PR CI 매트릭스 전체가 초록이 아니면 머지하지 않는다. `ubuntu-latest`·`windows-latest` 모두 초록이어야 한다.
- 로컬은 현재 OS에서 검증하고, 나머지 OS는 다음 커밋 전 CI로 확인한다.
- `git merge --no-ff` 또는 PR 머지로 병합 커밋을 남긴다. 트리를 대상 브랜치에 그대로 복사해 붙이지 않는다. `git merge-base --is-ancestor <PR head SHA> <대상 SHA>`로 확인한다.

## 문서 규격

- 제품 기획 상태 정본은 `docs/PLAN.md`(항목당 한 줄). 계획 번호는 기획 01~09를 유지한다. 유지보수는 같은 기획의 하위 절(`docs/plans/maintenance/<기획>/<하위>/`)로 두고, 새 계획 번호를 남발하지 않는다. 이름·상태는 `docs/INDEX.md`. 상태 줄은 갈아엎고 2,000자 이하.
- 계획 인계: 앞 계획을 닫고 다음 계획으로 넘어갈 때 인계 기록을 남긴다. 닫는 계획 `tasks.md`의 `## 잔여` 절, 넘어가는 계획 `plan.md`의 `## 근거(선행 계획 잔여)` 절, `docs/PLAN.md`·`docs/INDEX.md` 연결. 잔여는 같은 계획 안에서 잇고 잔여만 새 계획 번호로 분리하지 않는다. 잔여 PASS 뒤에 다음 계획 착수. 산출물(트레이트·모듈·시험 재료)은 이름·경로만 바꾸고 설명은 함께 고친다. 앞 계획 시험을 계승 시험으로 둔다.
- 라운드 로그는 `docs/tasks/<기획 순번>/<세부 순번>-<작업명>/T<번호>-<짧은 이름>.md`에만, 라운드 절 하나·새 라운드는 갈아엎기.
- 하네스 설치·업데이트 작업 문서는 `docs/tasks/update-harness/<번호>-<작업명>/`.
- `docs/plans/`·`docs/tasks/` 하위는 기획·세부 순번 폴더(두 자리). 예: `docs/tasks/02/config/T1-config-read.md`.
- 이름 중복 금지: 부모 폴더가 이름을 갖고 있으면 그 안의 파일·하위 폴더는 부모 이름을 되풀하지 않는다. 예: `tasks/01/foundation/` (`01-01-foundation` 금지), 세부 폴더는 `03/09-timeout-background/`처럼 번호만 남긴다. 파일 이름은 중복 접두 없이 책임만 밝힌다.
- `plan.md`에 `## 작업계획`(열: 작업|범위|금지|산출물|검증 명령)과 `## 작업 파일`(열: 파일|작업|상태)을 둔다. 상태는 계획/진행/완료/막힘. T-파일 상태가 기준이다.
- T-파일 필드: 목표, 근거, 읽을 파일, 할 일, 검증(게이트·명령·로그 경로), 완료 조건, 상태, 라운드 보고(하나). 결정 본문 복제 금지·원천 포인터만.
- T-파일 읽을 파일에 `harness/HARNESS.md`, `AGENTS.md`, `harness/PROJECT_RULES.md`, `.agents/skills/dev-principles/SKILL.md`(또는 `.claude/skills/…`)를 넣는다. 할 일·완료 조건에 플레이북 지정 잎 준수와 역할별 파일 분리를 적는다. 체크포인트: 파일·함수·폴더 생성 전 solid/dry/관심사 분리 확인·기존 정의 검색, 결과를 라운드 보고에 남긴다.
- `docs/plans/**/tasks.md`는 단계·테스트·DoD, 단계마다 "확인:".
- 리뷰 기록은 `docs/reviews/<기획 순번>/` 계층.
- 게이트 기록: 이름, 종료 코드, 로그 경로, 대상 SHA256, 시작·끝 시각. SHA가 같으면 결과 재활용.
- `.local/` 허용: 검증 로그(PASS 확정 후 삭제), `.local/research/`(상주), 문서 정리 백업(정리 후 삭제). 그 외 금지.
- 경로 이동 뒤 `docs/INDEX.md`·`docs/DECISIONS.md`·`docs/RESEARCH.md` 연결을 함께 고친다.

## 주석 전용 경량 게이트

`.rs` 주석·독스트링과 `.md`만 바뀌고 실행 문장·시그니처·설정 키·런타임 문자열이 그대로면 `cargo fmt --check`만 돌리고, clippy·test·WSL은 생략한다. diff로 실행 문장 무변경을 기록한다. 코드 줄이 바뀌면 게이트 3종·OS 양쪽으로 승격한다.

## 검사 명령

`cargo fmt --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test`
